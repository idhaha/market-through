# VI 독립창과 현재가 수신 간격 테스트

트레이딩 화면의 **VI** 버튼으로 Windows 독립창을 연다. 새 경로를 허용하는 최신 설치 파일(`public/downloads/MarketThroughSetup.exe`) 설치가 필요하다. 서버 변경을 적용하려면 서버를 재시작해야 한다.

## 화면 기준

- 기본 순위: 발동시각 내림차순. 열 제목 클릭으로 내림차순 → 오름차순 → 기본순으로 돌아간다.
- 거래소 다음에 구분을 표시한다. LS `vi_gubun` 1=정적, 2=동적, 3=동적,정적, 0=해제.
- KRX대비라는 공통 제목 아래 NXT 괴리율과 선물 괴리율을 둔다. 계산식은 `(비교 가격 / KRX 가격 - 1) × 100`이다. LS가 제공하는 이론가 대비 선물 괴리율을 그대로 쓰지 않는다.
- 같은 종목의 KRX·NXT 이벤트는 거래소별 행으로 구분해, 구분·발동시각·실제 해제시각을 정확히 표시한다. 같은 거래소의 재발동은 해당 행을 갱신한다. 해제 행은 당일 유지하고 글자를 흐리게 한다.
- 발동 중인 VI 행은 방향에 따라 깜박인다. 상승 VI는 빨강(#c90000↔#ff9999), 하락 VI는 파랑(#2563eb↔#dbeafe)이며 사이드카와 같은 1.5초 주기다. 방향은 발동가와 정적·동적 기준가를 비교해 정한다.
- 깜박이는 행을 클릭하면 해당 발동 건의 깜박임이 꺼진다. 해제 여부는 서버 state.json의 행 상태(flashDismissed)에 저장돼 모든 독립창에 동기화되고 서버 재시작 후에도 유지된다. 같은 종목에 새 VI가 발동되면 다시 깜박인다.
- 카운트다운은 발동시각 + 2분의 예상값이다. 0이 되어도 실제 해제 이벤트가 없으면 ‘해제 수신 대기’로 표시한다.
- 서버는 `data/vi-monitor/state.json`에 당일 VI 상태를 저장한다. 다음 한국 날짜에 초기화한다. 재시작 전 마지막 상태가 실제로 계속 유효한지는 연결 중단 중 이벤트를 복구할 수 없어 보장하지 않는다.
- 종목명·시장: `t8436`. 선물: `t8401.basecode`의 `A` 접두어를 제거해 현물 코드와 대조한다. SP 스프레드는 제외한다. `t8402.lastmonth`로 만기를 확인해 최근월·차기월을 자동 선택한다.
- 등락률·거래대금은 KRX 기준이다. 비교에 쓰인 각 가격의 마지막 수신시각은 셀 툴팁으로 확인한다. 양 시장 체결이 동시 발생한다는 보장은 없다.

## 장중 수신 간격 측정

프로젝트 루트에서 다음 명령을 실행한다. 인증은 루트 `.env`의 `LS_APPKEY`, `LS_SECRETKEY`를 사용하며 인증값은 출력하지 않는다.

```powershell
node dev/ls-quote-cadence.cjs --stock 005930 --market KOSPI --future auto --seconds 600
```

`--future auto`는 같은 현물의 최근월 선물코드를 자동으로 찾는다. 특정 월물을 비교하려면 `--future A116B000`처럼 실제 마스터에 존재하는 코드를 지정한다. 선물을 제외하려면 해당 옵션을 생략한다. 코스닥은 `--market KOSDAQ`를 지정한다.

결과 JSON은 `dev/output/ls-quote-cadence/`에 생성된다. KRX(S3_/K3_), NXT(NS3), 주식선물(JC0)을 별도로 집계한다.

- 체결 메시지 수와 첫 수신 이후 가격 변경 횟수
- 단조 시계로 측정한 메시지 수신 간격의 평균·중앙값·p95·최대·최소 및 초당 수신 수
- 같은 서버 체결초에 들어온 메시지 수
- 구독 확인 응답과 연결 오류

장중 거래가 활발한 종목으로 10분씩 2~3회 측정하고, 거래가 적은 종목에서도 같은 조건으로 비교한다. VI 중에는 해당 거래소 체결이 멈출 수 있으므로 정상 거래 구간과 VI 구간을 별도로 해석한다. 체결 메시지는 구독 확인 응답을 제외하고 유효한 현재가·체결시각을 가진 메시지만 집계한다. 서버 시각은 초 단위이므로 밀리초 네트워크 지연이나 거래소에서 생성된 원래 틱의 누락률은 이 측정만으로 구할 수 없다. 비거래일 무수신은 고정 발행 주기를 뜻하지 않는다.

## 장중 VI 이벤트 수신 측정

전체 시장 VI_/NVI 이벤트를 지정 시간 동안 기록한다. 결과는 --out 폴더의 vi-events.jsonl과 vi-summary.json으로 저장된다.

    node dev/ls-vi-live-check.cjs --seconds 1800 --out outputs/vi-live-check-20261103

2026-11-03 장중 측정은 Windows 작업 스케줄러에 등록했다: VI 이벤트 09:00:30부터 30분, 삼성전자 KOSPI·선물 10:00부터 10분, 에코프로비엠 KOSDAQ 10:15부터 10분.

## 로컬 통합 시험 (키움 VI · LS 조회 수급 · NH 현재가)

세션이 겹치지 않는 구성을 검증하는 로컬 전용 시험이다. 오라클 서버는 바꾸지 않는다.

- `dev/local-rest-vi-test.cjs`: 로컬 서버를 아래 설정으로 재시작하고 VI 비교를 20:00까지 실행한다. 끝나면 서버를 일반 설정으로 되돌린다. 기록은 `outputs/local-rest-vi-YYYYMMDD/`에 남는다.
- `dev/vi-compare-live.cjs`: 키움 실시간 1h(그룹 1 전체, 그룹 2 `_NX`)와 LS `VI_`/`NVI`를 함께 기록한다. VI가 발동한 종목은 NH로 KRX(oc)·NXT(nc)·최근월 주식선물(vC)을 구독하고, 해제 3분 뒤 구독을 푼다. 기록은 `outputs/vi-compare-YYYYMMDD/`에 남는다.
- `nh-quote-feed.js`: NH 토큰을 `data/nh-plug/token.json`에 보관해 24시간 재사용한다. 재발급하면 NH 보안 알림이 가므로 401/IGW40043일 때만 재발급한다. 구독은 30건까지 받고, 넘는 종목은 NH 조회로 받는다. 구독할 종목이 없으면 NH가 연결을 끊으므로 필요할 때만 연결한다.
- 서버 설정(기본값은 기존 실시간 방식):
  - `LS_MARKET_SUPPLY_MODE=rest`: 지수·선물 투자자와 프로그램을 t1602·t1662로 30초마다(:15·:45) 조회한다.
  - `LS_STOCK_PROGRAM_MODE=rest`, `LS_STOCK_PROGRAM_REST_CODES=005930`: 종목 프로그램을 t1637로 1분마다 조회한다. LS 공용 실시간 연결을 열지 않으므로, LS 거래대금 실시간(IJ_·US3)도 받지 않는다.
  - `VI_MONITOR_REALTIME=false`: VI 독립창의 LS 실시간 연결을 끈다.

2026-11-01 실제 LS 서버에서 KRX `000000`, NXT `N000000   ` 키 구독의 정상 응답을 확인했다. 빈 키는 `10008`로 거부된다. 삼성전자 `A005930` → `A116B000` 매핑과 실제 만기일 조회, KRX·NXT·선물 체결 채널 구독도 확인했다. 비거래일이므로 전체 종목의 VI 이벤트 수신 범위·발동/해제 전달·실제 체결 수신 빈도는 아직 확인하지 못했다.

장중에는 LS HTS의 VI 현황과 이 창을 나란히 놓고, 서로 다른 종목의 발동·정적/동적 구분·해제와 거래소별 누락 여부를 확인해야 한다. 정상 구독 응답만으로 전체시장 전송을 검증한 것으로 보지 않는다. 수신 시작 이전 또는 연결 단절 중의 과거 VI는 자동 복구되지 않으며 화면에도 이를 안내한다.

브라우저 통합 테스트는 LS 형식의 테스트 WebSocket 메시지를 주입해 서버 상태 → SSE → 실제 Edge 렌더링, 정렬·구분·해제 유지·월물 전환·KRX대비 계산·날짜 전환·저장 복구·권한 만료를 검증한다. 장중 실제 LS 이벤트 검증을 대체하지 않는다.

Windows 네이티브 테스트도 실제 WebView2에서 SSE 데이터, 해제 행, 공통 헤더 및 항상 위 브리지를 검증했다. 기존 트레이딩 독립창 회귀 테스트도 통과했다. 제한된 실행 환경에서는 WebView2 프로세스에 접근 거부가 발생할 수 있어 일반 실행 환경에서 확인했다.

공식 명세: [LS API 가이드](https://openapi.ls-sec.co.kr/apiservice) — VI_, NVI, S3_, K3_, NS3, JC0, t8401, t8402, t8436.
