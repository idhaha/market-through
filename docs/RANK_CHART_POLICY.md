# Rank 공통 차트 정책

최종 기준: 2026-10-24, 한국 시간. 이 문서는 해당 대화의 최종 결정을 정리한 현재 정책이다. 다른 문서의 과거 배치·레이블·높이·캔들 개별 조작 설명과 충돌하면 이 문서를 우선한다. 데이터 수집은 [신고가·신저가](BREADTH_CHART.md), [수급](SUPPLY_CHART.md), [쏠림율](CONCENTRATION_CHART.md)을 함께 참고한다.

오늘 변경의 요약·원인·검증·적용 범위는 [2026-10-23 작업 기록](operations/2026-10-23-rank-charts.md)을 참고한다. 이 문서에서 명시적으로 대체된 이전 정책은 변경 이력이며 현재 동작으로 해석하지 않는다.

## 메인 배치

- 2026-10-25 한투 비교: 실제 현재 CNN 카드(3행 2열) 오른쪽 3행 3열에 `쏠림율[한투]`를 배치한다. 기존 쏠림율과 그리기 코드를 공유하고 종목·주기·시간축·호버·캔들·과거/자동 갱신 정책에 함께 참여한다. 거래대금 계산만 한투 실제 금액으로 바꾸며 상세 원천·제한은 [쏠림율](CONCENTRATION_CHART.md)의 한투 비교 카드 항목을 따른다. 카드 출처는 `한투`다. 아래의 이전 배치 기록보다 이 안내와 현재 CSS 배치를 우선한다.

- 첫 줄: 쏠림율 / 종목 수급 / 시장 수급.
- 둘째 줄: 신고/신저 / 거래대금 / 변동성.
- 셋째 줄: CNN Fear & Greed·하이일드 스프레드 / ADR.
- 2026-10-24 시장 수급 추가 후에도 3열을 유지한다. 상세 원천·표시·제한은 [시장 수급](MARKET_SUPPLY_CHART.md)을 따른다.
- 독립창은 기존 거래대금 순위·쏠림율·수급의 세로 배치를 유지한다.

## 카드 출처 표시 (2026-10-23)

- 각 카드 하단에 `출처: …`를 오른쪽 정렬로 표시한다. 메인창과 독립창에 동일하게 적용한다.
- 쏠림율·수급·거래대금·신고가·신저가 차트와 거래대금 상위·실시간 조회 순위·관심종목 순위는 `키움`, 대주가능 종목은 `한투`, ADR·변동성·CNN/하이일드 차트는 `jusikbot`으로 표시한다.
- 신고가·신저가의 현재 수집 원천은 키움 `ka10016`이다. Jusikbot은 전환 이전에 보존·이관한 과거 자료의 원천이며 현재 카드 출처로 표시하지 않는다. 이전 Jusikbot 설명보다 [신고가·신저가 정책](BREADTH_CHART.md)과 현재 서버의 `/api/risk/breadth` 구현을 우선한다.

## 그래프 높이와 시작선

- 7개 메인 차트 모두 실제 메인 캔버스 높이 286px를 사용한다. 상태·출처를 한 줄로 합치면서 기존 260px에서 26px를 확보했다. 내부 그래프 여백은 위 10px·아래 34px로 통일한다.
- 높이만 같게 하는 것으로 끝내지 않고, 카드 상단부터 캔버스 시작까지 거리도 맞춘다. 제목 줄 36px, 버튼 줄 40px, 외부 마우스 정보 줄 20px를 기준으로 한다.
- 이전 기본 데스크톱 검증에서는 시작 오프셋 127px·높이 260px를 확인했다. 현재 플롯 높이 286px는 하단 줄 회귀 검증으로 확인한다. 127px는 현재 기본 레이아웃의 측정값이며 임의 화면 배율에서 고정 좌표로 사용하지 않는다.
- 두 줄 레이블은 행당 18px, 행 사이 2px로 버튼 줄 안에 배치한다. 날짜 추가나 큰 글꼴 때문에 버튼 줄·그래프가 아래로 밀리면 안 된다.
- 거래대금의 기간·캔들 버튼은 기본 카드 폭에서도 한 줄에 들어가도록 간격을 조정한다. 아래 캔들 영역은 메인 그래프와 별도다.

## 레이블과 기준 날짜

- 거래대금: KOSPI·KOSDAQ 두 행. 시장명 시작점은 왼쪽 정렬, 금액은 오른쪽 정렬한다. 두 행 위에 실제 마지막 유효 값의 날짜를 표시한다. 시장별 날짜가 다르면 시장별 날짜를 구분한다.
- 신고가·신저가: 두 행, 신고가 빨강·신저가 파랑으로 그래프와 같은 색을 사용한다. 위에 표시 값의 기준 날짜를 표시한다. 마지막 기준 봉이 결측이면 값·날짜를 만들어 채우지 않는다.
- 변동성: VKOSPI·VIX 두 행을 각 그래프 색으로 표시하고 위에 마지막 값의 날짜를 둔다. 날짜가 다르면 지표별로 구분한다.
- CNN·하이일드: 두 행을 각 그래프 색으로 표시한다. 공통 날짜 한 줄 대신 각 지표의 날짜를 해당 레이블 왼쪽에 표시한다.
- 쏠림율·ADR: 현재값 바로 위에 기준 날짜를 표시한다. 쏠림율 날짜는 버튼 줄의 가로 스크롤 영역 밖에 두어 위쪽이 잘리지 않게 한다.
- 수급: 이름 12px·수치 13px, 개/외/기/프 두 행을 버튼 줄 오른쪽에 둔다. 위에 각 주체의 마지막 유효 관측 날짜를 표시하고, 날짜가 다르면 가장 이른 날짜~가장 늦은 날짜 범위를 표시한다. 개별 값의 마우스오버에는 정확한 기준 시각을 유지한다.
- 날짜 형식은 YYYY-MM-DD다. 레이블 위 날짜는 절대 위치로 배치해 값·버튼·캔버스 위치와 높이에 영향을 주지 않는다.
- 수급의 절댓값이 1,000주 이상이면 1,000으로 나눈 뒤 소수 부분을 0 방향으로 버리고 천주로 표시한다. 예: 12,345주→12천주, -12,345주→-12천주, 999주→999주. 원본 저장·계산값은 바꾸지 않고 레이블·마우스 정보·수급 세로축 표시만 바꾼다. 가격 캔들 축에는 적용하지 않는다.

## 신고가 전환 안내

카드 우측 상단에 다음 두 줄을 표시한다. 설명 묶음의 오른쪽 끝은 세로축 레이블의 오른쪽 끝에 맞추고 두 줄끼리는 왼쪽 정렬한다. 문구를 기존 제목 줄보다 6px 위로 올리며 그래프 위치를 바꾸지 않는다.

```text
2026-10-20까지 KOSPI
2026-10-21부터 KOSPI+KOSDAQ(KRX+NXT 통합)
```

## 캔들 버튼

- 메인창에서 어느 차트의 캔들 버튼을 눌러도 7개 차트를 모두 같은 상태로 펼치거나 접는다. 차트별 로딩·높이·aria-expanded 처리를 재사용하고 완료된 상태를 한 번 저장한다.
- 독립창은 동기화 대상에서 제외한다. 독립창의 차트별 캔들 조작과 창별 펼침 상태는 유지한다.
- 메인창의 초기 설정 복원에도 공통 펼침 상태를 적용한다. 기준은 쏠림율의 `rankChartDisplay.candleOpen`이며 수급이 늦게 생성되어도 같은 값을 따른다. 저장값이 없는 상태의 기본값과 사용자 저장 상태는 구분한다.

## 날짜 경계의 세로 점선

- 일봉: 월이 바뀌는 첫 봉. 분봉: 거래일이 바뀌는 첫 봉.
- 회색 점선, 최소 32px 간격. 더 좁은 경계는 생략하고 확대·이동·리사이즈 후 다시 계산한다.
- 메인 그래프의 경계 X좌표를 아래 캔들에도 공유한다. 당일 분봉만 있으면 거래일 경계선은 없다.
- 거래일을 같은 봉 간격으로 그리는 차트는 월별 거래일 수에 따라 월 경계 사이 폭이 달라진다. 주말·휴장일을 가짜 봉으로 채우지 않는다.

- 이번 대화에서 실행·통과한 관련 검증: `breadth-service.test.cjs`, `supply-service.test.cjs`, `risk-volatility.test.cjs`, `rank-supply.test.cjs`, `rank-volatility.test.cjs`, `rank-turnover.test.cjs`, `chart-value-dates.test.cjs`.

## 거래대금 기간·과거 조회 (2026-10-23)

- 버튼은 `일 / 1분봉 / 캔들+ 과거 조회 / 캔들차트` 순서다. 6M·1Y·3Y·5Y 기간 선택은 제거한다.
- 수급 정책과 같이 일봉 최초 범위·봉 수는 삼성전자 통합시장 `ka10081` 첫 페이지로 정한다. 600봉 같은 상수를 두지 않고 실제 응답 날짜에 맞추며 시장 지수의 누락 값은 null이다.
- 과거 조회는 일봉의 이전 페이지, 분봉의 이전 거래일을 이어 붙인다. 화면 갱신은 이미 불러온 페이지와 확대·스크롤 위치를 유지한다. 봉 종류 변경 시 새 시간축으로 초기화한다.
- 1분봉은 최신 거래일 전체를 조회하고 이전 거래일 cursor를 제공한다. 거래대금은 기존 지수×거래량 기반 누적 추정값이며 거래일 사이 누적 합계를 이어 더하지 않는다. 수급의 서버 관측 저장 정책을 거래대금에 새로 적용한 것은 아니다.
- 봉 종류 변경·갱신·과거 조회로 캔들을 자동으로 펼치지 않는다. 기존 공통 캔들 동기화와 출처 `키움`은 유지한다.
- 인증된 `GET /api/turnover/chart?mode=day|minute&cursor=YYYYMMDD`는 `markets.kospi/kosdaq`, `cursor`, `has_more`, `warnings`를 반환한다. 서버는 60초 메모리 캐시와 순차 키움 요청을 사용한다. 일시 조회 오류는 한 번 재시도하고 중간 실패 시 확보한 자료와 경고를 반환한다.
- 구현은 `turnover-service.js`, `server.js`, `public/rank-turnover-chart.js`다. 검증은 `node --test dev/tests/turnover-service.test.cjs`, `node dev/tests/rank-turnover.test.cjs`다.

## 변동성·CNN·ADR 초기 봉 수와 조작 (2026-10-23 정정)

- 초기 범위는 다른 카드와 날짜를 강제로 맞추거나 지표의 관측 개수로 정하지 않는다. 각 차트에서 캔들차트를 최초 조회할 때 받은 기준 가격 캔들 한 페이지의 실제 봉 수·시간축을 사용한다. 캔들을 접어 둔 상태에서도 같은 기준을 조회한다. 600봉 등 고정 개수나 1Y 등 달력 기간으로 대체하지 않는다.
- 기준 캔들은 변동성·CNN은 KOSPI, ADR은 선택 시장의 키움 `ka20006` 일봉 / `ka20005` 1분봉 첫 페이지다. API의 실제 연속조회 키로 다음 페이지를 추가한다. 원천마다 첫 페이지 봉 수가 다르면 그 응답을 따른다.
- 변동성·CNN은 `일 / 과거 조회 / 캔들차트`, ADR은 `일 / 1분봉 / 과거 조회 / 캔들차트` 순서다. 기간 선택 버튼은 제거하고 ADR도 최초 일봉으로 시작한다. 변동성·CNN에 없는 분봉을 생성하지 않는다.
- 지표 값은 실제 원천 자료만 표시한다. 기준 캔들에 대응하는 값이 없으면 빈 자리·—로 두며 0·직전값·보간으로 채우지 않는다. 캔들 데이터는 실제 가격으로 표시한다. ADR 과거 분봉은 보존된 실제 관측만 사용하며 일별 마감값으로 분봉을 만들지 않는다.
- 과거 추가조회 후에도 갱신 시 불러온 페이지를 유지한다. 캔들 열림·접힘을 이유로 시간축·봉 수를 변경하지 않는다. 기존 기간 설정은 새 기간 버튼을 복원하지 않으며 캔들 상태만 적용한다.
- 인증된 `GET /api/chart-reference?mode=day|minute&market=kospi|kosdaq&cursor=…`는 기준 가격의 `points`, `count`, `cursor`, `has_more`를 반환한다. cursor는 키움의 불투명 연속조회 키다. 응답은 60초 메모리 캐시한다.
- 검증: `node --test dev/tests/chart-reference-service.test.cjs`, `node dev/tests/rank-reference-controls.test.cjs`.

### 기준 캔들 API 배포와 오류 처리

- 새 화면과 함께 `server.js`, `chart-reference-service.js`를 서버에 반영하고 Node/PM2 프로세스를 재시작해야 한다. 브라우저 조회·새로고침만으로 실행 중인 서버에 새 경로가 등록되지는 않는다.
- `/api/chart-reference`가 HTML을 반환하면 지표 조회 전체를 중단하지 않는다. 기준 캔들이 아직 없을 때는 실제 지표 자료를 임시 표시하고 `기준 캔들 API 미반영 · 서버 업데이트·재시작 필요`를 표시한다. 이 임시 표시는 캔들 한 페이지 기준 적용 완료를 뜻하지 않는다. 정상 API 응답 후 기존 기준으로 복구한다.
- 기존 기준 캔들이 있으면 실패 때도 유지한다. 없는 API 경로는 홈페이지 HTML 대신 404 JSON을 반환한다. 화면 스크립트 캐시 버전도 함께 갱신한다.
- 회귀 검증은 정상 페이지·과거 조회와 함께 기준 API가 `<!DOCTYPE html>`을 반환하는 경우에도 세 차트의 실제 값이 표시되는지 확인한다.

- ADR X축은 거래대금과 같이 일봉 `YY-MM-DD`, 분봉 `HH:mm` 형식이다. 표시 폭에 맞춰 실제 봉에서 눈금을 추리고 아래 캔들에도 같은 눈금을 사용한다. 이전의 연·월·일 한국어 표기와 5Y 기준 연도 눈금은 사용하지 않는다.

## 전체 차트 공통 X축 (2026-10-23)

## 분봉 과거 조회 표시 단위와 실제 확인 (2026-10-23, 이전 표시 정책)

## 분봉 공통 시작점: 조회 범위의 교집합 (2026-10-23 최종)

이 절은 직전의 “한 번에 이전 거래일 하루씩 표시” 정책을 대체한다. 추가조회 자체는 각 원천의 연속조회·과거 조회 기능을 사용하고, 각 분봉 차트가 현재 확보한 시간축의 최초 시각 중 **가장 최신 시각**을 전체 분봉 차트의 공통 X축 시작점으로 정한다. 더 오래 확보된 자료는 유지하되 그 공통 시작점 이전은 표시하지 않는다.

- 분봉으로 선택되어 자료가 있는 차트만 비교한다. 일봉 전용 차트와 자료가 전혀 없는 차트는 시작점 계산에 참여하지 않는다. 지표가 부분적으로 없는 구간은 해당 차트의 기준 가격 시간축을 유지하되 지표 값을 생성하지 않는다.
- 어느 차트든 추가조회 결과가 도착하면 모든 분봉 차트의 시작점을 다시 계산·그린다. 반복 클릭에도 같은 규칙이며 아직 과거 범위가 짧은 차트가 있으면 공통 시작점은 그 범위보다 더 과거로 가지 않는다.
- 처음 분봉 선택과 `당일`은 한국 시간 당일 08:00 기준이다. 추가조회 모드에서는 비교 결과의 정확한 시각을 사용하고 08:00으로 임의 반올림하지 않는다. 서로 다른 API 페이지 크기와 거래시간을 화면 시작 날짜의 차이로 노출하지 않는다.
- 원본 저장·조회 범위는 잘라 버리지 않는다. 본체·캔들은 동일한 공통 시작 좌표를 사용하며, 확대·스크롤은 그 공통 범위 안에서 동작한다. 독립창은 해당 창에 표시된 분봉 차트끼리 계산한다.
- `rank-chart-axis.js`의 `sharedRange`가 범위 등록·비교·다른 차트 재그리기를 처리한다. `rank-chart-today.test.cjs`는 최초 시각이 서로 다른 두 입력, 추가조회로 범위가 바뀌는 경우, 빈 자료·일봉 제외, 당일 복귀를 검증한다.

- 공통 시작점이 같더라도 빈 초기 자료에서 유효 분봉이 도착하면 표시 봉 수를 다시 계산한다. 초기 0봉을 사용자 확대 범위처럼 유지하지 않는다. `당일`·과거 조회의 명시적 범위 전환도 모든 차트의 범위 적용 상태를 초기화한다. `rank-minute-initial-render.test.cjs`는 수급·신고가·ADR 최초 진입에서 API 응답을 지연시킨 뒤 실제 선·막대가 그려지는지 검증한다.

## 분봉 표시 기간·눈금의 데이터 독립성 (2026-10-23)

- 분봉 X축은 실제 값이 존재하는 봉에서 눈금을 골라 만들지 않는다. 공통 시작 시각과 전체 분봉 차트의 가장 최신 수신 시각을 표시 기간으로 사용하고, 그 기간에서 일정한 시간 간격의 눈금을 생성한다. 시작은 당일 08:00 또는 과거 조회의 공통 시작점 정책을 따른다.
- 특정 차트가 09:00부터만 데이터를 제공하거나 마지막 수신이 다른 차트보다 늦어도 축 기간을 줄이지 않는다. 데이터가 전혀 없어도 공통 기간·눈금은 표시한다. 값·가격·거래량은 보간하거나 0으로 생성하지 않는다.
- 여러 거래일은 활성 분봉 차트의 거래일 합집합을 같은 세션 좌표로 사용한다. 본체와 아래 캔들 모두 같은 공통 도메인과 눈금을 사용한다. 눈금 간격은 공통 기간을 기준으로 고르며 실제 데이터 간격과 무관하다. 좁은 카드에서는 기존 겹침 방지 규칙을 적용한다.
- `minuteDomain`은 공통 시작·끝·거래일을, `minuteTicks`는 값이 없는 시각을 포함한 눈금을 계산한다. `rank-chart-today.test.cjs`에서 서로 다른 최초/마지막 시각과 빈 자료를 가진 차트의 기간·눈금·좌표 일치를 검사한다.

## 분봉 추가 조회의 공통 처리 순서 (2026-10-23)

- 분봉에서 어느 카드의 `더 불러오기`를 눌러도 현재 분봉으로 표시 중인 차트들의 과거 조회를 함께 진행한다. 각 차트의 로더는 순차 실행하며 진행 중인 자체 조회가 있으면 완료를 기다린다. 일봉에도 아래의 전체 추가조회 동기화를 적용한다.
- 조회 진행 중에는 기존 공통 시작점을 고정한다. 모든 과거 조회가 끝난 뒤 조회된 최초 시각 중 가장 최신 시각으로 공통 시작점을 한 번에 갱신한다. 시작점을 기존보다 최신으로 옮겨 기간을 축소하지 않는다. 특히 첫 추가조회에서 당일 08:00이 당일 09:00으로 바뀌면 안 된다.
- 과거 자료가 부족하거나 조회가 끝나지 않아 표시 기간을 넓힐 수 없으면 기존 범위를 유지하고 카드에 안내를 표시한다. 중복 클릭으로 공통 조회를 겹쳐 실행하지 않는다. 수급은 가격 캔들 조회까지 마친 뒤 완료로 처리한다.
- 회귀 검증은 서로 다른 초기 범위, 지연된 로더, 반복 추가조회, 더 이전 공통 범위가 없는 경우를 포함한다.

## 봉 종류 버튼의 전체 동기화 (2026-10-23)

- 어느 차트의 일봉 버튼을 눌러도 표시 중인 전체 차트가 일봉으로 전환된다. 변동성·CNN의 일봉 버튼도 전체 일봉 전환을 시작할 수 있다.
- 어느 차트의 분봉 버튼을 눌러도 분봉을 지원하는 쏠림율·수급·신고가/신저가·거래대금·ADR은 모두 분봉으로 전환된다. 분봉이 없는 변동성·CNN은 일봉을 유지하고 분봉 버튼을 추가하지 않는다.
- 기존 각 차트의 전환·취소·조회·설정 저장 경로를 재사용한다. 분봉 전환 시 공통 당일 08:00 표시 규칙을 적용하며 캔들 펼침 상태는 바꾸지 않는다.
- 조회 중이라 즉시 전환할 수 없는 카드는 전환을 재시도한다. 사용자가 다른 봉 종류를 선택하면 이전 전환 재시도를 취소하고 최신 선택을 따른다. 동기화로 발생한 클릭이 다시 전체 동기화를 호출하지 않도록 재진입을 막는다.
- 메인창·독립창 각각 현재 화면의 차트들에 적용한다. 검증은 실제 7개 차트를 로드하는 `rank-candle-restore.test.cjs`에 수급·ADR·쏠림율·CNN을 통한 일/분 전환과 분봉 미지원 예외를 포함한다.

## 일봉 추가 조회의 전체 동기화 (2026-10-23)

- 어느 일봉 차트의 `더 불러오기`를 눌러도 현재 일봉으로 표시 중인 차트 전부가 같은 추가조회 작업에 참여한다. 변동성·CNN/하이일드도 등록하며, 각 로더의 기존 연속조회·자료 보관·오류 처리를 재사용한다.
- 각 차트가 확보한 최초 날짜 중 가장 최신 날짜를 공통 시작일로, 최신 수신 날짜를 공통 종료일로 정한다. 모든 일봉 차트는 같은 일자 시간축·눈금을 사용하고, 본체와 아래 캔들의 좌표도 공유한다. 없는 날짜의 지표·가격을 생성하지 않는다.
- 조회 중에는 기존 공통 시작점을 유지한다. 참여 조회가 끝난 뒤 공통 범위를 갱신하며, 반복 추가조회도 같은 규칙을 따른다. 단독 차트만 과거를 펼치지 않는다.
- 분봉에서 일봉으로 새로 전환할 때는 기존 최초 페이지 정책으로 시작한다. 이후 일봉 추가조회를 누른 시점부터 공통 일봉 범위를 적용한다. 확대·축소·스크롤도 아래의 공통 표시 범위 정책에 따라 같은 주기의 차트에 전파한다.
- `requestHistory('day')`, `dailyDomain`, `sharedRange`가 일봉의 추가조회·공통 범위·좌표를 처리한다. 회귀 검증은 7개 일봉 로더 참여, 서로 다른 조회 범위에서 시작·종료일·눈금·가격 좌표 일치, 실제 ADR·변동성·CNN의 동시 추가조회를 포함한다.

## 추가 자료가 없을 때도 공통 축 유지 (2026-10-23)

- 공통 과거 조회가 끝나면 더 이전 자료가 생겼는지와 관계없이 범위 적용 버전을 갱신하고 모든 참여 차트의 표시 범위를 공통 시작점으로 다시 맞춘다. “기존 표시 기간 유지”는 각 차트가 서로 다른 확대 범위를 유지한다는 뜻이 아니다.
- 공통 축 갱신 판단에는 최초·마지막 시각뿐 아니라 중간 거래일 구성도 포함한다. 양 끝이 같아도 내부 거래일이 추가되면 모든 차트의 공통 좌표·눈금을 다시 그린다.
- 쏠림율은 조회 중에도 기존 데이터를 사용해 공통 축 변경을 다시 그린다. 로딩 상태라는 이유로 이전 X축을 그대로 남기지 않는다.
- 회귀 검증은 공통 시작점이 변하지 않는 추가 조회, 개별적으로 줄어든 표시 범위 복구, 양 끝이 같은 중간 날짜 추가, 브라우저 캔버스의 실제 날짜 레이블 일치를 포함한다.

## 차트 조회 시작 순서와 표시 (2026-10-23)

- 공통 시작 순서는 **쏠림율 → 수급 → 신고가/신저가 → 거래대금 → ADR → CNN/하이일드 → 변동성**이다. 변동성은 사용자 지정 목록에 없어서 마지막에 둔다.
- 일반 조회·자동 갱신은 `refreshCharts`가 이 순서로 비동기 함수를 호출하며 앞 차트의 완료를 기다리지 않는다. 각 차트는 응답이 끝나는 대로 바로 표시한다. 쏠림율을 거래대금 순위 응답 후에 중복 갱신하지 않는다.
- 메인 화면 새로고침에서는 개별 차트의 조기 초기 조회를 억제하고 인증·설정 복원 뒤 같은 공통 갱신 경로를 사용한다. 선택 종목이 전혀 없는 최초 실행은 순위에서 최초 종목을 정한 뒤 쏠림율 조회를 시작하고 나머지를 순서대로 시작한다. 이후 선택 종목이 있으면 순위표 응답과 무관하게 즉시 시작한다.
- `더 불러오기`는 같은 순서로 참여 차트의 과거 자료를 순차 조회한다. 각 완료 자료는 바로 그리며, 전체 추가 조회가 끝나면 공통 X축을 최종 갱신한다. 화면 위치나 초기화 등록 순서에 의존하지 않는다.
- 검증은 `rank-chart-refresh-order.test.cjs`의 7개 시작 순서·완료 순서 독립성, `rank-refresh.test.cjs`의 순위 응답 대기 제거·선택 유지, `rank-minute-initial-render.test.cjs`의 초기 개별 조회 차단·정상 분봉 표시를 포함한다.

## 상태·출처 공통 하단 줄 (2026-10-23)

상태·조회 기간·로딩 문구는 출처와 같은 카드 하단 줄 왼쪽에, 출처는 오른쪽에 둔다. 긴 상태는 한 줄 말줄임 처리하며 추가조회 안내는 같은 상태 영역에 표시한다. 줄 하나를 합친 26px를 메인 플롯에 돌려주어 높이를 260px에서 286px로 늘린다. 본체 시작 위치와 캔들 데이터는 유지한다. `rank-card-footer.test.cjs`에서 줄 정렬·플롯 높이·동적 안내·중복 방지를 검증한다.


## 확대·축소·스크롤 동기화 (2026-10-23)

- 확대/축소 버튼, 마우스 휠, 드래그 구간 확대 및 하단 슬라이더 조작은 같은 주기의 모든 차트에 표시 시작·종료 날짜/시간으로 전파한다.
- 차트별 데이터 누락이나 봉수 차이가 있어도 표시 기간과 x축 좌표는 공통 범위를 사용하며, 없는 자료는 빈 구간으로 둔다.
- 일봉과 분봉의 표시 범위는 별도로 유지한다. 주기 전환, 당일 및 더 불러오기는 기존의 공통 기간 정책으로 범위를 재설정한다.
- 단순 캔버스 클릭과 호버는 표시 범위를 변경하지 않는다.

- 동기화된 일봉의 날짜 눈금은 공통 거래일 목록에서 최대 5개를 고른다. ADR 등 차트별 가격축 여백 차이가 눈금 날짜 선택을 바꾸지 않도록 한다.

- 상태 문구 대신 메인 차트 영역 다음에 캔들, 캔들 다음에 슬라이더를 배치한다. 두 영역은 카드 본체의 직접 자식으로 유지한다.

## 독립창의 창 간 차트 분리 (2026-10-23)

- 메인창과 독립창 사이에서는 차트 종목·일/분 주기·과거 조회·확대/축소·스크롤·캔들 펼침 상태를 전파하지 않는다. 메인 스냅샷이나 서버 정기 갱신 자료가 독립창의 로컬 차트 상태를 덮어쓰지 않는다.
- 독립창을 처음 열 때 메인 종목을 초기값으로 한 번 사용할 수 있다. 이후 종목·주기와 조회된 자료는 독립창에서 관리한다. 인증된 릴레이를 통한 데이터 요청은 유지하지만 그 요청이 메인 차트의 조회 조건을 변경하지 않는다.
- 독립창 안의 쏠림율·수급은 기존 공통 주기 전환, 당일, 추가조회, 표시 기간·확대/축소·슬라이더 동기화를 유지한다. 각 창의 `RankChartAxis` 상태는 별개다. 캔들 펼침은 기존 독립창의 카드별 동작을 유지한다.
- 수급 선택 종목은 독립창에서는 창별 `sessionStorage`, 메인창에서는 기존 `localStorage`에 저장해 같은 브라우저 저장소를 사용해도 다음 복원 때 서로 덮어쓰지 않는다.
- 일반 갱신 시 독립창은 자신의 현재 조회 조건으로 다시 요청하고 과거 페이지·표시 범위를 유지한다. 순위표와 순위 조건·등록 수급 목록의 서버 공유는 이번 차트 표시 상태 분리의 대상이 아니다.
- 구현: `public/rank-independent-client.js`, `public/rank-independent-main.js`. 창 간 분리를 위해 요청의 `pinned` 격리 경로를 사용하며 사용자에게 동기화 선택 옵션을 추가하지 않는다.
- `rank-independent-isolation.test.cjs`는 두 실제 브라우저 페이지와 릴레이에서 양방향 종목·주기 분리, 독립창 내부 주기·줌, 조회·새로고침 후 선택 유지를 검증한다. 기존 창 간 동기화를 요구하는 테스트 기대값은 이 정책으로 대체한다.

## 드래그 선택 영역 오른쪽 끝 (2026-10-23)

- 쏠림율의 드래그·휠·호버 경계와 봉 좌표에서 남아 있던 추가 24px 차감을 제거한다. 가격축 여백은 이미 공통 플롯 오른쪽 경계에 포함되어 있으므로 다시 빼지 않는다.
- 드래그 미리보기, 실제 선택 봉 계산, 가격 캔들 좌표는 동일한 플롯 경계를 사용한다. 차트 밖까지 드래그하면 선택 영역을 플롯 끝에 고정하고 최신 봉을 포함한다.
- `rank-drag-edge.test.cjs`는 독립 모드에서 쏠림율·ADR의 본체와 캔들에 실제 마우스 드래그를 수행해 반투명 선택 영역이 플롯 오른쪽 끝까지 도달하고 확대 후 최신 분봉 시각이 유지되는지 검증한다.

## 줌 바 위치의 공통 기준 (2026-10-23)

- 표시 기간을 동기화해도 줌 바를 차트별 원본 봉 인덱스로 계산하면 확보한 과거 페이지·결측 봉 수에 따라 손잡이 위치가 달랐다.
- 모든 줌 바는 현재 주기의 공통 전체 표시 가능 범위 안에서 보이는 구간의 상대 위치를 사용한다. 입력 범위는 내부적으로 0~10000으로 정규화하며, 같은 시간 구간이면 같은 손잡이 위치를 표시한다.
- 줌 바 이동은 원본 봉 인덱스가 아니라 공통 시간 좌표로 시작·끝을 정한다. 분봉의 08~09시 빈 구간과 데이터가 드문 구간도 같은 시간 폭으로 이동한다. 더 오래 수신한 원본 페이지 때문에 특정 카드의 손잡이가 앞뒤로 치우치지 않는다.
- 메인창과 독립창 각각에 적용하며 창 사이의 표시 상태를 전달하지 않는다. 빈 구간에서도 같은 주기의 축과 줌 바는 공유하고 지표 값은 생성하지 않는다.
- `updateSlider`, `scrollViewport`, `sliderDomain`이 계산·조작을 담당한다. `rank-chart-viewport.test.cjs`는 서로 다른 과거 페이지·결측 자료의 위치와 끝점 이동을, `rank-slider-sync.test.cjs`는 메인·독립 모드에서 실제 차트의 같은 손잡이 위치 및 좌우 끝 이동을 검증한다.


## 공통 마우스 시점 (2026-10-24)

- 같은 창의 8개 차트는 마우스가 선택한 날짜 또는 분 시각을 공유한다. 각 차트의 기존 호버 렌더링을 사용하므로 세로선·가로선·값 표시는 해당 차트 정책을 따른다. 캔들에서도 동일하게 적용한다.
- 일봉과 분봉은 같은 주기끼리 연결한다. 표시 범위에 정확한 시점이 없으면 인접 자료로 대체하지 않는다. 마우스 이탈·드래그 시작·취소 시 다른 차트의 호버를 해제한다.
- `registerHover`, `synchronizeHover`, `matchesHover`가 시점 전달을 담당한다. `rank-shared-hover.test.cjs`는 실제 마우스의 양방향 전달과 이탈 해제를 검증한다.

사용자가 어느 차트에서 시장을 선택하면 같은 페이지의 다른 차트 중 정확히 같은 내부 선택값을 가진 카드만 해당 값을 선택한다. KOSPI/KOSDAQ은 네 카드가 따라가며, 신고 합산 선택은 다른 카드 상태를 바꾸지 않는다. 선물 선택 역시 현물만 있는 카드의 상태를 바꾸지 않는다. 동일 시장을 이미 선택한 카드에는 중복 이벤트를 보내지 않고 재진입을 막아 순환 동기화를 방지한다. 시장수급의 일/분 전환에 따른 선택지 변경과 기존 선택 보관 정책은 유지한다. 선택 후 각 카드의 기존 조회·캔들 이름표 갱신을 사용한다.

검증: Chrome `rank-market-radio-sync.test.cjs`에서 한 카드 KOSDAQ 선택의 4카드 전파, 합산/선물 선택 시 미지원 카드 유지, 다른 카드 KOSPI 선택의 역방향 전파 및 캔들 실제 그리기를 확인했다. 기존 시장 선택/이름표 브라우저 테스트도 라디오 UI에 맞춰 갱신했다. 운영 배포 후 실제 데이터 검증은 별도다.

주기 전환과 당일 버튼은 이전 과거조회 epoch·대기 목표·공통 실패 안내를 초기화한다. 전환 이전 작업의 늦은 완료는 새 주기의 viewport/cutoff/안내를 적용하지 못한다. 분봉 당일 기준은 한국 날짜 08:00으로 재설정한다. 이전 작업의 완료가 새 작업의 busy 상태도 해제하지 않도록 epoch로 구분한다.

## 종목수급 분봉의 종목 변경 후 기간 복원 (2026-10-25)

종목 선택 시 공통 minuteDomain을 먼저 보관하고 새 종목 상태를 초기화한다. 최신 하루만 조회하던 경로를 수정해 공통 표시 기간 안의 각 날짜를 `/api/supply/chart?code=...&mode=minute&date=YYYY-MM-DD`로 다시 읽는다. 해당 날짜들을 minuteDays에 등록해 가격 캔들도 종목/날짜별로 확보한다. 공통 viewport는 변경하지 않으며 과거 범위를 선택한 상태면 당일 전용 상태로 되돌리지 않는다. 다음 과거 cursor는 확보한 공통 시작일보다 이전의 실제 보관 날짜로 갱신한다. 자동/수동 새로고침도 현재 공통 기간의 날짜별 기록을 다시 병합한다. 저장하지 않은 수급 값은 빈 구간으로 남기며 다른 종목 값을 재사용하지 않는다.

기존 요청 취소·응답 revision 검사를 유지하여 빠른 종목 변경의 늦은 응답이 현재 선택에 덮이지 않도록 한다. 가격 캐시 키는 기존대로 종목+날짜다.

검증: Chrome `rank-supply-symbol-history.test.cjs`에서 기본 응답은 최신 하루만 반환하도록 한 뒤 5일 공통 범위에서 삼성전자→SK하이닉스→삼성전자 전환 시 과거 4일 요청·5일 가격 캔들·종목 이름표가 유지됨을 확인했다. 기존 전체 분봉 캔들 회귀도 통과. 실제 보관하지 않은 날짜의 수급은 복구 생성하지 않는다.

## 다른 카드의 선택 변경 후 기간 점검 (2026-10-25)

종목수급과 같은 최신 페이지만 다시 조회하는 경로가 쏠림율(키움/한투) 종목 선택, 시장수급·ADR·신고 시장 선택에도 있어 보완했다. RankChartAxis.restoreHistoryRange는 현재 공통 시작 시점을 목표로 변경된 카드만 필요한 페이지를 추격하며 다른 카드의 과거 범위를 더 확장하지 않는다. 고정 커서의 progress, 실제 기준 페이지의 coverageFirst, 선택 identity와 busy/error를 함께 확인한다. 가격이 합쳐져 시간축만 길어졌다고 지표 기준 페이지도 확보한 것으로 오판하지 않는다.

쏠림율은 새 종목의 최초 조회가 완료된 뒤 공통 기간까지 추가 조회한다. 시장수급 분봉은 공통 기간의 날짜별 저장 수급과 응답 캔들을 다시 병합하고 선택 시장의 가격 보강을 완료한다. ADR·신고는 새 시장의 기준/지표 페이지를 추가 조회한 뒤 목표 가격 기간도 보강한다. 원천 과거 자료가 끝난 경우 지표는 결측으로 남기되 가능한 가격 보강은 수행한다. 선택이나 주기가 바뀌면 이전 복원 작업은 현재 선택을 덮지 않으며 실패는 해당 카드 안내로 남긴다.

거래대금은 원래 KOSPI/KOSDAQ 자료를 모두 보관하고 표시 선택만 바꾸므로 해당 최신 페이지 초기화 문제가 없다. 변동성·투자심리는 종목/시장 선택 자체가 없다. 한투 API 제한이나 미수집 한투 업종 금액처럼 실제 원천이 없는 문제까지 해결된 것으로 해석하지 않는다.

검증: 선택 카드만 여러 페이지로 공통 기간 추격·다른 카드 추가조회 없음·자료 끝에도 가격 ensure 실행을 포함한 목표 회귀 9개, Chrome 시장 라디오/캔들 회귀 및 종목수급 5일 왕복 회귀 통과. 실제 운영 선택 변경은 별도 확인한다.
