# 시장 수급(LS) 비교 카드

2026-10-25. 기존 시장 수급 카드는 유지하고 트레이딩 차트의 마지막에 추가한다.
두 카드는 `public/rank-market-supply-chart.js`의 같은 렌더러를 사용한다. 일봉·가격 캔들·0 표시·확대/드래그·과거 조회·공통 날짜축/마우스·시장 라디오·캔들 동기화 정책은 기존과 같다. 선택/표시 주체 설정은 `lsMarketSupply`로 별도 저장한다. 독립창에는 추가하지 않는다.

## 원천과 수집

- 일봉: 기존 한투 서비스와 캐시를 공유. 가격: 기존 키움 지수 서비스 공유.
- 현물 투자자: UBT `U001` / `U301`, 개인 `msval1`, 외국인 `msval2`, 기관계 `msval3`.
- 현물 프로그램: UPM `U0` / `U1`, `tval` 전체 순매수금액. 공식 필드 설명과 예제(`01`)가 서로 다르므로 실제 구독 성공과 시장 echo를 검증해야 한다. 추측한 다른 키로 자동 대체하지 않는다.
- 선물 후보: BMT `900` / `901`. `901`과 각 선물의 정확한 대상은 아직 미확인이다. 단순 구독 ACK나 데이터 도착만으로 코스닥150 선물이라고 판정하지 않는다. 선물 프로그램은 미제공이고 대응하는 현물지수 캔들을 유지한다.
- 서버 한 연결에서 여섯 구독을 공유한다. 실제 ACK에는 `tr_key`가 없으므로 한 요청의 ACK를 받은 다음 구독을 보낸다. `.env`의 `LS_APPKEY`, `LS_SECRETKEY`는 서버에서만 읽고 토큰/키/원본 axios 오류는 응답·로그에 출력하지 않는다.
- 공식 TLS 접속 주소만 사용한다. 연결 실패 시 5초~5분 지수 대기, 재연결 시 재구독, 토큰 만료 전 갱신을 수행한다.
- 평일 08:00~20:01 및 기존 `confirmMarket()`의 당일 개장 확인을 따른다. 선물은 15:46 이후 수신 자료를 저장하지 않는다.
- 계속 수신하면서 원천 시각의 분마다 마지막 유효값을 메모리에 보관하고 분이 끝나면 디스크에 쓴다. 동일 값의 새 원천 시각은 정상 관측이다. 새 메시지가 없으면 다음 분을 만들지 않는다. 실제 0은 보존한다.
- 시각의 앞 6자리를 HHmmss로 해석한다. 잘못된 시각, 미래, 2분 이상 지연, 시장 불일치, 역순 메시지는 제외한다. 8자리 시각의 마지막 두 자릿수 의미도 실수신 검증 대상이다.
- LS 원본은 `data/ls-market-supply/raw/<시장>/<날짜>.json(.gz)`에 저장한다. 기존 한투 분봉과 섞지 않는다. 원자적 쓰기·완료일 gzip은 공통 저장기를 사용한다.
- 시작/재연결 때 REST t1602의 당일 금액·누적(`gubun1=2`, `gubun3=''`), 통합(`exchgubun=U`) 이력을 조회한다. REST 자체의 단위·누적·시각이 확인된 시장만 보완한다. 이미 저장된 더 최신 원천 시각은 덮어쓰지 않는다. 미확인 선물, 프로그램의 과거 보완, 전일/오래된 원천 자료는 생성하지 않는다.

## 검증 대기와 활성화

실데이터의 금액 단위·누적 의미·시장·시각이 확정되기 전에는 원본을 수집하되 차트 수치는 미제공으로 유지한다. 추정한 금액 배율로 서로 다른 원천을 같은 축에 그리지 않는다. 이 제한은 현물에도 적용한다.

검증 결과는 Git 제외인 `data/ls-market-supply/validation.json`에서 읽는다. 재시작 없이 반영된다. 각 키 `UBT:U001`, `UBT:U301`, `UPM:U0`, `UPM:U1`, `BMT:900`, `BMT:901`에 다음 속성이 모두 필요하다.

- `market`: `kospi`, `kosdaq`, `futures`, `futuresKosdaq` 중 해당 시장.
- `cumulative`: 검증된 당일 누적이면 `true`.
- `timeFormat`: UPM은 `HHmmss`, 투자자는 `HHmmsscc`.
- `toMillionWon`: 원본 금액을 백만원으로 바꾸는 검증된 양의 배율.
- `evidence`: 공식 단위 설명 또는 같은 시점·시장 자료와 대조한 검증 근거.

REST 보완은 `t1602:U001`, `t1602:U301`에 같은 속성을 별도로 기록해야 한다. REST와 웹소켓이 같은 단위라고 가정하지 않는다. 근거 없는 예제 배율을 운영 파일에 복사하지 않는다.

## 현재 확인 결과

2026-10-26: 현물 UPM U0/U1의 프로그램 표시를 활성화했다. LS 저장 자료와 기존 한투 FHPPG04600101 UN 저장 자료를 08:13~08:25 완료 분별로 대조했으며 코스피·코스닥 각각 13개 분 모두 누적 순매수금액의 차이가 백만원 기준 0~1이었다. toMillionWon=1로 기록했다. 진행 중인 최신 분은 대조에서 제외했다. 검증 파일은 실행 중 서버가 조회마다 읽으므로 재시작 없이 반영된다. UBT와 선물 BMT의 활성화 여부와 독립적이다.

2026-10-25 23:36 KST, 키 갱신 후 공식 토큰 발급과 웹소켓 연결이 성공했다. UBT 두 키, UPM 두 키, BMT 900/901 여섯 구독 요청 모두 `00000` 정상 ACK를 받았다. ACK에는 tr_key가 없었다. 휴장일의 15초 관측 동안 데이터 메시지는 0건이었다.

같은 인증으로 t1602 금액·누적 조회도 성공했다. 통합 `001`/`301`은 `ex_upcode=U001/U301`과 각 3개 시간 행, KRX `900`도 3개 행을 반환했다. `901`은 정상 응답 코드와 ex_upcode=901을 반환했지만 시간 행 0개, 집계값 모두 0이었다. 이를 실제 0 수급 또는 코스닥150 선물 지원으로 확정하지 않는다. 휴일 REST 응답에는 날짜가 없어 당일 자료로 저장하지 않았다.

인증 문제는 해소됐다. 실제 장중 데이터, 단위/시각/누적/선물 대상 검증은 남아 있어 활성화 기록은 만들지 않았다. 키와 토큰은 출력하거나 저장하지 않았다. 비밀값 없는 조회 결과는 Git 제외인 `dev/output/ls-validation-probe.json`에 보관했다.
