# 시장 수급

최종 갱신: 2026-10-24, 한국 시간. 메인 Rank 카드이며 독립창의 기존 구성은 유지한다. 화면의 공통 조작·기간 정책은 [Rank 공통 차트 정책](RANK_CHART_POLICY.md), 종목별 원천과 수량 단위는 [종목 수급](SUPPLY_CHART.md)을 함께 참고한다.

## 화면

- 3열 배치: 첫 줄 쏠림율 / 종목 수급 / 시장 수급, 둘째 줄 신고/신저 / 거래대금 / 변동성, 셋째 줄 CNN / ADR.
- 일봉 시장 선택: 코스피·코스닥. 프로그램 / 외국인 / 기관 / 개인의 4개 독립 영역과 0 수평선. 기준선의 숫자 0은 표시하지 않는다. 양수 빨강, 음수 파랑. 영역마다 보이는 값의 절댓값으로 높이를 정하므로 주체 사이 막대 높이로 금액 크기를 비교하지 않는다.
- 분봉 시장 선택: 코스피·코스닥·코스피 선물·코스닥 선물. 종목 추가 기능은 없다. 기존 수급과 같은 선 색상과 두 행 레이블을 사용한다. 금액을 사용하므로 주/천주 표기를 적용하지 않는다.
- 선물 프로그램은 미제공이며 선을 만들거나 0으로 채우지 않는다. 사용자 결정에 따라 코스피200 선물에는 코스피, 코스닥150 선물에는 코스닥 현물 지수 캔들을 표시하고 캔들 위에 현물지수임을 명시한다. 실제 선물 가격이나 연결선물로 표시하지 않는다.
- 공통 확대·축소, 휠, 드래그, 슬라이더, 날짜축, 일/분 전환, 과거 조회, 캔들 열림/닫힘을 공유한다. 메인 플롯 높이와 시작선, 상태/출처 하단 줄도 기존 수급 정책을 따른다.
- 시장·봉 종류·표시 주체는 `rankChartDisplay.marketSupply`에 저장한다. 캔들 상태는 메인 공통 설정을 따른다. 카드 출처는 한투다.

## 원천과 확인 사항

- 투자자 일별: FHPTJ04040000. `KSP/0001`, `KSQ/1001`, `FID_COND_MRKT_DIV_CODE=U`, 두 입력 날짜는 동일하다. 개인 `prsn_ntby_tr_pbmn`, 외국인 `frgn_ntby_tr_pbmn`, 기관 `orgn_ntby_tr_pbmn`을 사용한다.
- 투자자 분별: FHPTJ04030000의 현재 스냅샷을 1분마다 관측한다. 현물은 위 시장 코드, 코스피200 선물은 `K2I/F001`, 코스닥150 선물은 `KQI/F002`. 원천 시각/날짜가 없는 TR이므로 저장 시각은 관측 시각이며 미수집 분봉을 소급 생성하지 않는다.
- 프로그램 일별: FHPPG04600001, `FID_COND_MRKT_DIV_CODE=UN`, `FID_MRKT_CLS_CODE=K/Q`. 전체 순매수대금 `whol_smtn_ntby_tr_pbmn`을 우선 사용하며 미제공일 때만 차익+비차익 합계를 사용한다. 어느 한쪽이 결측이면 합계도 결측이다.
- 2026-10-24 실제 코스피 일별 조회에서 UN은 2025-01-01~28을 0건, J는 17건 반환했다. UN의 2026년 3·7·8월 표본 구간은 정상 반환했다. 통합 과거 미제공 구간을 KRX로 임의 대체하지 않는다. 빈 프로그램 날짜 범위를 만나도 더 오래된 범위 조회는 계속하며 결측 안내를 남긴다.
- 프로그램 분별: FHPPG04600101, 동일한 UN/K/Q. 최근 30개 원천 시각 `bsop_hour`의 전체 순매수대금을 병합한다. 중복 시각은 갱신하고 미래 시각·다른 날짜가 명시된 자료·20:00 이후 시각은 제외한다.
- 2026-10-24 실서버 읽기 검증: 네 TR 모두 정상 응답. 투자자 일별 코스피/코스닥 각 300행, 투자자 시세 코스피/코스닥/선물 각 1행, 프로그램 일별 양 시장 각 15행(2026-10-01~23), 프로그램 시세 코스피 30행을 확인했다. 프로그램 UN 시간 응답은 19:36~20:05였고 최신 값은 전일 일별 마감과 일치했다. 공식 예제의 15:30 이후 제한을 UN 원천에 그대로 적용하지 않는다. 휴일 조회 결과를 당일 관측으로 저장하지 않는다.
- **투자자 통합시장 범위는 미확정이다.** 투자자 두 TR에는 거래소 선택 입력이 없다. 2026-10-23 KIS 코스피 외국인 -978,948(대금 원본)과 키움 명시적 통합 조회 -11,028억원이 달랐다. 키움 KRX 값은 -9,785억원이었다. 서로 다른 증권사의 집계 차이도 가능하므로 이를 통합 지원이나 미지원의 최종 증명으로 단정하지 않는다. 화면에 통합 집계 여부 미확인 경고를 표시한다. 프로그램 UN 지원과 구분한다. 사용자는 지정 TR 우선과 통합 여부 미확인 표시를 선택했다. 투자자 원천은 한투 두 TR을 유지하고 프로그램은 UN을 사용한다.

## 수집·과거 조회

- 서버 공통 수집기 한 개. 브라우저 접속 수와 무관하게 60초마다 네 시장을 수집한다. 기존 `supply.confirmMarket()`의 당일 개장 확인과 평일 한국 시간 08:00~20:01 조건을 사용한다. 선물 주간 관측은 15:46 이후 중단한다.
- `data/market-supply/KOSPI0|KOSDAQ|FUTURE|FUTKQ0/YYYY-MM-DD.json`에 분별 자료를 저장한다. 기존 수급 저장기를 재사용해 동일 분 병합, 누락과 실제 0 구분, 원자적 쓰기, 20:02 이후 무손실 검증 gzip 압축을 적용한다. Git에서는 제외한다.
- 일봉은 영구 저장하지 않는다. 과거 원천 자료와 조회 완료 범위는 메모리에 6시간 보관하고 최신 결과는 60초간 재사용한다. 갱신 시 최근 두 거래일과 미조회 범위만 요청한다. 실패한 범위는 다시 조회하고 과거 페이지 결과도 6시간 재사용한다. 서버 재시작 시 캐시는 초기화된다. 기준 봉 수와 날짜는 실제 코스피/코스닥 지수 일봉 한 페이지를 따른다. 투자자는 가장 오래 받은 날짜 이전으로, 프로그램은 날짜 범위로 추가조회하며 실제 자료만 기준 날짜에 결합한다.
- 가격·투자자·프로그램은 도착하는 대로 화면에 표시하며 중간 결과 확인은 동일한 조회 작업을 공유한다. Y축 주체 이름은 범례와 같은 색이며 각 행의 0 기준선에 맞춘다.
- 분봉 과거 조회는 저장 자료와 가격의 이전 날짜를 사용한다. 현물 지수 캔들은 기존 `chart-reference-service`를 사용한다. 일별 값을 분별로 펼치지 않는다. 조회 실패 후 화면의 기존 정상값은 유지한다.
- 인증된 `GET /api/market-supply/chart?code=kospi|kosdaq|futures|futuresKosdaq&mode=day|minute&cursor=...`. 일봉 cursor는 가격 API의 불투명 키, 분봉 cursor는 YYYYMMDD다. 선물 일봉은 지원하지 않는다.

## 로딩 시간 개선

종목 수급과 시장 수급의 일봉에 같은 캐시·중간 결과 전달 방식을 적용했다. 이전에는 가격 기준 봉을 받은 뒤 투자자·프로그램 과거 페이지를 모두 받아야 화면을 완성했고, 짧은 결과 캐시가 만료되면 오래된 페이지도 다시 조회했다. 시장 프로그램은 날짜 범위를 여러 번 조회하므로 전체 완료까지 기다리는 시간이 길어질 수 있었다.

- `daily-query-cache.js`의 원천별 이력 캐시는 정상 조회한 날짜 범위와 실제 자료를 6시간 보관한다. 최신 결과는 60초, 과거 cursor 결과는 6시간 재사용한다. 메모리만 사용하므로 재시작·만료·캐시 퇴출 후 최초 조회에는 다시 과거 요청이 필요하다.
- 최신 갱신은 가격 기준 봉의 최근 두 거래일과 아직 받지 않은 범위만 다시 조회한다. 투자자와 프로그램은 별도 작업으로 시작하지만 실제 한투 HTTP 호출은 기존 단일 큐와 요청 간 300ms 간격을 유지한다. 무제한 병렬 호출 방식이 아니다.
- 가격 기준 봉이 도착하면 첫 중간 결과를 보내고, 투자자·프로그램은 페이지가 도착하는 대로 채운다. 일봉 화면은 `progressive=1`로 조회하며 `pending=true`인 동안 400ms 간격으로 같은 작업의 중간 결과를 확인한다. 마지막 결과의 `pending=false`에서 확인을 끝낸다. 일반 API 호출은 중간 옵션 없이 완료 결과를 기다린다.
- 동일한 시장·cursor 조회가 진행 중이면 여러 화면의 요청도 작업 하나를 공유한다. 중간 결과 확인 횟수가 원천 TR 호출 횟수로 늘어나지 않는다. 갱신 중에는 기존 정상값을 유지하며 늦게 도착한 이전 선택의 응답은 현재 선택에 적용하지 않는다.
- 실패·부분 조회 범위는 정상 완료 범위로 기록하지 않아 다음에 재시도한다. 결과 경고에 실패·오류·한도·미제공이 있으면 결과 캐시를 5초로 줄인다. API가 반환하지 않은 과거 자료를 캐시로 만들어내지는 않는다.
- 프로그램은 최대 28일의 달력 날짜 범위로 나누어 조회한다. 한 범위가 비어도 다음 과거 범위를 계속 조회한다. 투자자는 응답의 가장 오래된 날짜 이전으로 이동한다. 각각 한 작업의 과거 조회 상한은 100회다.

검증에서는 시장 일봉 70일 모의 자료의 첫 조회가 투자자 1회+프로그램 3회였고, 60초 만료 후 갱신은 투자자 1회+최근 프로그램 1회로 줄었다. 종목 수급도 과거 연속 페이지를 반복하지 않고 최근 두 거래일만 갱신하며 날짜 전환 후 신규 거래일을 추가하는 것을 확인했다. 프로그램 응답을 지연시킨 검사에서는 투자자 중간 결과가 먼저 표시되고 중간 확인 요청이 중복 작업을 만들지 않았다. 이는 호출 수와 표시 순서 검증이며 실제 서버의 로딩 초수나 개선율을 측정한 결과는 아니다.

## 날짜축·십자선 동기화

- 기본 일봉부터 공통 날짜 목록으로 봉 위치와 날짜 눈금을 계산한다. 원천별 결측 날짜 때문에 같은 날짜가 서로 다른 위치에 놓이지 않도록 한다. 줌·드래그·슬라이더는 봉 인덱스 대신 같은 시간 범위를 공유한다.
- 같은 창에서 마우스가 선택한 날짜/분 시각을 다른 차트로 전달한다. 각 차트는 기존 호버 정책에 따라 세로선·가로선·값을 표시한다. 표시 범위에 정확한 시점이 없으면 인접 자료를 대신 표시하지 않는다. 일봉과 분봉은 같은 주기끼리 연결하고 마우스 이탈 시 함께 해제한다.
- 독립창에는 시장 수급 카드를 추가하지 않는다. 기존 쏠림율·종목 수급도 공통 날짜축을 사용하며 좌우 그리기 여백을 맞춘다. 서로 다른 날짜가 빠진 두 차트에서도 날짜 레이블과 양방향 마우스 세로선의 화면 위치가 일치하는지 검증했다.

## 선물 캔들 최종 결정 (2026-10-24)

- 사용자가 현물 지수 캔들로 대체하기로 결정했다. 선물 가격 TR FHKIF03020100/FHKIF03020200 및 연결선물 합성은 사용하지 않는다. 코스피200 수급은 K2I/F001, 코스닥150 수급은 KQI/F002로 수집한다. 두 시장의 프로그램 값은 결측이다.
- KQI/F002 실서버 읽기 검증에서 개인·외국인·기관 순매수대금이 정상 반환됐다.
- 가격은 기존 키움 ka20005 조회·캐시를 공유한다. 선물별 priceMarket을 kospi/kosdaq로 매핑하며 종목 선택과 가격 데이터의 명칭을 구분한다. 과거 수급과 같은 날짜의 실제 지수 캔들을 결합하고 없는 가격을 만들지 않는다.
- 모든 봉의 t와 공통 RankChartAxis 등록을 유지한다. 시장 수급의 줌·슬라이더 조작은 다른 차트에 같은 날짜/시각 범위를 전달하며 봉 수가 아닌 시간축으로 맞춘다. 일봉/분봉 전환과 과거 조회도 공통 정책을 따른다. 선물에서 일봉으로 전환하면 대응하는 현물 시장을 선택한다.
- 사용자가 보고한 EADDRINUSE 원인은 기존 로컬 Node 서버(PID 663504)였다. 포트 소유 명령을 확인하고 로컬 HTTP 페이지와 현재 index.html의 SHA256이 일치함을 확인한 뒤 해당 프로세스만 종료했으며, 종료 직후 3000번 리스너가 0개임을 확인했다.

## 드래그 직후 클릭으로 줌 해제되는 문제 추가 수정 (2026-10-24)

## 시장수급 분봉 가격의 공통 기간 보강 (2026-10-24)

사용자 이미지에서 시장수급만 이전 날짜 가격이 비는 현상을 보고 기존 시장수급 응답의 캔들만 사용하는 구조를 보강했다. 분봉 캔들을 펼치면 공통 minuteDomain의 시작/끝 날짜로 `/api/adr/candles`를 요청한다. 코스피·코스닥 및 선물 수급의 실제 현물 가격 시장을 사용하며 받은 캔들을 시각별 병합한다. 수급 값이 없는 가격 시각은 시간축 슬롯만 추가하고 수급 값을 만들지 않는다. 공통 기간 확대 시 부족한 범위를 조회하고 같은 범위의 진행 요청은 중복 실행하지 않는다. 시장·조회 전환 시 진행 요청을 취소하며 오래된 응답을 적용하지 않는다. 가격 조회 실패·부분 응답은 상태로 알리고 기존 캔들은 유지한다. 기존 서버 공통 지수 캐시를 사용한다.

`all-minute-candles.test.cjs`에서 이틀 수급/다른 카드 가격은 있으나 시장수급 응답은 최신 5봉만 주는 경우, 공통 과거 더 불러오기로 10/22~10/23 가격을 보강하여 전체 정상 봉을 그리는 것을 검증했다. 무효 OHLC 한 봉은 제외하고 두 날짜 및 시장 전환은 유지한다. 실제 사용자 화면은 최신 정적 스크립트 적용 후 재검증해야 한다. 진단 결과 `{}`는 두 진단 함수가 해당 페이지에 없다는 의미이며 데이터가 0봉이라는 의미가 아니다.
