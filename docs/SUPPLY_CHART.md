# 종목별 수급 차트

> 2026-10-21 신고가·신저가 수집기와 개장 확인을 공유한다. 신고가·신저가 수집기가 활성화된 서버에서는 수급 등록 종목이 없어도 개장 확인을 수행한다. 기존의 “등록 종목이 없으면 개장 확인도 하지 않는다”는 수급 단독 수집기 설명이며, 현재 서버 전체 동작은 [신고가·신저가 정책](BREADTH_CHART.md)을 따른다.

최종 정책 기준: 2026-10-21, 한국 시간. 구현 파일과 실제 조회 결과를 대조해 이 대화의 최종 결정을 정리했다. API 전환 검토 등 이전 결정과 충돌하면 이 문서의 현재 정책을 따른다. 독립창은 [사용·설치 안내](../desktop/README.md), 변경 적용과 점검은 [운영 절차](operations/server-runbook.md#9-수급-차트와-독립창-변경-적용)를 함께 참고한다.

## 데이터 원천과 수량 의미

- 개인·외국인·기관의 일봉과 장중 관측은 `ka10060`, `/api/dostk/chart`를 사용한다. 조건은 `stk_cd=<code>_AL`, `amt_qty_tp=2`, `trde_tp=0`, `unit_tp=1`이다.
- 프로그램 일봉은 `ka90013`, `/api/dostk/mrkcond`, `amt_qty_tp=2`로 조회한다.
- 프로그램 장중 관측은 `ka90008`, `/api/dostk/mrkcond`, `amt_qty_tp=2`로 조회한다.
- 모든 종목별 조회는 통합시장 코드 `<code>_AL`을 사용한다. 표시 단위는 주다. 프로그램과 투자자별 분류는 중복될 수 있으므로 합산하지 않는다.
- 일봉은 해당 거래일의 순매수수량, 1분봉은 매분 관측한 **당일 누적 순매수수량**이다. 1분간 순매수 증분이 아니며, 날짜를 이어 그려도 서로 다른 거래일의 누적값을 합산하지 않는다.
- 개인을 고정 0으로 두는 정책은 취소했다. 세 투자자 모두 실제 API 값을 기록한다. API가 반환한 0은 유효한 값이며, 미제공·조회 실패는 0과 구분한다.

## 종목 지정과 수집 주기

서버 공통 수집 목록은 최대 5종목이다. 화면에서 한 종목을 선택해 보되 나머지 종목도 서버가 계속 수집한다. 화면 갱신과 백그라운드 수집은 별개다.

- 서버 시작과 종목 목록 변경 후 수집을 시도하고, 한국 시간 평일 08:00~20:01에 60초 간격으로 반복한다. 브라우저 접속·표시 종목·탭 활성 여부와 무관하다.
- 화면에는 별도 조회 버튼이나 전용 1분 타이머를 두지 않는다. 기존 트레이딩 화면 갱신 주기에서 수급을 함께 조회한다. 독립창도 기존 서버 갱신 경로를 이용한다.
- 중복 수집 실행을 합치고 각 수급 API 요청 사이에 300ms 간격을 둔다. 다른 기능의 키움 요청 큐와 별개이므로 전체 요청 제한이 자동으로 통합 관리되는 것은 아니다.
- `ka10060`의 응답에 당일 날짜가 있는지 확인한 뒤 수량을 기록한다. 시각만 반환하는 `ka90008`도 같은 거래일의 날짜 확인 후 기록하며 `program_at`에 원천 시각을 남긴다. 당일 자료가 없는 휴일에 전일 값을 오늘 자료로 만들지 않는다.
- 일부 주체나 종목 조회가 실패해도 다른 값은 계속 수집한다. 등록 삭제·재등록 도중 돌아온 이전 응답으로 새 기록을 쓰지 않는다.

## 저장과 용량

일봉은 API로 다시 조회할 수 있으므로 네 주체 모두 영구 저장하지 않는다. 요청 결과는 60초 메모리 캐시만 사용한다. 가격 캔들도 수급 파일에 저장하지 않는다.

분봉만 같은 서버에 저장한다. 최종 구현은 별도 DB 없이 JSON과 gzip을 사용한다.

- `data/supply/watchlist.json`: 수집·보관 종목과 동시 편집 방지 `revision`.
- `data/supply/<code>/YYYY-MM-DD.json`: 당일 관측 기록. 같은 분은 최신 관측값으로 갱신하며 임시 파일 작성 후 rename한다.
- 한국 시간 20:02 이후 그날 자료를 `YYYY-MM-DD.json.gz`로 무손실 압축한다. 압축을 풀어 원본 바이트와 일치하는지 확인한 후에만 JSON 원본을 제거한다.
- 시작 시점과 1분 주기 점검에서 지난 날짜의 미압축 파일도 처리한다. 수집에서 제외한 종목의 기록도 압축 대상이다.
- 과거 요청은 JSON 또는 gzip을 읽고, gzip은 메모리에서 해제한다. 디스크에 다시 펼치지 않는다. 중단으로 둘 다 남으면 JSON을 우선 읽고 압축 검증을 다시 수행한다.
- 종목을 삭제해도 과거 파일은 유지하며 팝업의 보관 기록에서 조회한다. 자동 삭제나 보존 기간 제한은 구현하지 않았다.
- 데이터는 Git에서 제외한다. 서버를 단일 PM2 인스턴스로 운용하고 여러 수집기를 동시에 실행하지 않는다.

네이버 카페 날짜별 게시글 저장과 사용자 PC 저장은 검토만 했으며 구현하지 않았다. 수집 이전·중단 구간을 일봉에서 분봉으로 소급 생성하지 않는다. 기존 관측 기록을 API 변경 시점에 임의로 고쳐 쓰지도 않는다.

## 메인 화면과 조작

현재 메인 배치는 쏠림율 오른쪽에 수급, 기존 수급 위치인 신고가·신저가 아래에 ADR이다. 처음 제안했던 신고가 아래 수급 배치는 취소했다.

- 제목 옆 `+ 종목 추가`에서 별도 팝업을 열어 검색·추가·삭제한다. 별도 종목관리 버튼이나 메인 화면의 종목 옆 삭제 X는 없다.
- 종목 드롭다운, 일봉, 1분봉(누적), 과거 조회 아이콘, 캔들차트 버튼을 한 줄에 배치한다. 드롭다운에 ‘종목선택’ 안내 옵션은 두지 않는다.
- 종목명은 Unicode 기준 6글자로 줄이며 전체 이름은 마우스오버로 표시한다. 팝업의 방향키·Enter·Escape 조작을 지원한다. 쏠림율과 같은 IME 중복 입력 방어로 화살표를 한 번 눌렀을 때 강조 항목이 한 번 이동한다.
- 개인은 파랑 `#339af0`, 외국인은 빨강 `#e11d48`, 기관은 초록, 프로그램은 보라다. 우측 상단에 `개/외/기/프` 한 글자와 수치를 표시하고 점 표식은 두지 않는다.
- 상단 값은 각 주체의 마지막 유효 관측값이다. 가격만 있는 마지막 봉이나 다른 주체의 누락 때문에 ‘미제공’으로 바꾸지 않는다. 값 위 마우스오버로 기준 날짜·시각을 표시한다.
- 같은 시점의 갱신 응답에서 주체 값이 빠지면 기존 유효 값을 유지한다. 다른 시점의 빈 값을 이전 값으로 채우거나 0으로 만들지는 않는다.
- 과거 조회는 쏠림율과 같은 캔들+ 아이콘을 1분봉 버튼 바로 오른쪽에 둔다. 모든 차트의 캔들 버튼 앞 간격은 10px다.
- 메인 차트의 마우스 정보 영역은 20px, 본체 플롯 높이는 260px로 통일했다. 정보 영역은 숨겨져도 공간을 유지하며 위아래 여백은 1px이다. 가로 눈금선은 다른 차트와 같은 `#b8c1cc`, `[3,5]` 점선이다.
- 수급 카드 전체 크기는 쏠림율 기준 카드 크기를 따른다. 메인 수급 캔들은 280px를 추가하며 독립창의 캔들 높이 정책과 구분한다.
- 상태 문구는 한 줄로 표시하고 넘치는 내용은 생략·툴팁 처리한다. 확대·축소·드래그·슬라이더와 개별 주체 표시 전환을 제공한다.

## 과거 조회와 누락 처리

일봉의 최초 날짜·봉 수는 쏠림율과 같은 `ka10081` 첫 페이지를 기준으로 한다. 별도 6M·1Y 기간 버튼은 두지 않는다. 과거 조회 아이콘은 더 이전 날짜의 페이지를 추가하며 갱신 후에도 이미 읽은 구간과 조회 위치를 유지한다.

분봉은 날짜 선택 없이 과거 조회를 누를 때마다 이전 거래일을 같은 시간축에 이어 그린다. 저장 수급의 cursor와 가격 API의 cursor를 함께 확인한다. 수급 기록이 없어도 가격 과거 자료가 있으면 조회 버튼을 활성화하고 가격만 표시할 수 있다.

캔들 열림·접힘은 사용자가 선택한다. 봉 종류 변경·새로고침·과거 조회·수급 미제공을 이유로 자동으로 펼치지 않는다. 캔들을 접어도 가격의 이전 거래일 유무를 확인하기 위한 조회는 수행할 수 있다. 캔들을 열면 수급 없는 구간에도 실제 가격을 표시하며 수급 값은 만들지 않는다.

일봉 연속조회는 일시 실패를 한 번 재시도한다. 중간 페이지가 계속 실패하면 이미 받은 구간을 반환하고 실패 원인을 함께 표시한다. 실패한 한 페이지 때문에 프로그램 전체 이력을 버리지 않는다.

## 독립창 최종 정책

- 위에서부터 **거래대금 상위 목록 → 쏠림율 → 수급**, 항상 세로 한 열이다.
- 쏠림율·수급 종목 선택은 메인과 양방향 동기화한다. 종목동기화 해제 옵션은 제거했다. 봉 종류·간격과 공유 조건도 연동한다.
- 캔들 열림·접힘, 카드 접기·펼치기, 줌·스크롤은 창별로 유지한다. 메인의 캔들 상태를 최초 실행 때도 독립창에 가져오지 않는다.
- 캔들을 열 때 그 카드 본체의 현재 높이만큼 아래에 추가한다. 본체와 다른 카드 높이는 유지한다. 닫으면 해당 공간만 제거한다.
- 창 자동 변경은 가로 증감 0으로 요청한다. 사용자가 바꾼 너비를 초기 너비로 돌리지 않는다. 모니터 높이에 제한되면 내부 스크롤을 쓰고 실제 늘어난 창 높이만 복원한다.
- 수동 크기 변경과 네이티브 자동 변경 완료 신호를 구분한다. 캔들 토글로 다른 카드 높이를 다시 나누지 않는다.
- 거래대금 제목 옆 `⇅`는 **5개 → 10개 → 기본** 순서다. 목록·카드 높이만 조절하고 다른 차트·너비는 유지한다. 데이터 갱신 후에도 선택한 개수를 유지한다.
- 조회 중 도착한 공유 상태는 조회가 끝나면 다시 적용한다. 수급 설정은 실제 변경한 필드만 전달해 지연된 캔들/표시 설정이 새 종목 선택을 덮어쓰지 않도록 한다. 캔들 상태는 공유 필드에서 제외한다.

## API와 관련 파일

기존 로그인 인증을 적용한다.

- `GET /api/supply/watchlist`: 수집·보관 목록과 상태.
- `PUT /api/supply/watchlist`: `{ codes: ["005930"], revision: 0 }`. 최대 5개, 중복 금지, 서버 종목 마스터 확인. 동시 변경은 409다.
- `GET /api/supply/chart?code=005930&mode=day[&cursor=YYYYMMDD]`: 일봉·가격 캔들·경고·과거 cursor.
- `GET /api/supply/chart?code=005930&mode=minute[&cursor=YYYYMMDD]`: 최신 또는 이전 저장 거래일. `investor_api=ka10060`, `individual_supported=true`다.
- `GET /api/supply/candles?code=005930&mode=minute[&date=YYYY-MM-DD]`: 실제 가격 분봉과 이전 거래일 cursor. 일봉은 수급 응답에 포함된 캔들을 재사용한다.
- `GET /api/server/storage`: 데이터 저장 디스크의 전체·사용 가능한 여유 공간. 헤더의 ‘서버에서 불러오기’ 왼쪽에 남은/전체 GB를 표시하고 5분 및 화면 갱신에 맞춰 조회한다. 1,024³바이트를 GB로 표기한다.

서버 구현은 `supply-service.js`, `supply-store.js`, `server-storage.js`, `server.js`에 있다. 화면은 `public/rank-supply-chart.js`, `public/server-storage.js`, 독립창은 `public/rank-independent-*`와 `rank-independent.js`, 네이티브 앱은 `desktop/IndependentWindow.cs`를 사용한다.

## API 확인 기록과 해석

- 2026-10-20 장 종료 후 삼성전자·SK하이닉스의 20거래일 개인·외국인·기관 수량/금액이 ka10059와 일치하는 것을 확인했다. 이후 ka10060을 최종 원천으로 선택했다.
- 실제 일봉 조회에서 삼성전자·SK하이닉스의 각 600봉에 프로그램 값이 모두 있었고, 삼성전자 최초 600봉 날짜·개수가 쏠림율과 일치했다. 초기 범위는 2024-04-29부터였으며 2025-10-20 제한은 최종 정책이 아니다.
- 2026-10-21 09:05:16과 09:06:07에 ka10060 당일 개인·외국인·기관이 두 종목 모두 0이었다. 같은 시간 전일 값은 정상이고 프로그램과 저장 시각은 갱신됐다. 이 관측만으로 ka10060이 장중 내내 갱신되지 않는다고 결론 내리지는 않는다.
- 사용자 요청으로 ka10063 전환을 시도했으나 확인 당시 외국인·기관 목록은 빈 배열이었다. 사용자 확인 후 ka10060으로 복원했다. 복원된 수집기 실측에서 삼성전자 외국인 +407,000주, SK하이닉스 +4,000주가 기록됐고 개인·기관은 당시 0이었다. 이는 당시 관측값이며 현재 값이나 고정 갱신 주기가 아니다.
- 09:16 점검 당시 로컬 서버는 08:46 시작 프로세스여서 중간 코드 변경이 메모리에 반영되지 않은 상태였다. Node 서버 코드 변경은 브라우저 새로고침만으로 적용되지 않는다.
- 검증용 원시 결과와 스크립트는 Git에서 제외한 `dev/output/`에 있다. 이 확인으로 Oracle 운영 서버 배포나 실사용 PC 재설치를 완료했다고 간주하지 않는다.
