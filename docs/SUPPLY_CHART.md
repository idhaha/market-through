# 종목별 수급 차트

독립창에서도 같은 수급 차트를 사용한다. 거래대금 상위 목록 → 쏠림율 → 수급을 한 열로 배치하며 각 카드를 독립적으로 접고 펼칠 수 있다. 수급 종목은 기본적으로 메인 화면과 양방향 동기화하고, 수급 제목 옆의 종목동기화 해제를 선택하면 해당 창의 종목을 따로 유지한다. 봉 종류·캔들·표시 주체 설정은 동기화한다. 독립창의 API 조회와 종목 목록 변경은 기존 인증 릴레이를 거치고, 서버의 독립창 갱신 주기에도 수급을 포함한다. 분봉 과거 조회는 저장된 수급과 가격을 함께 이어 붙이며, 수집 이전 구간에는 가격만 표시한다. 작은 창에서는 카드 높이를 확보하고 내부 세로 스크롤을 사용한다.

트레이딩 탭의 쏠림율 차트 오른쪽(기존 ADR 위치)에 표시한다. 서버의 공통 수집 목록은 최대 5종목이며, 차트에서 한 종목을 선택하는 동작은 수집 목록을 변경하지 않는다. 제목 바로 옆의 `+ 종목 추가`를 누르면 별도 팝업에서 검색·등록할 수 있다. 등록한 종목은 그 아래 한 줄의 드롭다운에서 선택하고, 바로 오른쪽에 일봉·1분봉·과거 조회 아이콘·캔들차트 버튼을 둔다. 추가 즉시 서버에 저장하며 팝업 안의 목록에서 삭제하면 수집 목록에서 제외하고 기존 분봉은 유지한다. 제외된 종목은 팝업 안의 보관 기록 버튼에서 조회할 수 있다. 개인은 파란색(#339af0), 외국인은 빨간색(#e11d48), 기관은 녹색, 프로그램은 보라색으로 표시한다.

종목 드롭다운의 표시 이름은 Unicode 문자 기준 최대 6글자로 제한하고 전체 이름은 옵션과 선택창의 툴팁으로 제공한다. 수급 수치는 별도 행을 차지하지 않고 카드 우측 상단에 `개/외/기/프` 한 글자와 값만 표시하며 점 표식은 사용하지 않는다. 차트의 조회 버튼과 독립된 60초 화면 타이머는 없고, 기존 트레이딩 화면 갱신 주기의 `loadTransactionRank`에서 수급 화면 조회를 함께 요청한다. 서버 분봉 수집기는 화면 갱신 주기와 별개로 60초 수집을 유지한다.

종목 추가 팝업의 자동완성은 ↑/↓로 후보를 이동하고 Enter로 강조한 종목을 등록한다. 처음 ↑를 누르면 마지막 후보를 선택하며 양 끝에서 순환한다. 입력창의 포커스를 유지하고 강조 후보를 스크롤해 보여준다. Escape는 열린 후보 목록을 먼저 닫는다. combobox/listbox/option 및 aria-activedescendant로 키보드 선택 상태를 제공한다.

쏠림율 자동완성과 동일하게 완성된 검색어가 변하지 않는 한 IME의 중복 입력 이벤트로 후보 목록과 강조 상태를 초기화하지 않는다. 조합 중 단독 자모를 제외하고 compositionupdate/end를 반영한다. 키보드 선택 뒤 스크롤로 발생한 마우스 이벤트가 선택을 덮어쓰지 않도록 후보 강조는 방향키가 관리하고 마우스는 클릭으로 선택한다. 일봉의 과거 데이터 더 불러오기 버튼은 하단이 아니라 일봉·분봉·캔들 버튼과 같은 상단 제어 줄에 배치한다.

과거 데이터 더 불러오기는 쏠림율과 동일한 28px 캔들+ 아이콘을 사용하며 1분봉 버튼 바로 오른쪽에 둔다. 텍스트 대신 툴팁과 접근성 이름으로 용도를 제공한다.

수급 카드 전체 너비는 같은 그리드 열 너비를 사용하고, 전체 높이는 쏠림율 카드에서 캔들 영역을 뺀 기본 높이와 맞춘다. 수급 캔들을 펼칠 때만 280px를 더한다. 고정 최소 높이 620px는 사용하지 않으며, 내부 그래프가 남은 공간에 맞춰 줄어들도록 한다. 기준 카드 크기 변경도 ResizeObserver로 반영한다. 브라우저 테스트에서 카드 너비·높이 일치와 450→730px 캔들 확장을 확인했다.

## 데이터 원천과 저장 정책

- 개인·외국인·기관: `ka10060`, `/api/dostk/chart`, `amt_qty_tp=2`, `trde_tp=0`, `unit_tp=1`.
- 프로그램 일봉: `ka90013`, `/api/dostk/mrkcond`, `amt_qty_tp=2`.
- 프로그램 장중 관측: `ka90008`, `/api/dostk/mrkcond`, `amt_qty_tp=2`.
- 모든 조회는 통합시장 종목코드 `<code>_AL`을 사용하며 수량 단위는 주다. 프로그램과 기관 수급은 서로 중복될 수 있으므로 합산하지 않는다.
- 일봉은 요청 시 연속조회하고 60초간 메모리에서만 재사용한다. 개인·외국인·기관·프로그램 어느 일봉도 파일에 저장하지 않는다.
- 분봉은 API가 제공하는 당일 누적 순매수수량의 **서버 관측 기록**이다. 1분간 순매수 증분을 뜻하지 않는다. 같은 분은 최신 관측값으로 갱신한다. 수집 전·중단 구간을 소급 생성하거나 0으로 채우지 않는다.
- `ka10060`이 장중 당일 값을 갱신한다는 사용자 가정으로 구현했다. 2026-10-20 장 종료 후 삼성전자·SK하이닉스의 20거래일 개인·외국인·기관 수량/금액이 ka10059와 일치하는 것은 확인했으나, 장중 실제 갱신 주기는 확인하지 않았다.
- ka90008은 시각만 제공한다. 같은 거래일의 ka10060 날짜를 확인한 이후에만 프로그램 수량을 기록하고 원천 시각을 `program_at`에 보존한다. 날짜가 확인되지 않는 휴일에는 전일 값을 오늘 데이터로 만들지 않는다.

## 서버 수집과 파일

서버 시작과 종목 설정 저장 시 수집을 시도하고 60초 간격으로 반복한다. 수집 시간은 한국 시간 평일 08:00~20:01이며 브라우저의 접속·표시 종목·탭 활성 여부와 무관하다. 중복 수집 실행은 합치고 각 API 요청은 직렬화해 300ms 간격을 둔다. 다른 기능의 키움 요청 큐와는 별개다.

- `data/supply/watchlist.json`: 현재 수집 종목, 보관 종목, 동시 편집 방지 revision.
- `data/supply/<종목코드>/YYYY-MM-DD.json`: 장중 분봉 관측 기록. 임시 파일을 쓴 뒤 rename하여 교체한다.
- 한국 시간 20:02 이후에는 그날의 파일을 `YYYY-MM-DD.json.gz`로 무손실 gzip 압축한다. 압축 파일을 다시 읽어 원본과 바이트 단위로 일치하는지 확인한 뒤 JSON 원본을 제거한다. 과거 조회는 gzip 파일을 메모리에서 해제해서 읽으며, 디스크에 다시 펼치지 않는다.
- 서버 시작과 1분 주기 점검에서 지난 날짜의 미압축 파일도 처리한다. 수집 목록에서 제외한 종목의 기록도 대상이다. 오늘 장중 파일은 압축하지 않는다. 재시작·중단 후 두 파일이 남아 있으면 JSON을 우선 읽고 다시 압축한다.
- 데이터 디렉터리는 Git에서 제외한다. 배포 시 별도 데이터 마이그레이션이나 DB 설치는 필요 없다. 자동 삭제·PC 이동·카페 저장은 구현하지 않았다.
- 서버가 여러 프로세스로 실행되면 파일 저장을 공유하므로 단일 PM2 인스턴스로 운용한다. PM2 reload 시의 잠깐의 중첩을 포함해 여러 수집기를 동시에 장기간 실행하지 않는다.

수집 오류는 종목 버튼의 설명과 분봉 차트 상태에 표시한다. API가 일부 항목을 주지 않으면 해당 항목만 누락 상태로 보존하고 나머지를 수집한다. 종목 변경 중의 이전 응답으로 제외한 종목에 새 기록을 쓰지 않는다.

## API와 화면

기존 로그인 인증을 공통 적용한다.

- `GET /api/supply/watchlist`: 수집/보관 목록, 수집 상태.
- `PUT /api/supply/watchlist`: `{ codes: ["005930"], revision: 0 }`. 최대 5개, 중복 금지, 서버 종목 마스터로 확인한다. 다른 창에서 변경하면 409를 반환한다.
- `GET /api/supply/chart?code=005930&mode=day`: 일봉. 쏠림율과 동일한 `ka10081` 초기 한 페이지의 봉 날짜·개수를 기준으로 수급을 조회한다. 날짜별 누락값을 0으로 채우지 않는다. `has_more`와 `cursor`를 반환하며, 과거 데이터 더 불러오기에서 같은 요청에 cursor를 추가하면 앞선 날짜 구간을 조회한다. 자동 갱신 뒤에도 이미 불러온 과거 데이터와 추가 조회 위치를 유지한다. 일봉 캔들도 같은 응답에 포함한다.
- `GET /api/supply/chart?code=005930&mode=minute`: 최근 저장 거래일 분봉. `has_more`와 cursor를 반환하며 다음 요청에 cursor를 추가하면 그 이전 저장 거래일을 반환한다. JSON/gzip을 구분하지 않고 조회한다. 화면에는 날짜 선택을 두지 않고 일봉과 같은 과거 조회 아이콘으로 이전 날짜를 이어 붙인다. 갱신은 최신 거래일만 갱신하며 이미 불러온 과거 날짜와 추가 조회 위치는 유지한다.
- `GET /api/supply/candles`: 같은 code/mode/date 조건으로 가격 캔들을 조회한다. 일봉은 수급 응답에 이미 포함된 캔들을 재사용하며, 분봉만 펼칠 때 별도로 조회한다. 수급 파일에 저장하지 않는다.
- `GET /api/server/storage`: 데이터 저장 디스크의 전체 용량과 프로세스 사용자가 쓸 수 있는 여유 공간. 헤더에서 5분마다 갱신하며, 1,024³바이트를 GB로 표시한다.

차트는 우측 수량축, 0 기준선, 네 수급 선과 개별 표시 토글, 최신 수량, 커서 정보·수평선·값 표시, 가격 캔들 펼침, 휠/버튼 확대축소, 슬라이더 이동을 제공한다. 왼쪽에서 오른쪽으로 드래그하면 구간 확대, 반대 방향은 전체 구간으로 복원한다. 일봉·분봉 모두 과거 데이터 더 불러오기 아이콘을 제공한다. 분봉은 여러 날짜를 한 시간축에 이어 표시하고 여러 날짜가 보이면 X축에 날짜와 시각을 함께 표시한다. 각 값은 원천의 당일 누적값을 유지하며 다른 거래일 누적값을 합산하지 않는다. 마지막 선택 종목은 브라우저에 기억한다.

캔들의 접힘·펼침 상태는 사용자가 선택한 상태를 유지한다. 수급이 없거나 봉 종류를 전환하거나 과거 데이터를 조회해도 자동으로 펼치지 않으며, 캔들차트 버튼으로 열면 가격을 표시한다. 분봉의 저장 기록이 없어도 최신 실제 거래일 가격 캔들을 조회해 시간축을 만들고, 수급 값은 미제공으로 둔다. 일봉 수급 API가 모두 실패해도 이미 조회한 가격 캔들은 반환한다. 일부 구간만 수급이 빠진 경우에도 가격 캔들은 그 구간에 표시한다. 여러 날짜의 분봉 캔들은 날짜별로 조회하고 과거 날짜는 메모리에서 재사용한다. 이 과정에서 수급 값을 만들거나 파일에 저장하지 않는다.

분봉의 과거 조회 가능 여부는 저장 수급과 가격 캔들의 이전 거래일을 함께 본다. ka10080 응답에서 조회일보다 앞선 실제 거래일을 찾아 가격 cursor를 제공한다. 수급 기록이 없어도 가격 cursor가 있으면 아이콘을 활성화하며, 두 cursor 중 더 최근의 날짜부터 조회한다. 불러온 가격 날짜는 중복 조회 대상에서 제외하고 과거 기록은 갱신 시 유지한다. 캔들을 접은 상태에서도 가격의 과거 조회 가능 여부를 확인하며, 수급이 없는 과거 구간을 요청하면 가격 캔들을 펼쳐 표시한다. 가격 API가 실제로 더 이전 거래일을 제공하지 않을 때만 가격 기준 추가 조회를 종료한다.

## 검증

```bash
node --test dev/tests/supply-service.test.cjs
node dev/tests/rank-supply.test.cjs
node dev/tests/server-storage.test.cjs
```

브라우저 테스트는 기존 프로젝트 테스트와 같이 Windows Edge를 사용한다. 수집 테스트는 모의 API와 테스트 전용 디렉터리만 사용한다. 실제 삼성전자 6개월 일봉 조회에서 수급 122일·가격 캔들 122일과 당일 프로그램 수량 856,591주를 확인했고, 일봉 조회 후 데이터 파일이 생성되지 않는 것을 확인했다. Oracle 운영 배포 및 장중 관측은 별도다.

초기 페이지 방식으로 변경한 뒤 실제 삼성전자 쏠림율과 수급의 초기 600봉 개수가 일치하는 것을 확인했다. 과거 페이지가 첫 페이지보다 앞선 날짜인지도 확인했다. 서비스 테스트 9개와 상단 버튼 추가·선택·제외·최대 5종목·과거 추가 조회의 브라우저 테스트가 통과했다.

기존 `rank-volatility.test.cjs` 회귀 테스트는 통과했다. `rank-turnover.test.cjs:43`은 가격축 라벨 검사에서 실패했으며 변경 전 HEAD의 CSS로도 같은 실패를 재현했다. 해당 테스트는 소수점 둘째 자리 가격 라벨만 수집하지만 기존 거래대금 차트 코드는 쉼표가 들어간 정수 가격을 표시한다. 별도 진단에서 정수 라벨을 인식하도록 보정했더니 캔들 30개·축 라벨 5개를 확보했고, 캔들 오른쪽 끝 578.484375px와 라벨 왼쪽 끝 582.484375px 사이가 4px로 측정됐다. 겹침은 아니지만 테스트의 최소 여백 8px 조건은 만족하지 않는다. 따라서 테스트의 라벨 인식 불일치와 화면의 요구 여백 미달이 함께 있다. 기존 차트와 원래 테스트는 수정하지 않았다.
