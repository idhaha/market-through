# 차트 브라우저 캐시

2026-10-27: 트레이딩 차트와 독립창의 차트 API 응답을 IndexedDB에 최대 16시간 보관한다. 캐시 시각은 마지막 성공 응답 시각이며 화면을 읽는 것만으로 만료가 연장되지 않는다. 같은 브라우저 프로필·같은 접속 주소에서 재사용하며 로컬과 Oracle, 다른 계정의 자료는 분리한다. 브라우저 저장 제한/오류 시 네트워크 조회로 동작하며 로그인하지 않은 상태에서는 저장 캐시를 읽지 않는다.

- 과거 날짜가 명시된 확정 응답은16시간 내 재사용한다. 오늘/최신 페이지는 캐시를 먼저 반환하고 기존 차트의 갱신 요청마다 백그라운드로 다시 조회해 화면을 갱신한다. 1초 이내 중복 재검증은 생략하지만 5초 갱신을1분 고정으로 바꾸지 않는다.
- 오류·pending·partial·미제공 경고·값 없는 응답은 장기 저장하지 않는다. 서버의 진행 중 일봉 작업은 후속 조회를 계속해 완료 결과를 받는다.
- 증권사/경로, 종목·시장·봉·분 간격·날짜·커서 등 모든 요청 조건과 서버에서 확인한 로그인 계정으로 키를 나눈다. 인증 응답·쿠키·API 키·토큰은 저장하지 않는다.
- 쏠림율의 추가조회 커서는 사용자 소유 서버 세션이므로 커서를 포함한 POST 응답을 장기 재사용하지 않는다. 최초 표시용 응답을 보관할 때 커서와 has_more는 제거하고, 재접속 후 서버에서 유효한 새 세션을 받아 갱신한다. 따라서 새 과거 구간/서버 세션 재구성에는 원천 조회 시간이 남을 수 있다.
- 최대180응답/24MiB로 정리하고 개별5MiB 초과 응답은 저장하지 않는다. 브라우저 캐시와 서버 메모리 캐시, 서버 JSON/gzip 분봉 저장은 서로 별개다. 이번 변경으로 서버 캐시 만료시간이나 분봉 영구저장 정책은 바꾸지 않았다.

검증은 dev/tests/rank-chart-cache.test.cjs에서 16시간 만료, 새로고침 후 복원, 현재값 갱신, 계정 분리, 실패·미제공 제외, 불투명 커서 보호, 진행 작업 완료를 실제 Edge 브라우저로 수행한다. 전체16카드 화면/기존 확대·이동·동기화 검사도 유지한다.


## 독립창의 인증 및 연결

네이티브 WebView 독립창은 일반 브라우저 로그인 쿠키 대신 전용 relay capability를 사용한다. 따라서 `/api/auth/session`으로 독립창 캐시 계정을 판정하지 않는다. 인증된 peer 응답이 주는 토큰과 별개의 cacheScope를 네임스페이스로 사용한다. 구 서버가 cacheScope를 주지 않으면 캐시를 우회하고 기존 relay 요청으로 동작한다. 연결 토큰·소유자 키는 IndexedDB에 저장하지 않는다.

main/peer 연결 확인용 스냅샷에는 독립창이 쓰지 않는 메인 차트 points/candles/priceHistory/minuteDays를 복제 전송하지 않는다. 독립창은 자신의 차트 요청과 캐시로 자료를 조회한다. compact 응답은 현재 네이티브 클라이언트가 요청한 경우에만 사용하고 기존 API의 기본 응답은 유지한다. 화면 반영에 실패한 스냅샷은 확인 버전을 올리지 않아 재시도한다. 연결 HTTP 실패·화면 반영 예외는 서로 다른 상태 문구로 표시한다.

2026-10-27 공개 Oracle 주소 확인: azikanbal.duckdns.org의 독립창 HTML에는 당시16시간 캐시 스크립트가 없었다. 비인증 세션 확인과 가짜 채널 검사에는 JSON401이 정상 반환되었으나 실제 독립창 capability의 오류는 원격 세션/로그 없이 확정하지 못했다. 로컬의 연결복구 및 compact·비쿠키 캐시 검증과 운영 장애 원인 확정을 혼동하지 않는다.

Oracle 읽기 전용 로그 추가 확인: 2026-10-27 09:00~09:52 KST의 독립창 peer 요청 3,064건이 HTTP401이며 같은 조회 범위에 owner/recover 요청은 없었다. PM2 서버 시작 시각은08:35 KST였다. 재시작으로 메모리 채널이 소실된 뒤 메인 소유자가 복구하지 않은 상황과 부합하지만, 메인 화면이 닫혔는지 새로고침됐는지까지 로그로 확정하지 않는다. 독립창 종료 → 메인 페이지 새로고침 → 독립창 버튼으로 재실행하여 새 capability를 발급한다.401/404 안내도 이 복구 방법을 표시한다. 운영 서버 변경/재시작은 하지 않았다.
