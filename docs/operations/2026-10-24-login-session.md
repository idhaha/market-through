# 로그인 세션 유지 정책과 구현

2026-10-24 한국 시간 기준. 로컬 구현이며 운영 배포는 별도다.

- 최초 Google 로그인 및 허용 이메일 확인 후 서버가 브라우저별 무작위 세션 토큰을 발급한다.
- 마지막 갱신부터 7일 유지하며, 인증 요청 시 최대 1시간에 한 번 연장한다. 자동 조회와 1분 주기의 세션 확인도 포함한다.
- 최초 로그인부터 30일의 재인증 기한은 연장하지 않는다. 쿠키 수명도 서버의 만료 시각을 넘지 않는다.
- `data/auth-private/sessions.json`에 SHA-256 토큰 해시, 이메일·표시 정보, 생성·갱신·만료·재인증 시각을 저장한다. 원본 토큰이나 Google 자격 증명은 저장하지 않는다.
- 서버 시작 시 유효한 세션을 복원한다. 파일 손상·기한 만료·허용 취소 시 인증하지 않는다. 저장 실패는 기록하며 메모리 갱신을 성공 처리하지 않는다.
- 임시 파일 작성 후 교체한다. 디렉터리 0700, 파일 0600 권한을 요청한다. Windows에서는 별도 ACL 관리가 필요하며 POSIX 권한과 동일한 보호를 의미하지 않는다. 서버 단일 프로세스 운영을 전제로 한다.
- 저장 경로는 public 밖이며 Git 및 기존 설정 백업 대상에서 제외한다. 서버 전체 디스크 백업은 별도로 접근을 보호해야 한다.
- 로그아웃은 해당 세션, 허용 이메일 삭제는 해당 계정의 모든 세션을 무효화한다.
- 기존 24시간 메모리 세션은 이관하지 않으므로 배포 후 최초 한 번 다시 로그인한다.
- 헤더의 서버 여유 왼쪽에 `재인증 D-30일`을 표시한다. 남은 일수는 시간 차를 올림한다. 기한 도달 또는 서버가 만료를 응답하면 페이지를 다시 불러와 로그인 화면을 표시한다.
- D-7부터 D-1까지 보이는 페이지에서 팝업으로 알린다. 브라우저 프로필의 localStorage에 세션 재인증 기한과 한국 날짜를 기록해 같은 날 재표시를 막는다. PC·프로필별로 별도 알림이며 브라우저 저장소를 지우면 다시 표시될 수 있다. 백그라운드 탭은 화면으로 돌아올 때 알린다.
- 서버 독립 데이터 수집과 저장 정책은 변경하지 않았다.

검증: `node --test dev/tests/auth-session-store.test.cjs dev/tests/auth-session-status.test.cjs` 및 변경 JavaScript 구문 검사. 실제 Google 로그인과 운영 서버 재시작은 이 로컬 테스트에 포함하지 않았다.
