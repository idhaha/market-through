# 브라우저 미실행 시 트레이딩 데이터 저장 현황

확인일: 2026-10-23 (한국 시간). 브라우저를 띄우지 않아도 트레이딩 탭의 일봉·분봉 등이 저장되는지에 관한 대화와 로컬 코드 확인 결과를 기록한다. 이 문서는 현행 구현 설명이며, 저장 기능을 추가하거나 변경한 기록은 아니다. 운영 서버의 배포 버전과 실제 실행 상태는 이번 확인에 포함하지 않았다.

## 결론과 전제

모든 데이터가 브라우저 없이 자동 저장되는 것은 아니다. 서버의 독립 수집 스케줄이 있는 항목과 화면/API 요청에 따라 조회·저장되는 항목이 섞여 있다.

자동 수집은 Node.js 서버가 계속 실행되고, 필요한 API 인증·원천 응답·개장 확인 등의 조건을 충족해야 동작한다. 브라우저 종료와 서버 종료는 다르며, 서버가 중단된 동안의 수집까지 보장하지 않는다.

## 브라우저 없이 자동 수집·저장하는 항목

- **등록 종목의 투자자·프로그램 수급:** 서버 시작 시 수집기를 실행하고 이후 60초마다 점검한다. 등록 종목에 대해 평일 한국 시간 08:00~20:01, 당일 개장 확인 등 조건 충족 시 관측 자료를 파일에 저장한다. 이 수급 자료와 쏠림율은 서로 다른 데이터다. 수급 일봉 조회 결과 자체는 짧은 메모리 캐시만 사용하며 디스크에 저장하지 않는다.
- **신고가·신저가:** 서버 시작 시와 이후 60초마다 수집기를 실행한다. 개장 확인 후 수집 시간에 1분 관측치를 저장하며, 20:02 이후 일봉 최종 집계를 시도한다. 조건 충족 시 다음날 08:00 미만까지 최종 집계를 재시도한다. 수집하지 못한 과거 분봉을 소급 생성하지 않는다. 상세 조건은 [신고가·신저가 정책](../BREADTH_CHART.md)을 따른다.
- **변동성·투자심리:** 서버 시작 시와 이후 1시간마다 두 서비스의 일별 자료를 조회·갱신하여 파일에 저장한다. 이는 분봉 수집이 아니다. 원천 조회 실패 시 갱신은 완료되지 않을 수 있다.

근거: [서버 시작 스케줄](../../server.js), [수급 수집기](../../supply-service.js), [수급 저장소](../../supply-store.js), [신고가·신저가 수집기](../../breadth-service.js), [변동성·투자심리 저장 서비스](../../risk-volatility.js).

## 요청이 있어야 저장하거나 조회하는 항목

- **ADR 분봉:** `/api/adr/today` 요청 처리 중 원천 응답을 서버 파일에 병합한다. 브라우저가 없어도 다른 클라이언트가 해당 API를 요청하면 저장될 수 있지만, 요청 없이 독립적으로 수집하는 서버 스케줄은 없다. 재접속 시 원천이 제공하는 분봉을 병합할 수 있으나 누락 구간 전체 복구는 보장하지 않는다. 저장소는 시장별 최신 거래일의 분봉을 유지하는 구조이며, 모든 거래일의 분봉을 계속 쌓는 장기 이력 저장소가 아니다.
- **시장 거래대금:** 요청할 때 원천 일봉·분봉을 조회하고 메모리에 잠시 캐시한다. 별도 자동 수집·파일 누적 저장 스케줄은 없다.
- **쏠림율 차트의 가격 봉:** 요청할 때 키움의 종목·시장 봉을 조회한다. 해당 서비스가 가격 봉을 디스크에 계속 누적 저장하는 구조는 아니다.

근거: [ADR API](../../server.js), [ADR 분봉 저장소](../../adr-minute-store.js), [거래대금 서비스](../../turnover-service.js), [쏠림율 서비스](../../concentration-chart.js).

## 쏠림율에 대한 재확인

사용자가 “쏠림율을 저장 안 한다고?”라고 재확인한 내용의 답은 **현재 구현은 쏠림율 일봉·분봉을 파일에 누적 저장하지 않는다**이다.

`concentration-chart.js`는 조회 요청에 따라 키움에서 종목·시장 데이터를 받아 쏠림율을 계산한다. 조회 세션과 원천 행은 서버 메모리의 `Map` 등에 임시 보관하며, 서버 재시작 후 유지되는 쏠림율 파일 저장 경로는 없다.

다시 화면을 열었을 때 과거 쏠림율 차트가 나오는 것은 저장한 쏠림율 파일을 읽는 것이 아니라, 키움에서 조회 가능한 과거 봉으로 다시 계산하기 때문이다. 따라서 원천이 제공하지 않는 과거 구간까지 자체 보관한다고 해석하면 안 된다.

독립창에는 접속 상태에 따른 서버 갱신 경로가 있지만, 그 결과도 메모리 상태이며 쏠림율 장기 파일 저장 기능을 의미하지 않는다. 서버 시작 시 실행되는 `startStockDirectorySchedule()` 역시 종목 목록 갱신이며 쏠림율 봉 수집이 아니다.

## 대화에서 확인한 최종 상태

“트레이딩 탭의 모든 데이터를 브라우저 없이 저장한다”는 상태는 아니다. 투자자·프로그램 수급, 신고가·신저가, 변동성·투자심리는 서버 스케줄이 있지만, 쏠림율 일봉·분봉의 영구 저장과 ADR 분봉의 독립 수집 스케줄은 현재 없다. 이번 요청에서는 이 현황만 문서화했으며 구현 변경은 하지 않았다.
