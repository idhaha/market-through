# Feature Specification: 동적 탭 — 사용자 정의 차트 탭

**Feature Branch**: `005-dynamic-tabs`

**Created**: 2026-09-29

**Status**: Draft

**Input**: 기존 구현(브라운필드) 문서화 — 현재 구현과 이 Feature의 Spec Kit 산출물을 기준으로 정리

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 차트 그리드 탭 추가 (Priority: P1)

사용자는 `+` 버튼으로 2×2 차트 그리드 탭을 추가하고, TradingView 또는 Investing.com 차트를 자유롭게 배치해 여러 종목을 동시에 모니터링할 수 있다.

**Why this priority**: 동적 탭의 가장 기본적인 형태이며, 나머지 유형 없이도 독립적으로 가치를 제공한다.

**Independent Test**: `+` → `Dynamic 차트`를 선택했을 때 4개 셀에 기본 심볼(USD/KRW, KOSPI, KOSDAQ, BTC/USDT)이 표시되는지 확인해 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 `+` 메뉴에서 `Dynamic 차트`를 선택한 상태, **When** 탭이 생성되면, **Then** 4개 셀에 기본 심볼이 채워진 차트 탭이 즉시 활성화된다.
2. **Given** 사용자가 셀의 심볼 입력창에 새 심볼을 입력하고 [이동]을 클릭한 상태, **When** 이동이 실행되면, **Then** 해당 셀이 TradingView 임베드로 갱신된다.
3. **Given** 사용자가 셀에서 Investing.com 아이콘을 클릭한 상태, **When** 전환이 발생하면, **Then** 해당 셀이 Investing.com 위젯으로 바뀐다.
4. **Given** 사용자가 `+` 메뉴에서 `금리/환율 차트`를 선택한 상태, **When** 탭이 생성되면, **Then** 환율/금리 커스텀 탭이 즉시 활성화되고 설정 입력이 가능하다.

---

### User Story 2 - 해외종목/환율·금리 커스텀 탭 (Priority: P2)

사용자는 사용자 정의 문법으로 여러 데이터 소스(Finviz, TradingEconomics, FRED, ECOS)의 차트를 하나의 탭에 구획별로 나열해 볼 수 있다.

**Why this priority**: 고급 사용자를 위한 기능으로, 기본 차트 그리드(P1)보다 학습 곡선이 있다.

**Independent Test**: 설정 텍스트에 항목을 입력하고 저장했을 때 해당 항목들이 구획별로 렌더링되는지 확인해 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 `[종목입력]` 모달에 `<구획명>`과 항목 줄을 입력한 상태, **When** 저장을 클릭하면, **Then** 탭이 구획별로 재렌더링되고 각 항목의 데이터가 조회된다.
2. **Given** 설정이 비어 있거나 해석 가능한 항목이 없는 상태, **When** 탭이 렌더링되면, **Then** "등록된 차트가 없습니다" 안내가 표시된다.
3. **Given** 사용자가 금리/환율 탭에 FRED URL/레이블 쌍을 한 행에 두 개 이상 입력한 상태, **When** 저장하면, **Then** 각 FRED 시계열이 하나의 차트에 별도 선으로 표시된다.

---

### User Story 3 - 동적 탭 관리(이름 변경/순서 변경/삭제) (Priority: P3)

사용자는 동적 탭을 드래그로 순서를 바꾸거나, 더블클릭으로 이름을 바꾸거나, 우클릭 메뉴로 삭제할 수 있다.

**Why this priority**: 탭이 늘어났을 때의 정리 편의 기능으로, 탭 생성(P1, P2) 없이는 필요하지 않다.

**Independent Test**: 동적 탭을 더블클릭해 이름을 바꾸고 저장되는지 확인해 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 동적 탭을 더블클릭한 상태, **When** 새 이름을 입력하고 확정하면, **Then** 탭 이름이 바뀌고 설정이 저장된다.
2. **Given** 사용자가 동적 탭을 우클릭한 상태, **When** 삭제를 선택하고 확인하면, **Then** 탭과 관련 데이터가 제거되고 설정이 저장된다.

### Edge Cases

- 사용자 정의 문법의 항목 수가 애매하면(쌍/삼중항 판별 모호) 어떻게 되는가? → 휴리스틱에 따라 의도와 다르게 해석될 수 있다.
- 캡처 모드 중 동적 탭 데이터 로드가 예정되어 있으면 어떻게 되는가? → 로드/새로고침을 건너뛴다.
- 외부 iframe(TradingView 등)이 브라우저 정책으로 차단되면 어떻게 되는가? → 앱은 프레임 내부 오류를 항상 판별할 수 없으며, 화면에 표시되지 않을 수 있다.
- 개별 데이터 소스(Finviz 이미지 등) 하나가 실패하면 어떻게 되는가? → 해당 항목만 실패로 기록되고 나머지 항목 로딩은 계속된다.
- FRED 식의 두 번째 인수가 시리즈의 만기와 혼동되면 어떻게 되는가? → 두 번째 인수는 관측값의 lookback 조회 기간이며, 시리즈 ID의 경제적 의미와 별개다.
- 한 화면에 TradingEconomics(TE) 차트가 여러 개이면 어떻게 되는가? → 화면이 TE 요청을 한 번에 1개씩 순서대로 보내고 서버도 Chrome을 동시에 1개만 실행하므로, 차트가 순서대로 채워진다. 전체 로딩 시간은 TE 항목 수에 비례해 길어진다(허용되는 제한).
- TE 수집이 지연되거나 서버의 대기 한도를 넘으면 어떻게 되는가? → 해당 항목만 실패(HTTP 500) 처리된다. 화면은 504·타임아웃·네트워크 오류에 대해 2초 뒤 1회 재시도한 뒤 해당 항목을 건너뛰며, 한 차트의 모든 항목이 실패하면 차트 영역에 '오류: 유효한 데이터가 없습니다.'가 표시된다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 차트 그리드, 해외종목 커스텀, 환율/금리 커스텀 3가지 유형의 동적 탭 생성을 지원해야 한다.
- **FR-002**: 차트 그리드 탭은 생성 시 4개의 기본 심볼(USD/KRW, KOSPI, KOSDAQ, BTC/USDT)로 채워져야 한다.
- **FR-003**: 각 그리드 셀은 TradingView와 Investing.com 공급자 간 전환을 지원해야 한다. 구현에서 추가 제공하는 AlphaSquare 바로가기도 허용한다.
- **FR-004**: 커스텀 탭은 사용자 정의 텍스트 문법(구획, URL/레이블/기간 조합)을 파싱해 차트를 렌더링해야 한다.
- **FR-005**: 새 동적 탭은 생성 직후 활성화되고 설정이 저장되어야 한다.
- **FR-006**: 동적 탭은 드래그로 순서 변경, 더블클릭으로 이름 변경, 우클릭 메뉴로 삭제가 가능해야 하며, 고정 탭은 이 동작에서 제외되어야 한다.
- **FR-007**: 개별 데이터 소스 항목의 로드 실패가 동일 탭 내 다른 항목이나 다른 탭에 영향을 주어서는 안 된다.
- **FR-008**: 캔버스 기반 커스텀 차트는 같은 탭 내에서 커서/줌 동기화를 지원해야 한다. 외부 iframe(TradingView, Investing.com)은 동기화 대상에서 제외된다.
- **FR-009**: 캡처 모드 중에는 동적 탭의 데이터 로드/새로고침이 억제되어야 한다.
- **FR-010**: 탭 전환 시 비활성화되는 탭의 콘텐츠 상태(입력 심볼, 공급자 모드 등)가 보존되어야 한다.
- **FR-011**: 금리/환율(`exchange_rate`) 탭은 `fred(seriesId[, period])` 표현식을 지원해야 하며, 조회 기간 생략 시 최근 1년을 사용해야 한다.
- **FR-012**: FRED 조회 기간은 `10년/10y`, `5년/5y`, `2년/2y`, `1년/1y`, `6개월/6m` 표기를 API 기간으로 정규화해야 한다. 서버는 기간을 각각 3650/1825/730/365/180일 전부터의 조회로 해석하며, 지원하지 않는 값은 `1y`로 처리한다.
- **FR-013**: 금리/환율 탭의 한 입력 행에 여러 FRED URL/레이블 쌍을 지정하면 모두 하나의 차트에 각각 별도 선으로 표시하고, 개별 시리즈 실패는 다른 시리즈 로드를 중단하지 않아야 한다.
- **FR-014**: FRED 기간 인수는 series ID의 만기가 아닌 최신 관측일 기준 lookback 기간이어야 한다. `fred(DGS10)`은 앱 전용 표현식이며, FRED 웹 시리즈 페이지 URL을 입력 표현식으로 취급하지 않는다.
- **FR-015**: FRED 시계열 캐시는 서버 로컬 JSON 파일에 저장되어 서버 재시작 뒤에도 유지되어야 한다. 저장 캐시가 없는 신규 시리즈는 최초 요청에서 전체 요청 기간을 가져와야 하며, 입력에서 시리즈를 삭제해도 캐시는 자동 삭제하지 않아 재등록 시 재사용할 수 있어야 한다.
- **FR-016**: 시리즈/기간 조합별로 매월 첫 성공 조회는 요청 기간 전체를 다시 가져와 날짜 기준으로 병합해야 한다. 해당 월의 전체 조회가 실패하면 완료로 기록하지 않고 다음 조회에서 재시도해야 한다. 월 경계는 UTC 기준이다. 갱신이 실패했을 때 기존 캐시가 있으면 기존 데이터를 `cacheStatus: 'stale'`로 HTTP 200에 담아 반환하고, 캐시가 없으면 HTTP 500 오류를 반환한다.
- **FR-017**: 같은 달의 후속 조회는 마지막 저장 관측일보다 30일 앞선 날짜부터 증분 조회하고 날짜 기준으로 병합하여 겹치는 날짜의 수정값을 반영해야 한다.
- **FR-018**: 1년간 사용되지 않은 FRED 시리즈 캐시만 자동 삭제해야 한다. 삭제된 시리즈를 이후 다시 조회하면 전체 요청 기간을 다시 받아야 한다. 시리즈의 마지막 사용 시각은 그 시리즈의 모든 기간 캐시 중 가장 최근 값을 기준으로 하며, 정리 여부는 서버 시작 시와 24시간마다 확인한다. 사용 시각이 없거나 해석할 수 없는 캐시 항목은 정리 대상이 된다.
- **FR-019**: 조회할 때마다 마지막 사용 시각은 서버 메모리에 즉시 기록하고, 디스크 저장은 변경이 있을 때만 최대 5분 간격으로 수행해야 한다(요청마다 캐시 파일 전체를 다시 쓰지 않는다). 시리즈 갱신(조회 성공) 시에는 캐시를 즉시 저장한다. 서버가 저장 주기 전에 종료되면 그 사이의 사용 시각 갱신은 디스크에 반영되지 않을 수 있다.
- **FR-020**: 서버의 `fred_api.py` 실행(Python 서브프로세스)은 동시에 최대 2개로 제한해야 하며, 초과분은 순서를 기다린다. 같은 시리즈/기간 조합의 중복 요청은 진행 중인 조회 결과를 공유한다. 실행은 `python`을 먼저 시도하고 실패하면 `python3`으로 재시도하며, 프로세스당 제한 시간은 120초이다.
- **FR-021**: 서버의 `GET /api/trading-economics`는 TE 웹페이지 URL이면 Puppeteer(헤드리스 Chrome)로 데이터를 수집하고, 그 밖의 URL은 일반 HTTP 요청(제한 시간 15초)으로 처리해야 한다. 성공한 결과는 URL과 기간 조합별로 서버 메모리에 캐시하며(만료 시간 없음, 서버 재시작 시 사라짐), `force_refresh=true` 또는 `1`이면 캐시를 무시하고 다시 수집한다. 실패한 결과는 캐시하지 않으며 HTTP 500과 `{ success: false, error, details }`로 응답한다.
- **FR-022**: 서버는 TE 수집용 Chrome을 동시에 1개만 실행해야 한다. 실행 중이면 최대 45초 대기하고, 그래도 비지 않으면 Chrome을 추가로 띄우지 않고 오류로 응답해야 한다(웹서버 프록시의 60초 제한보다 짧게). Chrome은 닫힌 뒤에만 실행 슬롯을 반납하며, 10초 안에 닫히지 않으면 프로세스를 강제 종료한다.
- **FR-023**: 화면은 TE 요청(TE 단일 차트와 다중 시리즈 차트의 TE 항목)을 탭·차트와 무관하게 한 번에 1개씩 전역 대기열로 보내야 한다. 대기열에서 차례를 기다리는 동안에는 타임아웃을 적용하지 않고, 실행 중인 요청마다 120초 타임아웃을 적용한다. 앞선 요청의 실패가 뒤 요청을 막아서는 안 된다.

### 금리/환율 탭 FRED 입력 문법

금리/환율 탭의 `[종목입력]`은 앱 전용 `fred(seriesId[, period])` 표현식을 지원한다. `fred(DGS10)`은 시리즈 ID `DGS10`의 최근 1년 관측값을 조회한다. `DGS10`은 10년 만기 국채 시리즈이고, 아래처럼 지정한 `10년`은 조회할 과거 기간이다.

```text
("fred(DGS10)", "미국채 10년물")
("fred(DGS10,10y)", "미국채 10년물")
("fred('DGS10','10년')", "미국채 10년물", "fred('DGS2','10년')", "미국채 2년물")
```

FRED의 시리즈 설명 페이지(`https://fred.stlouisfed.org/series/DGS10`)는 현재 데이터 조회 입력으로 직접 파싱되지 않는다. 두 번째 예시는 최근 10년을 조회하며, 세 번째 예시도 DGS2의 2년 만기와 조회 기간 10년을 구분한다. 한 행은 시리즈마다 `표현식, 레이블` 쌍으로 확장할 수 있다. 두 시리즈는 4개 필드, 세 시리즈는 6개, 네 시리즈는 8개 필드이며 한 Canvas에 함께 그려진다.

### Key Entities

- **동적 탭(Dynamic Tab)**: ID, 이름, 유형(차트그리드/해외커스텀/환율금리커스텀), 설정 데이터를 가진다.
- **그리드 셀(Grid Cell)**: 심볼, 공급자 모드(TradingView/Investing.com), 각 공급자 URL을 가진다.
- **커스텀 차트 항목(Custom Chart Entry)**: 데이터 소스 URL, 표시 레이블, 기간(선택)을 가진다.
- **구획(Section)**: 제목, 색상을 가지며 커스텀 탭 내 항목을 그룹화한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자는 탭 추가 버튼 클릭 후 1초 이내에 새 탭에서 작업을 시작할 수 있다.
- **SC-002**: 유효한 문법으로 작성된 커스텀 설정 항목은 저장 즉시 반영되어 표시된다.
- **SC-003**: 하나의 데이터 소스가 실패해도, 같은 탭 내 나머지 항목의 정상 표시율은 영향받지 않는다.
- **SC-004**: 운영 서버에서 여러 TE 차트를 한꺼번에 요청해도 Chrome 프로세스 묶음은 동시에 1개를 넘지 않고, 서버 메모리(`free -m`의 available)가 안정적으로 유지된다.

## Assumptions

- 사용자는 외부 서비스(TradingView, Finviz 등)의 임베드 정책과 가용성이 자체 제어 밖에 있음을 이해하고 있다고 가정한다.
- 커스텀 문법은 엄격한 검증기가 아닌 휴리스틱 파서로 동작함을 전제로 하며, 엄밀한 문법 오류 리포팅은 이 기능 범위 밖이다.
- FRED 기간 별칭은 `10년/10y`, `5년/5y`, `2년/2y`, `1년/1y`, `6개월/6m`이며, 미지원 값은 서버 측 기본 기간(1년)으로 처리된다.
- 운영 서버는 RAM 약 1GB(Oracle Cloud Free Tier)이므로 TE 수집은 동시 1개로 제한하며, 그 결과 TE 차트가 많을수록 전체 로딩이 느려지는 것을 허용한다. 서버 자원 규칙은 constitution v1.1.0 "Server Resource Constraints"를 따른다(근거: 2026-10-04 장애 기록, `docs/operations/server-runbook.md`).
- TE 캐시는 서버 메모리에만 있어 서버 재시작 직후 첫 로딩은 모든 TE 항목을 다시 수집한다.
