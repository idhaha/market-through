# Feature Specification: 설정 저장 및 동기화

**Feature Branch**: `006-settings-sync`

**Created**: 2026-09-29

**Status**: Draft

**Input**: 기존 구현(브라운필드) 문서화 — 현재 구현과 이 Feature의 Spec Kit 산출물을 기준으로 정리

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 설정 자동 저장 (Priority: P1)

사용자가 탭을 추가/삭제하거나, 이름을 바꾸거나, 갱신 주기를 변경하는 등 구성 변경을 할 때마다 시스템은 전체 설정을 브라우저 로컬과 서버에 자동으로 저장한다.

**Why this priority**: 사용자가 다시 방문했을 때 이전 상태를 그대로 이어받기 위한 핵심 전제 조건이다.

**Independent Test**: 탭 이름을 바꾼 뒤 페이지를 새로고침했을 때 변경된 이름이 유지되는지 확인해 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 새 탭을 추가한 상태, **When** 탭 생성이 완료되면, **Then** 설정이 로컬 저장소와 서버 양쪽에 저장된다.
2. **Given** 서버 저장 요청이 실패한 상태, **When** 저장이 시도되면, **Then** 로컬 저장소에는 내용이 남고 사용자에게 경고가 표시된다.

---

### User Story 2 - 여러 PC 간 설정 동기화 (Priority: P2)

사용자가 여러 PC나 브라우저에서 접속할 때, 시작 시점에 서버에 저장된 최신 전체 설정이 우선 적용된다.

**Why this priority**: 다중 환경 사용을 지원하는 기능으로, 단일 저장(P1)이 먼저 동작해야 의미가 있다.

**Independent Test**: 한 브라우저에서 저장한 설정이 다른 브라우저에서 접속했을 때 반영되는지 확인해 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 서버에 비어있지 않은 유효한 설정이 있는 상태, **When** 사용자가 새 브라우저에서 접속하면, **Then** 서버 설정이 로컬 설정보다 우선 적용된다.
2. **Given** 서버 접근이 실패한 상태, **When** 페이지가 로드되면, **Then** 유효한 로컬 설정이 있으면 그것으로 대체 동작한다.

---

### User Story 3 - 전체 설정 백업/복원 (Priority: P3)

사용자는 전체 설정을 파일로 서버 프로젝트 루트에 백업하고, 프로젝트 루트 백업 또는 선택한 파일로 복원할 수 있다.

**Why this priority**: 재해 복구·이전용 보조 기능으로, 평상시 자동 저장(P1)과는 별개로 필요할 때만 사용된다.

**Independent Test**: 전체 설정을 내보낸 뒤 다른 상태에서 복원했을 때 원래 상태로 돌아오는지 확인해 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 현재 앱 설정이 있는 상태, **When** "전체 설정을 프로젝트 폴더에 백업하기"를 클릭하면, **Then** 전체 설정 JSON 백업 파일 하나가 서버 프로젝트 루트에 생성된다.
2. **Given** 사용자가 JSON 백업 파일을 선택한 상태, **When** 가져오기를 확인하면, **Then** 현재 탭 구성이 백업 파일 내용으로 전체 교체된다.

### Edge Cases

- 여러 브라우저가 동시에 저장을 시도하면 어떻게 되는가? → 마지막으로 처리된 저장이 서버 파일 전체를 덮어쓰며, 필드 단위 병합은 없다.
- 로컬 저장소 쓰기가 실패(용량 초과 등)하면 어떻게 되는가? → 별도의 복구 로직 없이 실패한다.
- 손상되었거나 구버전 형식의 백업을 복원하면 어떻게 되는가? → 스키마 검증이 없어 일부 UI나 상태가 누락될 수 있다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 탭 추가/삭제/이름변경/순서변경, 차트 입력 변경, 갱신 주기 변경, 관심종목 그룹 변경 시 전체 설정을 자동 저장해야 한다. 메모는 사용자가 메모 저장 버튼을 누르면 자동 타이핑 저장 없이 HTML/Delta를 로컬에 먼저 기록한 다음 메모 전용 서버 경로로 저장해야 한다. 서버 메모 저장은 기존 전체 설정을 보존해야 한다.
- **FR-002**: 저장은 먼저 브라우저 로컬 저장소에 즉시 기록한 뒤 서버로 전송하는 순서를 따라야 한다.
- **FR-003**: 서버 저장이 실패해도 로컬 저장 내용은 유지되어야 하며, 사용자에게 실패가 통지되어야 한다.
- **FR-004**: 앱 시작 시 시스템은 서버 설정과 로컬 설정을 모두 확인하고, 서버에 유효한(비어있지 않은) 설정이 있으면 이를 우선 적용해야 한다.
- **FR-005**: 서버 접근이 불가능한 경우 시스템은 유효한 로컬 설정으로 대체 동작해야 한다.
- **FR-006**: 서버·로컬 모두 유효한 설정이 없으면 시스템은 고정 탭과 기본 화면(Rank)으로 시작해야 한다.
- **FR-007**: 설정 복원 중에는 자동 저장이 잠겨야 하며, 복원 완료 후에만 다시 활성화되어야 한다.
- **FR-008**: 사용자는 전체 설정 스냅샷을 단일 JSON 파일로 서버 프로젝트 루트에 백업할 수 있어야 한다.
- **FR-009**: 사용자는 프로젝트 루트에 있는 JSON 전체 백업 하나를 선택해 전체 설정을 복원할 수 있어야 한다.
- **FR-010**: 단일 가져오기 버튼은 접속 호스트와 관계없이 현재 서버의 프로젝트 루트 파일(`autosaved_user_settings.json`, JSON 백업) 목록을 불러와야 한다. 전체 설정 복원 전에는 확인 절차를 거쳐야 한다.
- **FR-011**: 서버는 모든 사용자가 공유하는 단일 설정 파일을 사용해야 하며, 이 저장소는 API 키·토큰 등 민감정보를 포함해서는 안 된다.
- **FR-012**: 동시 저장 충돌 시 시스템은 마지막으로 처리된 저장을 그대로 반영해야 하며, 별도 병합은 수행하지 않는다(현재 동작으로 문서화, 향후 개선 여지 있음).
- **FR-013**: 단일 가져오기 버튼의 풍선 도움말은 현재 서버 프로젝트 루트의 JSON 파일에서 전체 설정을 복원한다는 점을 안내해야 한다.
- **FR-014**: 백업 선택 UI는 서버의 JSON 파일을 스크롤 가능한 모달 목록으로 표시하고, 파일명 검색 및 수정 시각·크기 확인을 지원해야 한다.

### Key Entities

- **앱 설정 스냅샷(App Settings Snapshot)**: 활성 탭 ID, 탭 목록·순서, 탭별 콘텐츠, Rank/ADR 갱신 주기, 관심종목 그룹, 메모(HTML/Delta), 갱신 시각을 가진다.
- **서버 설정 파일(autosaved_user_settings.json)**: 최신 전체 스냅샷 하나를 보관하며 git에는 포함되지 않는다.
- **로컬 저장 항목**: 전체 스냅샷, 메모 로컬 사본, 관심종목 그룹 선택값, 사용자 세션 토큰을 복구/세션용 브라우저 사본으로 보관한다. 정상 동기화의 영구 저장소는 서버 프로젝트 루트 파일이다.
- **프로젝트 루트 백업 파일**: `manualsaved_user_settings_<timestamp>.json` 하나에 전체 설정 스냅샷을 담아 서버 프로젝트 루트에 저장하며 git에는 포함하지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 설정 변경 후 1초 이내에 로컬 저장이 완료된다.
- **SC-002**: 서버가 정상일 때, 새 브라우저 접속 시 100%의 경우 마지막 저장된 서버 설정이 적용된다.
- **SC-003**: 서버 접근 불가 상황에서도 사용자는 로컬 설정으로 앱을 정상적으로 계속 사용할 수 있다.
- **SC-004**: 전체 백업 파일로 복원한 직후, 복원 전 저장했던 탭 구성과 100% 동일하게 화면이 재구성된다.

## Assumptions

- 현재는 1인 사용자 환경이므로, 다중 사용자 동시 저장 충돌에 대한 필드 단위 병합은 이번 기능 범위에 포함하지 않는다(Constitution 원칙 IV, 향후 개선 과제로 분리).
- `autosaved_user_settings.json`과 로컬 저장소의 세션 토큰 등 민감정보는 Constitution 원칙 III(Secrets Isolation)에 따라 git에 포함되지 않는다고 가정한다.

## 서버 전송 버튼 아이콘 정책 — 2026-10-10

서버를 기준으로 아래쪽 화살표(↓)는 서버로 저장, 위쪽 화살표(↑)는 서버에서 불러오기를 의미한다. 상단 bulkDownload는 ↓ 전체 설정 저장, bulkUpload는 ↑ 서버 백업 불러오기이다. 버튼 아이콘·툴팁·접근성 이름과 실제 동작을 일치시킨다.

## 서버 백업 파일 삭제 — 2026-10-10

설정 백업 선택 창에서 수동 저장 및 전체 백업 파일의 행 오른쪽 끝에 X 삭제 버튼을 표시한다. 파일명을 포함한 확인을 승인하면 서버 파일을 삭제하고 목록·검색 결과 개수를 즉시 갱신한다. 선택된 파일을 삭제하면 복원 선택을 해제한다. 삭제 실패 시 파일을 목록에 유지하고 오류를 안내한다. 삭제 진행 중 복원 및 중복 삭제를 제한한다.

autosaved_user_settings.json에는 삭제 버튼을 표시하지 않으며 서버에서도 삭제를 차단한다. 삭제 대상은 기존 목록에 허용된 manualsaved_user_settings_YYYYMMDD_HHMMSS_mmm.json 및 full_backup_YYYYMMDD_HHMMSS_mmm.json으로 제한한다. 삭제 버튼의 클릭/Enter는 파일 선택·복원을 실행하지 않는다.
