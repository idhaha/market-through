# Implementation Plan: 시장경보

작성일: 2026-10-30 | 기능: `012-market-alert` | 실제 Git 브랜치: `br_oracle` | 요구사항: [spec.md](spec.md)

상태: 공식 JIF 상세 명세 확보 및 로컬 구현 완료. Phase 1 계약·데이터 모델·검증 절차 작성. 운영 실제 발동·해제 인수 확인 대기.

## Summary

제공 엑셀을 정리한 안내창과 LS 실시간 시장경보를 추가한다. 메인·독립창의 배너 및 카드 테두리를 함께 점멸하고, 사용자 확인 후 색상과 발생·해제시각을 당일 장 종료까지 유지한다.

## Technical Context

- Node.js >=20 / Express / ws, vanilla HTML/CSS/JS, 별도 프런트 빌드 없음.
- 운영 환경은 Oracle Cloud 약 1GB RAM 및 Windows WebView2 독립창. 작은 이벤트 상태만 보관하며 별도 상주 프로세스를 추가하지 않는다.
- 정적 설명과 실시간 이벤트 상태를 분리한다. 비밀값은 서버 환경변수에 유지한다.
- 기존 `dev/tests`의 Node 테스트 및 Playwright 브라우저 검증 패턴을 사용한다.
- JIF 구독 키 0과 CB 1·2·3단계 및 매수·매도 사이드카 코드는 공식 상세 JSON에서 확인했다. 시간 필드는 없으므로 수신시각을 표시한다. 당일 저장 데이터만 복구하고 수신 공백은 미확인으로 명시한다.

## Constitution Check

- Spec-first: 기존 구현과 예정 기능을 구분하고 별도 spec을 작성했다.
- API 장애 격리: 연결 장애 시 마지막 상태와 오류를 표시하고 다른 기능을 유지한다.
- 비밀 격리: 토큰을 브라우저나 Ollama에 전달하지 않는다.
- 단순성: 기존 인증·LS 토큰·독립창 통신을 활용한다. 별도 경보 전용 WebSocket 하나로 기존 수급 구독을 변경하지 않는다. 저장 이벤트64개와 진단200건으로 메모리를 제한한다.
- 게이트 결과: 공식 명세·Phase 1 설계 재평가 통과. 기존 미커밋 변경·비밀값·운영 설정에 영향을 주지 않는다. 운영 재시작과 실제 경보 인수 확인은 별도로 남긴다.

## 작업 및 담당

1. [Codex / 현재 세션 모델] 공식 페이지와 제공되는 DevCenter 자료에서 JIF 상세 명세 및 단계 판별 가능 여부를 확인한다. 확보되지 않는 항목은 research.md의 장중 검증 절차에 따라 실제 구독·응답을 기록해 검증한다. 정상 장 수신과 경보 코드 검증을 구분하며 희귀 이벤트를 관찰하지 못하면 미확인 상태로 남긴다. 단계가 없으면 공식 보조 데이터 경로를 검증한다. 추가 명세 제공을 사용자에게 전제하지 않는다.
2. [Ollama / qwen2.5:14b] 엑셀 A1:C12 발췌만 전달받아 안내 문구를 정리한다. Codex가 원문과 숫자·조치·제한사항을 대조한다. 첨부의 규정을 최신 공식 규정으로 단정하지 않는다.
3. [Codex / 현재 세션 모델] 공식 명세 확인 후 data-model.md, contracts/, quickstart.md를 작성한다. 서버 경보 이벤트, 사용자별 확인, 독립창 capability 통신, 장 종료·재시작·재접속 상태를 구체화한다.
4. [Ollama / qwen2.5-coder:7b] 관련 HTML/CSS 발췌와 확정된 상태 클래스를 입력받아 안내창·배너·카드 테두리 및 점멸 CSS 초안을 작성한다. 파일 접근이나 도구 연결을 추가하지 않는다.
5. [Codex / 현재 세션 모델] 초안의 대비·레이아웃·클릭 범위 및 기존 스타일 충돌을 검토하고 적용한다. JIF 수신·판정·기록·확인·화면 동기화를 구현한다. 구현 단계 전 tasks를 정리한다.

## 검증 계획

- 공식 코드별 이벤트 fixture로 발동·해제·단계 변경·시장 구분을 검증한다. 미확인 코드는 정상이나 해제로 처리하지 않는다.
- 중복 수신은 재점멸하지 않고 새 발동은 다시 확인하게 한다. 확인 상태를 다른 사용자와 공유하지 않는다.
- 한쪽 화면 확인 시 양쪽 배너·카드 테두리의 점멸이 멈추며 색상이 남는다. 해제시각과 당일 장 종료 초기화를 확인한다.
- 여러 경보의 동시 표시·대표 테두리색과 카드 내부 클릭 보존을 확인한다.
- 네트워크 단절·복구, 메인 휴면, 독립창 재접속, 서버 재시작에서 잘못된 정상 표시와 중복 구독이 없는지 검증한다.
- 브라우저에서 읽기 대비, 키보드 확인·안내창 닫기, 창 크기 변경을 검증한다. reduced-motion에서는 정적 경보와 미확인 표시를 유지한다.
