# Feature Specification: Google 계정 접근 제어 및 프로필

**Feature Branch**: `008-google-account-access`

**Created**: 2026-10-03

**Status**: Implemented

**Input**: Google이 로그인 계정을 인증하고, 서비스 허용 목록에 등록된 계정만 대시보드와 데이터 API를 이용한다. 허용 목록 관리자는 `azikanbal@gmail.com`으로 제한한다.

## User Scenarios & Testing

### User Story 1 - 허용된 Google 계정으로 로그인 (Priority: P1)

사용자는 Google 로그인 UI를 통해 인증한다. 서비스는 Google ID 토큰의 유효성, 이 서비스의 OAuth audience, 이메일 확인 여부와 만료 여부를 검사한 다음 해당 이메일이 허용 목록에 있는 경우에만 서버 세션을 만든다.

**Independent Test**: 허용된 Google 계정으로 로그인해 대시보드와 데이터 API를 사용할 수 있고, 허용 목록에 없는 계정은 UI 접근과 데이터 API 요청이 거부되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 로그인하지 않은 사용자, **When** 앱을 연다, **Then** 로그인 화면만 표시되고 대시보드 데이터 API 요청은 인증 없이 성공하지 않는다.
2. **Given** 유효한 Google 인증이 완료된 허용 이메일, **When** 서버가 ID 토큰을 검증한다, **Then** 서버 세션 쿠키를 설정하고 대시보드를 표시한다.
3. **Given** 미등록 이메일, 잘못된 토큰, 이메일 미확인 토큰 또는 다른 OAuth audience의 토큰, **When** 로그인을 시도한다, **Then** 세션을 발급하지 않고 로그인 오류를 표시한다.
4. **Given** 로그인된 사용자, **When** 브라우저가 `/api` 데이터 엔드포인트를 요청한다, **Then** 허용된 유효 서버 세션이 있을 때만 요청을 처리한다.

### User Story 2 - 허용 이메일 목록 관리 (Priority: P1)

`azikanbal@gmail.com` 관리자는 프로필 아이콘을 눌러 허용 이메일을 등록하거나 삭제한다. 다른 허용 사용자는 본인 이메일 확인과 로그아웃만 사용할 수 있다.

**Independent Test**: 관리자 계정만 목록을 조회·추가·삭제할 수 있고, 비관리자는 관련 UI가 보이지 않으며 관리자 API도 거부되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 관리자로 로그인, **When** 원형 프로필 아이콘을 누른다, **Then** 로그인 이메일, 허용 목록 관리 및 창 하단의 로그아웃 버튼을 본다.
2. **Given** 관리자, **When** 올바른 이메일을 등록하거나 기존 항목을 삭제한다, **Then** 목록이 갱신되고 새 등록은 다음 로그인부터 허용되며 삭제된 계정의 기존 세션은 폐기된다.
3. **Given** 일반 허용 사용자, **When** 프로필을 연다, **Then** 허용 목록 관리 UI는 표시되지 않고 로그아웃 기능만 사용할 수 있다.
4. **Given** 관리자가 아닌 사용자가 관리자 API를 직접 호출한다, **When** 요청이 처리된다, **Then** 서버는 권한 오류를 반환하고 목록을 변경하지 않는다.
5. **Given** 사용자가 로그아웃을 누른다, **When** 세션 종료 요청이 완료된다, **Then** 서버 세션 쿠키가 제거되고 페이지는 로그인 상태가 된다.

### User Story 3 - HTTPS로 안전하게 접속하고 인증서를 유지 (Priority: P1)

운영 사용자는 무료 인증서가 적용된 HTTPS 주소로 접속하며 HTTP 주소로 접속해도 HTTPS로 이동한다. 운영자는 인증서 만료 전 자동 갱신이 예약되어 있는지 확인하고 모의 갱신으로 실제 갱신 가능 여부를 검증한다.

**Acceptance Scenarios**:

1. **Given** 운영 HTTPS 주소, **When** 사용자가 접속한다, **Then** 신뢰할 수 있는 유효한 인증서로 연결되고 페이지가 정상 응답한다.
2. **Given** 운영 HTTP 주소, **When** 사용자가 접속한다, **Then** 운영 HTTPS 주소로 영구 이동한다.
3. **Given** 자동 갱신 타이머, **When** 운영자가 예약 상태를 확인한다, **Then** 다음 실행 시각을 확인할 수 있다. 예약 상태만으로 갱신 성공을 단정하지 않는다.
4. **Given** 모의 갱신 실행, **When** 모든 대상 인증서의 모의 갱신이 성공한다, **Then** 운영자는 갱신 경로의 테스트 성공을 기록한다. 실제 자동 갱신 성공은 별도 실행 기록으로 확인한다.

## Requirements

- **FR-001**: Google이 사용자 자격 증명을 검증해야 하며 서비스는 자체 이메일/암호를 수집하거나 보관하지 않는다.
- **FR-002**: 서버는 Google ID 토큰의 서명 유효성을 Google의 tokeninfo 서비스로 확인하고, OAuth audience, 이메일 확인 상태와 만료 시각을 검사해야 한다.
- **FR-003**: 초기 관리자 `azikanbal@gmail.com`은 허용 목록 파일 등록 여부와 관계없이 로그인할 수 있으며 허용 목록 관리 권한을 가진 유일한 계정이어야 한다.
- **FR-004**: 다른 사용자는 서버의 `authorized_emails.json`에 등록된 이메일과 Google 인증 이메일이 일치할 때만 로그인할 수 있어야 한다.
- **FR-005**: 로그아웃을 제외한 모든 `/api` 요청은 관리자가 등록한 세션을 요구해야 한다. 공개 예외는 Google 로그인, 현재 세션 조회, 로그아웃 절차다.
- **FR-006**: 서버 세션 식별자는 `HttpOnly`, `SameSite=Lax` 쿠키로 전달하고 마지막 갱신부터 7일 유지하고 인증 요청 시 최대 1시간에 한 번 연장하되 최초 로그인부터 30일에 반드시 만료해야 하며 HTTPS 요청에서는 `Secure` 속성을 설정해야 한다.
- **FR-007**: 허용 이메일 목록 조회·추가·삭제 API는 관리자 권한을 서버에서 확인해야 한다. 초기 관리자 항목은 삭제할 수 없어야 한다.
- **FR-008**: 허용 이메일 삭제 시 해당 이메일로 발급한 활성 세션을 폐기해야 한다.
- **FR-009**: 프로필 아이콘은 제공된 원형 사용자 실루엣 이미지 자체만 표시하고 텍스트, 테두리 또는 버튼 배경을 두지 않는다. 프로필 창 하단에 로그아웃을 둔다.
- **FR-010**: 허용 목록 파일과 임시 파일은 Git에 포함되지 않아야 한다.
- **FR-011**: 앱 설정 파일은 현재 공용 단일 스냅샷으로 유지된다. 허용 목록은 로그인 접근을 제한하지만 계정별 데이터 분리나 개인 설정 저장을 제공하지 않는다.
- **FR-012**: 로컬 HTTP 개발에서는 Google Identity Services가 요구하는 Referrer-Policy를 localhost 응답에 설정해야 한다. Google OAuth 웹 클라이언트에는 `http://localhost`와 실제 개발 포트 원본을 등록하고, 동의 화면이 Testing이면 로그인할 계정을 Test users에 등록해야 한다.

- **FR-013**: 운영 웹 접속은 신뢰할 수 있는 무료 인증서를 사용하는 HTTPS로 제공하고 HTTP 접속은 HTTPS로 영구 리다이렉트해야 한다. 로컬 HTTP 개발은 유지한다.
- **FR-014**: 인증서 갱신은 운영 서버에서 자동 예약되어야 하며, 운영 문서는 예약 확인·모의 갱신·실행 결과 확인 절차를 제공해야 한다.
- **FR-015**: 인증서 개인키 및 계정 자격 증명은 저장소에 포함하지 않는다. 인증서 유효기간과 확인 결과는 확인일을 명시한 운영 기록으로 관리한다.

## Edge Cases

- Google tokeninfo 서비스에 연결할 수 없거나 검증에 실패하면 로그인은 거부되고 사용자에게 오류를 표시한다.
- 허용 목록 파일이 없거나 손상된 경우 일반 사용자 로그인은 허용되지 않으며 초기 관리자는 목록을 새로 구성할 수 있다.
- 서버 재시작 시 비공개 파일에서 유효한 세션을 복원한다. 기존 메모리 전용 세션은 이관하지 않으므로 최초 배포 후 한 번 재로그인한다.
- 허용 목록에서 이메일을 제거하면 세션 검사 시 접근이 거부되며, 현재 프로세스의 해당 세션도 즉시 제거된다.
- 대시보드 HTML/정적 자산은 브라우저에 제공되지만 데이터 API는 서버 세션 없이는 반환되지 않는다.

## Success Criteria

- **SC-001**: 허용 이메일은 유효한 Google 인증 후 로그인할 수 있고 미등록 이메일은 세션을 얻지 못한다.
- **SC-002**: 모든 대시보드 데이터 `/api` 엔드포인트가 로그인하지 않은 요청에 인증 오류를 반환한다.
- **SC-003**: 허용 목록 관리 요청은 `azikanbal@gmail.com` 계정에서만 성공한다.
- **SC-004**: 사용자는 프로필 아이콘으로 계정을 확인할 수 있고 프로필 창에서 로그아웃할 수 있다.

## Assumptions

- Google Identity Services의 웹 OAuth client ID는 프론트엔드 로그인과 서버 audience 검사에 동일하게 사용한다. 운영 환경에서 바꾸려면 `GOOGLE_CLIENT_ID` 환경변수를 설정한다.
- 로컬 로그인 테스트에서는 Google Cloud OAuth 웹 클라이언트의 Authorized JavaScript origins에 `http://localhost`와 `http://localhost:3000`을 등록한다. 동의 화면이 Testing이면 `azikanbal@gmail.com`도 Test users여야 한다.
- 세션은 단일 Node.js 프로세스의 메모리와 비공개 JSON 파일로 유지한다. 다중 인스턴스 동시 쓰기는 지원하지 않는다.
- 허용 목록은 서비스 프로젝트 루트의 비추적 JSON 파일에 보관한다.

## HTTPS 운영 확인 기록

- 2026-10-19 외부 점검: 운영 HTTPS 주소가 인증서 검증을 통과하고 HTTP 200을 반환했다. HTTP 주소는 HTTPS로 301 이동했다.
- 인증서 발급 기관: Let's Encrypt (`YR2`). 당시 인증서 유효기간은 한국 시간 2026-10-16 11:20:14부터 2027-01-14 11:20:13까지다. 갱신 후에는 이 기간이 달라지므로 현재 값은 서버에서 다시 확인한다.
- 사용자가 제공한 서버 출력: `certbot.timer` → `certbot.service`, 최근 실행 2026-10-19 04:00:28 UTC, 다음 실행 2026-10-19 21:20:28 UTC. 한국 시간으로 각각 10월 19일 13:00:28과 10월 20일 06:20:28이다. 이는 당시의 예약 기록이며 현재 다음 실행 시각을 뜻하지 않는다.
- 자동 갱신 예약 확인은 완료. `certbot renew --dry-run` 결과와 실제 인증서 갱신 성공 기록은 아직 제공되지 않아 미확인이다.
- 구체적인 점검 명령은 [quickstart.md](quickstart.md#https-및-인증서-갱신-점검)와 [운영 절차](../../docs/operations/server-runbook.md#8-https-및-무료-인증서-자동-갱신)를 따른다.

## 로그인 유지 확장 (2026-10-24)

- **FR-016**: 최초 Google 로그인 후 브라우저 프로필별 독립 세션을 발급한다. 같은 프로필의 탭은 쿠키를 공유한다. 별도 설정이나 로그인 유지 체크박스는 추가하지 않는다.
- **FR-017**: 자동 조회와 세션 확인도 연장 대상이다. 7일 유지와 30일 절대 기한을 서버가 집행하며 쿠키 수명은 서버 만료를 넘지 않는다.
- **FR-018**: `data/auth-private/sessions.json`에 원본 대신 SHA-256 세션 토큰 해시와 사용자 표시 정보, 생성·갱신·만료·재인증 시각을 저장한다. Google 자격 증명은 저장하지 않는다. 파일은 Git·정적 제공·일반 설정 백업에서 제외한다.
- **FR-019**: 파일은 임시 파일 작성 후 교체하며 저장 실패를 기록한다. 실패한 세션 발급은 성공 처리하지 않고 갱신 실패 시 기존 만료를 유지한다. 손상된 파일은 인증 복원에 사용하지 않는다.
- **FR-020**: 로그아웃은 해당 세션을 파일에서도 제거하고 허용 취소는 해당 계정 모든 세션을 무효화한다. 서버 재시작으로 유지기간을 초기화하지 않는다.
- **FR-021**: 상단 서버 여유 왼쪽에 간격을 두고 `재인증 D-OO일`을 표시한다. 남은 시간을 일 단위로 올림하고 열린 페이지에서도 갱신한다. 30일 도달 또는 만료 응답 시 로그인 화면으로 돌아간다.
- **FR-022**: D-7~D-1에는 보이는 페이지에서 남은 일수 팝업을 한국 날짜 기준 하루 한 번 표시한다. 프로필 localStorage로 같은 세션의 새로고침·탭 간 중복을 억제한다. 다른 PC·프로필은 별도이며 저장소 삭제 시 재표시될 수 있다. 백그라운드는 복귀 시 안내한다.
- **SC-005**: 재시작 복원, 해시 저장, 시간당 갱신, 7일 미접속 만료, 고정 30일 기한, 로그아웃·허용 취소 및 파일 실패를 로컬 테스트로 검증한다.
- **SC-006**: D-07/D-06 표시, 같은 날 재로딩 중복 방지, 다음 한국 날짜 알림과 기한 도달 처리를 로컬 테스트로 검증한다. 실제 Google 로그인·운영 재시작·헤더 배치는 배포 후 별도 검증한다.

상세 구현 기록: [로그인 세션 정책](../../docs/operations/2026-10-24-login-session.md). 서버의 데이터 수집 정책은 이번 범위에서 변경하지 않는다.
