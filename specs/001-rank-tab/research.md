# Research: Rank 탭

## Decision: Node.js + Express 유지
- **Rationale**: 이미 프로덕션(Oracle Cloud)에서 안정적으로 운영 중이며, Constitution 원칙 IV(Solo-Maintainer Simplicity)에 따라 새 프레임워크 도입은 정당화되지 않는다.
- **Alternatives considered**: NestJS 등 구조화된 프레임워크 — 1인 개발·소규모 트래픽 환경에 비해 과도한 복잡성으로 기각.

## Decision: 인증 토큰 메모리 캐싱
- **Rationale**: 키움/한투 토큰은 24시간 유효하며 단일 서버 프로세스 내 변수(`cachedToken`, `tokenExpiryTime`)로 캐싱하는 것으로 충분하다.
- **Alternatives considered**: Redis 등 외부 캐시 저장소 — 다중 서버 인스턴스가 없는 현재 규모에서 불필요(YAGNI).

## Decision: 순차 처리 + 100ms 지연으로 Rate Limit 대응
- **Rationale**: 키움 REST API의 초당 요청 제한(약 5회)을 준수하기 위한 가장 단순한 방법이며 이미 코드에 적용되어 있다.
- **Alternatives considered**: Bottleneck 등 전용 rate-limiting 라이브러리 — 현재 호출 패턴(패널당 최대 20개 종목)에서는 과한 의존성 추가로 기각.

## Decision: 시장 구분(KOSPI/KOSDAQ) 캐시를 서버 메모리 Map으로 유지
- **Rationale**: 서버 재시작 시 캐시가 초기화되어도 재구성 비용이 낮아(개별 조회 3초 제한 내) 무리가 없다.
- **Alternatives considered**: 파일 또는 DB 영속화 — 이 정도 규모에서는 불필요한 인프라 추가.

## Decision: 거래대금 순위는 상위 30개 후보만 시장 보정
- **Rationale**: `/api/transaction_rank` 응답은 화면에서 최대 20개만 렌더링한다. 원본 100개를 모두 ka10100으로 순차 보정하면 초기 표시가 5초 목표를 넘을 수 있어, ETF/비주식 필터로 제외될 여지를 고려해 상위 30개만 처리한다. 2026-10-01 localhost 수동 조회에서 원본 100건을 받고 30건을 약 4초 안에 반환한 로그를 확인했다.
- **Trade-off**: 상위 30개 후보 중 11개 이상이 필터링되면 화면에 20개보다 적게 표시될 수 있다. 화면은 요구사항대로 최대 20개를 표시한다.
- **Alternatives considered**: 원본 100개 전체 순차 보정 — 필터링 후 20개를 채울 가능성은 높지만 초기 표시 목표를 넘는 기존 지연을 유지하게 되어 기각.

## 쏠림율 확장 결정 (2026-10-07)

- 두 순위 표는 같은 시장별 누적 거래대금 비율 함수를 공유한다. 시장 판별 실패를 임의의 코스닥 분모로 계산하지 않는다.
- 일봉은 종목·시장 모두 실제 trde_prica를 사용한다. 지수×거래량은 실제 거래대금과 일치하지 않으므로 대체하지 않는다. 2026-10-07 삼성전자와 코스피 실제 응답은 일봉 32.788394…%, 테이블 반올림 33%로 일치했다.
- 분봉 시장 거래대금은 사용자가 지정한 지수 /100, 거래량 ×10000 보정 추정식을 채택한다. 실제 거래대금 필드가 있는 일봉과 신뢰 수준이 다르며 공식 거래량 단위 검증 완료로 주장하지 않는다. 시간 구간별 현재 지수×거래량은 구성 종목 거래대금 합계와 정확히 일치하지 않을 수 있다.
- 시장 API의 간격 제한 때문에 15·45분은 5분, 60분은 30분으로 합산한다. 09:00 기준 날짜별 버킷으로 정렬하고 분모가 없는 분봉은 화면 시간축에서 제거한다.
- 사용자 선택으로 초기 70% 축 제한을 데이터에 맞춰 자동 확대하도록 변경했다. 일봉은 월 경계로 구분해 세로 점선이 촘촘한 격자로 보이는 문제를 방지한다.
- 기존 정적 JavaScript/canvas와 Express를 유지하고 계산·조회 및 브라우저 차트를 작은 별도 모듈로 분리했다. 과거 데이터는 사용자별 메모리 커서로 관리하며 종목·시장 연속조회 헤더를 분리하고 실패 시 성공 상태를 보존한다.
- 차트 자동 갱신은 기존 Rank 타이머를 공유한다. 최신 페이지와 과거 기록을 병합하고 확대 구간을 유지하며 조회·드래그·캡처 중 겹치는 갱신을 건너뛴다.
- 검증은 원천 모의 테스트와 브라우저 통합 테스트, 별도 실제 응답 검산으로 나눈다. 기존 패널 보류 항목이나 운영 환경 속도 검증을 차트 테스트로 대체하지 않는다.

추가 표시 결정: 분봉 하루 전체 구간도 날짜 하나 대신 매시 시간 눈금을 표시한다. X축은 분을 생략하며 화면 폭이 부족하면 시간 눈금 간격을 늘린다.

분봉 X축은 전체 보기에서 시간만 표시하고, 확대 후 인접 눈금 사이에 충분한 여유가 있으면 30분 간격(09:00·09:30 등)으로 표시한다. 화면이 좁으면 매시 또는 더 넓은 간격을 유지한다.

분봉 X축 눈금에는 시·분 접미사를 붙이지 않는다. 매시 간격은 09·10처럼, 30분 간격은 09:00·09:30처럼 표시한다.

## 개발 도구 폴더 정리 (2026-10-09)

자동 검증 코드는 dev/tests, 조회·추출·점검·복구 및 수동 실험 도구는 dev/scripts에 모으고 PNG·TXT·JSON·HTML 테스트 결과 및 자료는 dev/output에 모은다. 기존 experiments/tests/logs/exports 하위 폴더는 이 기준으로 통합했다. 출력 경로는 실행 작업 디렉터리와 무관하게 스크립트 위치 기준 dev/output으로 지정한다. 운영 로그는 프로젝트 바로 아래 logs에 일자별로 기록하고, dev/output에는 테스트 결과물만 저장한다. 자동 회귀 테스트도 dev/tests에 포함한다. 과거 fix/patch 스크립트는 일회성 수정 도구이며 이동 과정에서 실행하지 않는다.

데이터 추출 예: node dev/scripts/export-kospi-five-minute.js, node dev/scripts/check-kospi-outside-session.js. 정리는 파일 이동 전후 SHA256 일치로 검증했고, 변경한 스크립트는 구문 검사로 확인한다. API 호출이나 과거 패치 실행은 검증에 필요하지 않다.

## Rank ADR 결정 및 확인 범위 (2026-10-13)

- 고정 ADR 탭과 adrinfo.kr HTML 파싱을 제거하고 Rank ADR에서 Jusikbot today/history JSON을 이용한다. 사용자가 지정한 소스의 ADR를 직접 표시하며 ka20003 rising/fall만으로 20일 ADR를 구성하는 방법은 구현하지 않았다.
- 사용자가 서버 용량 절약을 위해 전일 분봉 서버 저장을 요청 범위에서 제외했다. 원천에 intraday가 남아 있는 동안 표시하고, 없으면 lastClosed 또는 이미 브라우저가 받은 기록으로 축소한다. 자정 이후 빈 intraday 응답을 관찰했지만 정확한 초기화 시각은 검증하지 않았다.
- intraday는 10초 간격 표본일 수 있으므로 그대로 1분봉이라 부르지 않고 분 단위로 병합한다. t는 초, asOf는 밀리초이며 장외 asOf는 차트 봉으로 만들지 않는다.
- 실제 1Y history 확인: 245개 series, 2025-10-13~2026-10-13, 마지막 ADR 70.72. 이 표본은 확인 당시 응답이고 운영에서 고정값으로 사용하지 않는다.
- 지수 캔들은 ADR 비율이 아닌 KOSPI/KOSDAQ OHLC를 비교하는 보조 그래프다. 기존 키움 지수 필드·가격 /100 처리를 따른다. 모의 테스트의 페이지 병합·스케일 검증을 실제 장기 지수 조회 완료로 취급하지 않는다.
- 정보창은 메인 그래프에만 표시하고 캔들 tooltip·ADR X축 커서 날짜 배지는 제거했다. 줌 바의 좌측 채움은 기간 이동을 확대/축소로 오해하게 해 제거했다.

## 거래대금 및 공통 차트 결정 (2026-10-13)

- 거래대금은 ADR의 오른쪽에 추가하고 세 차트 폭을 균등 분할한다. 기존 쏠림율의 거래대금 표 기준 고정 폭/디버깅 추가 폭보다 같은 줄 배치를 우선한다.
- 일봉 거래대금 원천은 이미 쏠림율 분모로 사용한 ka20006 trde_prica다. API 응답 필드는 공통 market_turnover(원)로 통일하고 변환 함수를 공유한다. 별도 추정값·서버 기록 저장·신규 데이터 소스는 추가하지 않는다.
- 두 시장/날짜 합집합은 동시에 유지한다. 시장 선택은 강조·지수 캔들만 변경한다. 동일 응답에 OHLC를 포함해 캔들 펼침 때 네트워크 호출을 추가하지 않는다.
- 거래대금 위 정보 줄과 캔들 버튼 행의 두 줄 오늘 값은 역할이 다르다. 정보는 커서 날짜 값, 마지막 값은 오늘 봉이며 과거 구간으로 이동해도 유지한다. 오늘 봉이 없는 휴장일에는 마지막 거래일을 오늘처럼 표시하지 않는다.
- 공통 오른쪽 Y축·회색 점선·오늘 주황 점·파란 쏠림율/ADR 선·값 기준 수평 가이드/배지를 적용한다. ADR 분봉의 모든 표본 점은 선을 가려 제거하고 오늘 마지막 점과 이동 점을 유지한다. MAX/MIN 표식은 사용자 요청으로 제거했다.
- ADR 마지막 점이 plot clip 경계에서 반으로 잘린 문제는 선만 clip하고 점을 해제 후 그려 해결한다. 배지와 최종값은 오른쪽 경계를 넘지 않도록 위치를 제한한다.
- 브라우저/API 모의 테스트와 픽셀 검증이 통과한 범위만 기록한다. 실제 서버 거래대금 필드 누락 원인은 로그인 응답을 확인하지 못해 확정하지 않았으며, 구버전 서버 응답과 원천 누락을 구분해야 한다. 실제 장기 조회·Oracle 운영 검증은 남겨 둔다.

### 운영 확인 후 검증 범위 (2026-10-13)

사용자 직접 확인: “oracle에서 세 차트 모드 잘 동작한다.” Oracle 운영 세 차트 정상 동작은 확인되어 T089를 완료했다. 이 증거는 모의 테스트와 구분하며 원천 데이터 누락 원인을 역으로 확정하거나 모든 기간/모드/오류 조합을 검증했다고 해석하지 않는다. 실제 데이터 검산 등은 T088/T090에 남긴다.

### 분봉 추정치의 실제값 비교 (2026-10-14)

첨부된 키움 ka20005 API 표에는 `trde_qty`와 `acc_trde_qty`만 있고 분봉 거래대금 필드가 없다. 하단의 `inds_dt_pole_qry`/`dt`/`trde_prica` 예시는 일봉 구조다. 따라서 지수×거래량×10,000 추정식을 실제 거래대금으로 승격하지 않는다. 2026-10-14 키움 1분봉 각 382개를 누적해 같은 날 ka20006 일봉 실제 거래대금과 비교했다: KOSPI 추정 22.7143444069조원 대 실제 21.390191조원(+6.19%), KOSDAQ 추정 3.8962688292조원 대 실제 6.165148조원(-36.80%). 단일 거래일의 표본이며 추정식의 안정적 정확도를 입증하지 않는다. 특히 KOSDAQ 오차가 커서 전일 대비 비율 역시 추정치로 안내한다.
