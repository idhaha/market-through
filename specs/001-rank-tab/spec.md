\## User Scenarios \& Testing \*(mandatory)\*



\### User Story 1 - 거래대금·실시간 조회 순위 확인 (Priority: P1)



사용자는 Rank 탭을 열어 국내 주식시장(코스피/코스닥)에서 전일 동시간 대비 거래대금이 많은 종목과, 키움증권 실시간 조회 순위가 높은 종목을 한눈에 확인할 수 있다. 순위는 자동으로 주기 갱신되며, 필요할 때 수동으로도 즉시 새로고침할 수 있다.



\*\*Why this priority\*\*: 이 두 패널이 Rank 탭의 핵심 목적(실시간 자금 유입·관심도 모니터링)이며, 이것만 동작해도 최소 기능 제품(MVP)으로서 가치를 제공한다.



\*\*Independent Test\*\*: Rank 탭을 열었을 때 거래대금 상위 표와 실시간 조회 순위 표가 각각 상위 20개 항목을 시장 구분(K/Q)과 함께 표시하는지 확인하여 독립적으로 검증할 수 있다.



\*\*Acceptance Scenarios\*\*:



1\. \*\*Given\*\* 사용자가 Rank 탭을 처음 연 상태, \*\*When\*\* 페이지가 로드되면, \*\*Then\*\* 거래대금 상위 패널과 실시간 조회 순위 패널에 각각 최대 20개 종목이 순위·시장·종목명·등락률·거래대금과 함께 표시된다.

2\. \*\*Given\*\* 사용자가 새로고침 주기를 변경한 상태, \*\*When\*\* 설정한 시간이 경과하면, \*\*Then\*\* 두 패널의 데이터가 선택한 주기에 맞춰 자동으로 갱신되고 최근 갱신 시간이 업데이트된다.

3\. \*\*Given\*\* 사용자가 수동 조회 버튼을 클릭한 상태, \*\*When\*\* 클릭이 발생하면, \*\*Then\*\* 4개 패널의 데이터가 동시에 즉시 갱신을 시도한다.

4\. \*\*Given\*\* 데이터 조회 중 통신 오류가 발생한 상태, \*\*When\*\* 오류가 감지되면, \*\*Then\*\* 에러 패널에 실패 사유가 표시되고 상태 메시지가 "데이터 로딩 실패"로 바뀐다.



\---



\### User Story 2 - 대주가능 종목 확인 (Priority: P2)



사용자는 한국투자증권 eFriend 연동을 통해 현재 대주가 가능한 종목 목록을 등락률이 높은 순으로 확인할 수 있다.



\*\*Why this priority\*\*: 공매도/대주 관련 정보는 일부 사용자에게만 필요한 보조 정보이며, 패널 1·2 없이도 별도로 표시·검증 가능하다.



\*\*Independent Test\*\*: 한투 API 키가 설정된 상태에서 패널 3이 대주가능 종목을 등락률 내림차순으로 표시하는지 확인하여 검증할 수 있다.



\*\*Acceptance Scenarios\*\*:



1\. \*\*Given\*\* 한투 API 키(EFRIEND\_\*)가 정상 설정된 상태, \*\*When\*\* Rank 탭 데이터가 로드되면, \*\*Then\*\* 대주가능 종목이 매매가능수량·매매가능금액과 함께 등락률 높은 순으로 표시된다.

2\. \*\*Given\*\* 한투 API 키가 설정되지 않은 상태, \*\*When\*\* 데이터 로드가 시도되면, \*\*Then\*\* 서버는 오류 없이 빈 목록을 반환하고 다른 패널은 정상 동작한다.



\---



\### User Story 3 - 관심종목 하락률 순위 확인 (Priority: P3)



사용자는 자신이 관리하는 관심종목 그룹 중 하나를 선택하여, 해당 그룹 내에서 하락률이 큰 종목을 순위대로 확인할 수 있다.



\*\*Why this priority\*\*: 개인화된 관심종목 기반 기능으로, 사용자가 그룹을 설정해야 의미가 있어 다른 패널보다 우선순위가 낮다.



\*\*Independent Test\*\*: 관심종목 그룹을 선택했을 때 해당 그룹의 하락률 상위 종목이 정렬되어 표시되는지 확인하여 검증할 수 있다.



\*\*Acceptance Scenarios\*\*:



1\. \*\*Given\*\* 사용자가 관심종목 그룹 드롭다운에서 그룹을 선택한 상태, \*\*When\*\* 선택이 확정되면, \*\*Then\*\* 해당 그룹 내 종목이 하락률이 큰 순서로 정렬되어 표시되고 선택값이 다음 방문 시에도 유지된다.

2\. \*\*Given\*\* 사용자가 그룹 ID를 직접 입력한 상태, \*\*When\*\* 입력이 완료되면, \*\*Then\*\* 드롭다운 선택 대신 입력한 그룹 ID 기준으로 즉시 조회된다.



\### Edge Cases



\- 장 운영 시간 외(야간/주말/공휴일)에 조회하면 어떻게 되는가? → 전일 마감 데이터를 정상 데이터로 취급해 그대로 표시하며, 오류로 처리하지 않는다.

\- 키움 API 인증 토큰이 만료되거나 무효화되면 어떻게 되는가? → 토큰을 즉시 무효화하고 다음 요청 시 재발급을 시도한다.

\- 필수 환경변수(키움 키)가 누락되면 어떻게 되는가? → 해당 요청은 HTTP 500을 반환한다.

\- 사용자가 화면 캡처 모드를 사용 중일 때 자동 갱신 주기가 도래하면 어떻게 되는가? → 캡처 중에는 자동 갱신을 건너뛴다.

\- 사용자가 Rank 탭이 아닌 다른 탭을 보고 있는 동안 자동 갱신이 실패하면 어떻게 되는가? → 오류 팝업 없이 콘솔 경고로만 기록한다.

\- 키움 API 요청이 초당 허용치를 초과하면 어떻게 되는가? → 종목별 상세 조회는 순차 처리하며 각 요청 사이 100ms 지연을 둔다.



\## Requirements \*(mandatory)\*



\### Functional Requirements



\- \*\*FR-001\*\*: 시스템은 Rank 탭에 거래대금 상위, 실시간 조회 순위, 대주가능 종목, 관심종목 하락률 순위의 4개 패널을 동시에 표시해야 한다.

\- \*\*FR-002\*\*: 시스템은 사용자가 새로고침 주기(30초/1분/10분/1시간/당일누적)를 선택할 수 있게 해야 하며, 선택된 주기에 맞춰 자동으로 데이터를 갱신해야 한다.

\- \*\*FR-003\*\*: 사용자는 수동 조회 버튼으로 4개 패널의 데이터를 즉시 동시에 갱신할 수 있어야 한다.

\- \*\*FR-004\*\*: 시스템은 마지막으로 성공한 데이터 수신 시간을 표시해야 한다.

\- \*\*FR-005\*\*: 시스템은 데이터 로딩 상태(대기 중/로딩 중/완료/실패)를 사용자에게 표시해야 한다.

\- \*\*FR-006\*\*: 통신 실패 시 시스템은 실패 사유를 포함한 에러 메시지를 표시해야 한다.

\- \*\*FR-007\*\*: 거래대금 상위·실시간 조회 순위 패널은 각각 상위 20개 종목으로 제한해 표시해야 한다.

\- \*\*FR-008\*\*: 시스템은 각 종목을 시장 구분(KOSPI/KOSDAQ)에 따라 분류하여 표시해야 하며, 판별 불가 시 이전에 확인된 유효한 값을 캐시에서 사용할 수 있다. 유효한 시장 정보가 없으면 시장을 추정하지 않고 쏠림율은 "-"로 표시해야 한다.

\- \*\*FR-009\*\*: 등락률은 양수/음수/0에 따라 서로 다른 색상으로 구분 표시해야 한다.

\- \*\*FR-010\*\*: 거래대금 상위 및 실시간 조회 순위 패널은 코스피 종목은 코스피, 코스닥 종목은 코스닥 전체 거래대금 대비 비율(쏠림율)을 동일한 정수 반올림 방식으로 계산해 표시해야 하며, 계산 불가 시 "-"로 표시해야 한다.

\- \*\*FR-011\*\*: 대주가능 종목 패널은 매매가능수량이 0을 초과하는 경우 강조 표시해야 하며, 매매가능금액(현재가 × 매매가능수량)을 계산해 표시해야 한다.

\- \*\*FR-012\*\*: 대주가능 종목 패널은 관련 API 키가 설정되지 않은 경우 서버 오류 없이 빈 목록을 반환해야 한다.

\- \*\*FR-013\*\*: 관심종목 하락률 패널은 사용자가 선택하거나 직접 입력한 그룹 ID 기준으로 조회되어야 하며, 하락률이 큰 순서로 정렬해야 한다.

\- \*\*FR-014\*\*: 사용자가 선택한 관심종목 그룹은 다음 방문 시에도 유지되어야 한다.

\- \*\*FR-015\*\*: 시스템은 종목 상세 정보를 순차 조회 시 요청 사이에 지연을 두어 외부 API의 초당 요청 제한을 준수해야 한다.

\- \*\*FR-016\*\*: 시스템은 인증 토큰을 캐시하여 재사용하되, 원천 API가 토큰 무효화를 응답하면 즉시 캐시를 폐기하고 재발급해야 한다.

\- \*\*FR-017\*\*: 시스템은 장 운영 시간 외에는 마지막 마감 데이터를 정상 데이터로 표시해야 하며 오류로 취급하지 않아야 한다.

\- \*\*FR-018\*\*: 사용자가 화면 캡처 중일 때 시스템은 자동 갱신을 일시 중단해야 한다.

\- \*\*FR-019\*\*: 사용자가 Rank 탭을 보고 있지 않은 상태에서 자동 갱신 오류가 발생하면, 시스템은 사용자에게 팝업을 띄우지 않고 기록만 남겨야 한다.

\- \*\*FR-020\*\*: 상단 `전체조회`는 Rank 시세/거래 순위/관심종목 순위, Rank ADR 및 동적 탭의 갱신 함수를 호출해야 하며, 버튼은 갱신 중 비활성화되었다가 2초 후 다시 활성화되어야 한다. 이 완료 표시는 원격 데이터 소스의 성공을 보장하는 동기 완료 표시가 아니라 갱신 명령 전송 상태를 의미한다.

\- \*\*FR-021\*\*: 작은 화면의 `더 보기` 버튼은 상단 작업 버튼 영역을 펼치거나 접어야 하며, 영역 바깥 클릭 시 메뉴를 닫아야 한다. 이 동작은 설정 스냅샷을 변경하지 않아야 한다.



\### Key Entities



\- \*\*거래대금 순위 항목(Transaction Rank Entry)\*\*: 순위, 종목코드, 종목명, 시장 구분, 등락률, 거래대금, 쏠림율을 가진다.

\- \*\*실시간 조회 순위 항목(Watch Rank Entry)\*\*: 순위, 종목코드, 종목명, 시장 구분, 등락률, 누적 거래대금, 시장 전체 거래대금, 쏠림율을 가진다.

\- \*\*대주가능 종목(Lendable Stock Entry)\*\*: 종목명, 시장 구분, 등락률, 매매가능수량, 매매가능금액을 가진다.

\- \*\*관심종목 그룹(Watchlist Group)\*\*: 그룹 ID, 그룹 내 종목 목록(순위·시장·종목명·등락률·거래대금 포함)을 가진다.



\## Success Criteria \*(mandatory)\*



\### Measurable Outcomes



\- \*\*SC-001\*\*: 사용자는 Rank 탭 진입 후 5초 이내에 4개 패널 모두의 초기 데이터를 확인할 수 있다.

\- \*\*SC-002\*\*: 자동 갱신이 활성화된 상태에서, 선택한 주기의 ±5초 이내에 데이터가 갱신된다.

\- \*\*SC-003\*\*: 외부 API 중 하나에 장애가 발생해도, 나머지 패널은 정상적으로 데이터를 계속 표시한다.

\- \*\*SC-004\*\*: 사용자가 관심종목 그룹을 변경한 뒤 다시 방문했을 때, 100%의 경우 마지막에 선택한 그룹이 유지된다.



\## Assumptions



\- 브라운필드 기능 문서화로, 초기 문서는 `br\_oracle` 브랜치의 동작을 기준으로 작성했다. 2026-10-07 갱신은 사용자가 추가 요청한 쏠림율 필드와 차트를 포함하며 배포 완료를 의미하지 않는다.

\- 사용자는 단일 운영자(본인)이며, 별도의 권한 체계나 다중 사용자 인증은 이 기능 범위에 포함하지 않는다.

\- 외부 API(키움, 한투 eFriend)의 응답 형식은 사양서에 기술된 형태로 유지된다고 가정한다.

\- 기존 패널의 반응형 동작은 유지하며, 쏠림율 차트는 데스크톱에서 테이블 영역의 절반 폭, 휴대폰에서는 화면 폭 안에 표시한다.

\- `GET /api/watchlist_debug`는 `curl` 등으로 수동 호출하는 디버그 전용 엔드포인트이며, 프론트엔드(`public/app.js`)에서 호출하지 않는다. Rank 탭의 정상 동작에는 영향을 주지 않으며, 향후 제거 여부는 별도로 검토한다.

## 2026-10-07 추가 범위: 쏠림율 차트

### User Story 4 - 선택 종목의 쏠림율 추이 확인 (Priority: P1)

사용자는 거래대금 상위·실시간 조회 순위·대주가능 테이블의 종목을 선택해 아래 공통 차트에서 일봉 또는 분봉 쏠림율과 현재 값을 확인한다.

**Independent Test**: 세 테이블 각각의 행을 클릭하거나 Enter/Space로 선택하고, 봉 종류·간격·조회 기간·갱신 주기를 바꿔 선택 종목의 추이가 유지되는지 확인한다.

**Acceptance Scenarios**:

1. 종목을 선택하면 종목명과 시장 구분을 헤더에 표시하고 기본 조회 과거 데이터 전체를 그린다. 일봉 선택 시 분 간격 버튼은 비활성화된다.
2. 시장 거래대금이 없는 분봉은 시간축에서도 제외한다. 시장 판별 실패는 계산 불가로 처리하고 다른 시장으로 대체하지 않는다.
3. 로딩 중 시장 표기와 차트 위치를 유지하며 기존 차트에 약한 블러를 적용한다. 최신 값은 그래프와 겹치지 않는 헤더 우상단에 표시한다.
4. 추가조회로 과거 데이터를 확장하고, 버튼·슬라이더·드래그로 조회 범위를 조절한다. 자동 갱신은 추가로 가져온 과거 기록과 확대 구간을 유지한다.

### 추가 Functional Requirements

- **FR-022**: 세 테이블 아래 공통 쏠림율 차트를 두고, 클릭 및 키보드 선택에 응답해야 한다. 표 갱신 후에도 선택 표시를 유지해야 한다.

## 5분봉 원본 비교 디버깅 (2026-10-08)

차트 오른쪽에 삼성전자(ka10080, 통합 거래소 005930_AL)와 코스피(ka20005, 업종 001)의 최근 완료된 5분봉 5개를 각각 최신순으로 표시한다. cntr_tm은 봉 시작 시각이며 시작+5분이 지난 봉만 포함한다. cur_prc·trde_qty는 부호·선행 0을 포함한 원본 값을 그대로 표시한다. 두 원천을 따로 표시해 시장 데이터 누락을 숨기지 않는다. 비교 대상은 차트 선택 종목·간격과 독립적이다.

최초 화면 표시 때 조회하고 5분 경계 2초 뒤마다 재조회한다. 진행 중 봉은 제외하고 조회 실패 시 기존 표를 유지한다. 중복 조회·숨김 문서·캡처 중 조회를 건너뛰며 문서 복귀 시 재조회한다. 디버깅용 타이머는 Rank 주기의 차트 갱신 타이머와 별도다. 데스크톱 패널 폭은 기존 절반 폭에 360px를 추가하며 휴대폰은 표를 차트 아래에 배치한다.

차트 API의 minute/interval=5 응답은 debug_five_bars={fetched_at, stock, market}를 추가한다. stock·market 배열 항목은 {cntr_tm, cur_prc, trde_qty} 원본 필드이며 다른 봉 종류·간격에서는 debug_five_bars=null이다. 디버깅 요청은 code=005930, mode=minute, interval=5를 고정한다. 운영 서버는 새 응답 필드 반영을 위해 재시작해야 한다.

## 차트 종목 직접 입력

차트 종목명은 편집 가능한 입력란이다. 정확한 종목명 또는 6자리 종목코드를 입력하고 Enter를 누르면 테이블 표시 여부와 무관하게 해당 종목 차트를 조회한다. 현재 일/분 및 간격 설정은 유지한다. 실패 시 기존 선택과 차트를 유지하며 오류를 안내하고, 검색 중 테이블 종목을 선택하면 늦은 검색 결과를 무시한다.

인증된 GET /api/concentration-stock?q=입력값은 {success:true, stock:{code,name,market}}를 반환한다. 이름 조회는 ka10099의 코스피/코스닥 전체 연속조회 목록으로 정확히 일치하는 종목을 찾고 성공 목록을 24시간 메모리 캐시한다. 코드 조회는 ka10100으로 이름과 시장을 검증한다. 빈 입력 400, 미일치/모호한 이름/지원하지 않는 시장 404, 외부 오류 502다. 최초 이름 조회는 목록을 가져오는 시간이 필요하다. 서버 재시작이 필요하다.

### 디버깅 대상 및 조회 방식 수정

이전 삼성전자 고정 규칙을 대체한다. 디버깅은 테이블 또는 직접 입력으로 선택한 종목과 해당 시장(코스피 001 / 코스닥 101)의 완료된 최근 5개 5분봉을 표시한다. 선택 즉시 재조회하고, 다른 종목의 늦은 응답을 취소·무시한다. 차트 봉 설정과 무관하게 디버깅은 5분봉을 사용한다.

POST /api/concentration-chart에 {code:선택종목, mode:"minute", interval:5, debug_five:true}를 보내면 최신 원천 페이지 두 개만 조회하여 {success,market,debug_five_bars}를 반환한다. 과거 기록 보충·차트 커서 생성은 생략한다. 빈 데이터·조회 실패·서버 응답 필드 누락을 표에 안내한다. 실패 시 같은 종목의 기존 값은 보존한다. 새 서버 코드 적용에는 재시작이 필요하다.

### KRX 종료 후 디버깅 갱신 중지

한국 시간 평일 09:00~15:30에만 디버깅을 조회한다. 15:30 경계의 예약 조회는 2초 뒤 마지막 완료 봉을 한 번 가져오고 중지한다. 이후 예약·종목 선택·문서 복귀로도 디버깅을 조회하지 않으며 기존 표를 유지하고 갱신 중지 상태를 표시한다. 다음 평일 정규장 시간에 예약 조회가 재개된다. 일반 쏠림율 차트의 Rank 주기 갱신 규칙은 유지한다. 이 시간 게이트는 정규 시간 기준이며 휴장일·특별 운영시간 자동 판별은 포함하지 않는다.

### 동일 시각 디버깅 비교 (2026-10-09)

종목의 독립적인 최신 5봉 대신 시장의 최근 완료된 5개 5분봉 cntr_tm을 기준으로 종목 원본을 정확히 매칭한다. stock·market 배열의 길이와 시각 순서는 동일하다. 해당 시각 종목 봉이 없으면 그 시각은 유지하고 cur_prc/trde_qty를 null(UI는 -)로 표시한다. 시장 마감 이후 NXT 종목 봉은 비교 표에 포함하지 않는다. 시장 봉이 없으면 양쪽 모두 빈 배열이다. 이 규칙은 일반 차트 응답의 디버깅 필드와 디버깅 전용 요청에 동일하게 적용한다.


쏠림율은 모든 유효한 봉에 주황색 원형 표식을 가진 꺾은선으로 표시한다. 불러온 마지막 현재 봉이 표시 범위 안에 있으면 그 표식은 더 큰 파란색 원과 흰 테두리로 구분한다. 과거 범위의 마지막 봉을 현재 봉으로 표시하지 않는다.

## 쏠림율 아래 종목 캔들차트

종목 ka10080/ka10081 원본 open_pric·high_pric·low_pric·cur_prc의 절댓값을 stock_open·stock_high·stock_low·stock_price로 전달한다. 같은 봉 배열과 X좌표를 공유하는 캔들차트를 쏠림율 아래 기본 닫힘 상태로 두고 버튼으로 펼치거나 접는다. 시가보다 현재가가 높으면 붉은색, 낮으면 파란색, 같으면 회색이다. OHLC가 누락·무효이면 해당 위치는 유지하고 캔들을 그리지 않는다.

일봉·모든 분 간격·추가조회·확대·이동·자동갱신·계산 불가 분봉 제거가 두 차트에 동일하게 반영된다. 어느 차트에서 마우스를 이동해도 동일 봉의 날짜/시간·쏠림율·전일 대비 상승률을 메인 쏠림율 차트 정보창 한 곳에 표시하고 두 차트에 같은 수직선을 표시한다. 전일 종가를 확인할 수 없으면 상승률은 -다. OHLC는 캔들 렌더링에 사용하며 정보창에는 표시하지 않는다. 가격 축은 현재 표시 범위의 OHLC에 맞춰 조절하되 시간축은 쏠림율 차트와 정확히 공유한다. 서버 재시작 후 새 OHLC 필드를 받을 수 있다.

### 마우스 정보와 전일 대비 상승률

마우스 정보는 메인 쏠림율 차트 내부의 빈 공간 한 곳에 표시하며 캔들차트에는 중복 정보창을 표시하지 않는다. 날짜/시간 · 쏠림율 · 상승률 순으로 표시하고 OHLC 및 시가 대비 문구는 제거한다. 상승률은 (현재 봉 현재가 / 전일 종가 - 1) × 100이다.

원천 pred_pre 및 pred_pre_sig(1/2 상승, 4/5 하락, 3 보합)로 전일 종가를 복원하여 stock_previous_close·stock_change_rate를 반환한다. 전일 대비 기호가 없으면 명시적 부호가 있는 pred_pre 또는 0만 사용한다. 일봉은 전일 대비 필드가 없을 때 직전 거래일 봉 종가를 사용할 수 있다. 분봉은 직전 분봉 또는 당일 시가를 전일 종가로 대체하지 않는다. 기준을 확인할 수 없으면 상승률은 -다. 새 필드는 서버 재시작 후 적용된다.


캔들차트의 세로 날짜 구분선은 쏠림율에서 계산한 경계 X좌표를 그대로 공유한다. 분봉은 날짜 경계, 일봉은 월 경계이며 최소 32px 간격과 회색 점선 스타일을 동일하게 적용한다. 확대·이동·리사이즈 후에도 구분선 위치가 일치한다.


캔들차트 펼침/접음 버튼은 헤더의 과거 데이터 불러오기 버튼 바로 오른쪽에 12px 간격으로 배치한다. 두 버튼을 같은 그룹에 넣어 좁은 화면에서도 함께 배치한다.

### 차트 내부 여백에 마우스 정보 배치

고정 외부 정보 영역을 제거하고 기존 정보 색상을 유지한 채 메인 쏠림율 차트 안 한 곳에만 정보를 표시한다. 선택 봉의 위·아래 공간을 비교해 여유가 큰 쪽 끝을 우선 선택한다. 정보 상자와 선분·표식 또는 캔들 고저가 영역의 충돌을 검사해 좌우 빈 위치를 찾는다. 우선 방향에 빈 위치가 없으면 반대 방향을 확인하고, 모든 위치가 겹치는 경우 겹침이 가장 적은 위치를 사용한다. 상자는 차트 가로 경계를 넘지 않고 마우스 이벤트를 가로막지 않는다. 날짜/시간·쏠림율·전일 대비 상승률 내용은 유지한다.


두 차트 모두 포인터 드래그 확대/전체 복원을 지원한다. 어느 차트에서 시작해도 드래그 진행 영역의 X좌표·폭·방향별 색상을 두 차트에 동일하게 표시한다. 공유 표시 범위를 변경하므로 종료 후 확대/복원 결과도 동일하다. 포인터 캡처·취소 처리는 드래그를 시작한 캔버스에 귀속하며 조회를 추가로 발생시키지 않는다.


디버깅 표 오른쪽에 최근 5봉 각각의 계산 거래대금(원)을 표시한다. 종목은 abs(cur_prc)×trde_qty, 시장은 사용자 지정 추정식 (abs(cur_prc)/100)×(trde_qty×10000)이다. 쉼표로 자릿수를 구분하고 원본 필드가 누락·무효이면 -로 표시한다. 시장 값은 실제 거래대금이 아닌 기존 추정식 결과다. 비교 표 폭은 430px, 데스크톱 패널은 기존 절반 폭에 450px를 추가한다.


현재 쏠림율 숫자는 상단 헤더 대신 쏠림율 세로축 위에 표시하며 쏠림율 제목 글자는 제거한다. 디버깅은 세로축 중앙의 텍스트 없는 화살표 버튼으로 펼치거나 접는다. 버튼은 접근 가능한 이름과 펼침 상태를 제공한다. 접으면 패널 폭을 원래 절반 폭으로 복원하며 기존 디버깅 값·차트 선택·표시 구간을 보존한다.

### Rank 차트 펼침 상태 저장

사용자 설정 스냅샷에 rankChartDisplay={debugOpen:boolean,candleOpen:boolean}를 포함한다. 둘의 기본값은 false이며 필드가 없는 예전 설정도 닫힘으로 복원한다. 버튼 변경은 기존 saveAppData 경로로 로컬 설정과 autosaved_user_settings.json에 저장한다. 전체 설정 다운로드 및 manualsaved_user_settings/full_backup 수동 백업도 같은 스냅샷 필드를 포함한다. 기존 설정 파일·과거 백업을 직접 덮어써서 마이그레이션하지 않는다.

시작 시 서버/로컬 설정 적용과 수동 백업 복원 모두 동일한 상태 적용 함수를 사용한다. 복원 자체는 토글 클릭이나 별도 자동 저장을 발생시키지 않는다. 값은 엄격한 boolean true만 펼침으로 처리한다. 저장 실패 처리는 기존 설정 동기화 정책을 따른다.


현재 쏠림율 숫자는 캔들 펼침 버튼과 같은 헤더 가로줄에 배치해 축 위 별도 높이를 없앤다. 디버깅 펼침 버튼은 세로축보다 오른쪽인 차트 영역 맨 오른쪽 끝에 붙이고 세로 중앙을 유지한다. 축 숫자는 버튼과 겹치지 않도록 오른쪽 여백을 확보한다.


줌 슬라이더·± 버튼 및 기간 표시를 디버깅 영역과 분리된 차트 열 안에 배치한다. 디버깅 펼침으로 패널 전체가 넓어져도 줌 조절 영역은 차트 열의 폭을 유지한다. 데스크톱 추가 450px는 디버깅 434px와 열 간격 16px로 맞추며 휴대폰에서는 줌 영역이 캔들차트 아래, 디버깅 표 위에 위치한다.


캔들 버튼의 표시 글자는 캔들차트만 사용하며 펼침/접음은 접근 가능한 이름과 aria-expanded로 제공한다. 디버깅을 접었을 때 차트 패널 폭은 거래대금 상위 패널의 실제 폭과 맞춰 내부 차트 폭이 테이블 폭과 같도록 한다. ResizeObserver로 표 패널 폭 변경을 반영하고 모바일 화면 폭 제한을 유지한다. 디버깅 펼침은 이 기준 폭에 450px를 추가한다.


일·분 선택 버튼은 종목 입력 아래 분봉 간격 버튼과 동일한 가로줄에 배치한다. 두 그룹이 서로 다른 줄로 나뉘지 않도록 공통 행으로 묶는다.


일·분, 분 간격, 추가조회, 캔들 버튼 및 현재 쏠림율을 같은 공통 행으로 묶는다. 버튼 폭과 간격을 조절해 데스크톱 차트 폭 안에 배치하며 매우 좁은 화면에서는 같은 행을 가로 스크롤한다.

### 봉 종류와 간격 저장

차트 기본 봉 종류는 day(일봉), 기본 분 간격은 1이다. 기존 rankChartDisplay 설정에 mode(day/minute)와 interval(1·3·5·10·15·30·45·60)을 추가한다. 일·분 및 분 간격 변경은 기존 사용자 설정 자동 저장과 수동 백업에 포함된다. 시작/설정 불러오기/전체 백업 복원 시 선택 버튼과 차트에 적용한다. 필드가 없거나 무효이면 일봉·1분으로 처리한다. 일봉에서도 마지막 분 간격을 보존하고 분봉 전환 시 적용한다.


### 종목 자동완성
- 차트 종목 입력 시 완성된 글자의 부분 일치 종목을 목록으로 제공하고 클릭 또는 방향키·Enter로 선택한다.
- 서버 시작 시 전체 코스피·코스닥 ka10099 연속조회로 메모리 마스터를 구축하고 한국시간 매일 08:42 갱신한다. 이후 입력 검색은 외부 API 없이 서버 로컬에서 처리한다.
- stk_cd/stk_nm 및 문서 실제 응답 code/name을 지원하고 갱신 실패 시 마지막 정상 마스터를 유지한다.

## 2026-10-13 추가 범위: Rank ADR 차트 및 공통 차트 표시

기존 쏠림율 확장의 단계별 UI 기록 중 모든 봉 표식, 거래대금 표 기준 고정 폭 및 디버깅 펼침 시 패널 폭 추가 설명은 아래 FR-032와 최신 거래대금·공통 표시 절로 대체한다. 현재 패널은 세 차트의 같은 줄 배치를 유지한다.

이 절은 현재 로컬 코드의 최종 동작을 기록한다. 이전 절과 충돌하는 정보창·캔들 기본 상태·하단 배치 설명은 이 절을 따른다. Oracle 배포 완료를 의미하지 않는다. ADR 고정탭과 전용 HTML 프록시는 제거했다. ADR는 Rank 차트에서 제공한다.

### User Story 5 - 시장 ADR 추이와 지수 캔들 비교 (Priority: P1)

사용자는 쏠림율 차트 오른쪽의 ADR 차트에서 KOSPI/KOSDAQ, 일/당일 1분, 일별 기간을 선택하고 같은 시간축의 시장 지수 캔들 및 확대 구간을 비교한다.

**Acceptance Scenarios**:

1. 최초 조회는 KOSPI·1분이며, 시장 변경은 해당 시장 API로 즉시 전환한다. 일 선택은 기본 1Y 및 6M·1Y·3Y·5Y 버튼을 제공한다.
2. `intraday`의 초 단위 타임스탬프를 1분으로 묶어 같은 분의 마지막 값을 표시한다. 불러온 최신 거래일을 표시하고 새로운 당일 타임스탬프가 들어오면 오늘로 전환한다. 오래된 응답이나 빈 응답 때문에 이미 수신한 분봉을 지우지 않는다.
3. 장 마감 후에도 원천에 분봉이 남으면 표시한다. 새 브라우저 조회에서 분봉이 없고 `lastClosed`만 있으면 마감값 점과 분봉 기록 없음 안내를 표시한다. 원천의 자정 초기화 시점은 확정된 계약으로 가정하지 않는다.
4. Rank 갱신주기마다 현재 모드를 조회하고 캔들 펼침 중에는 ADR 조회 완료 후 지수도 조회한다. 접힌 캔들은 조회하지 않으며 시장·기간·모드 변경 및 캔들 펼침은 즉시 조회한다.
5. 두 캔버스 중 어느 쪽을 가리켜도 수직선이 연동되며 날짜/시간·ADR 정보는 메인 ADR 차트에만 표시한다. 캔들 OHLC 정보창과 커서 X축 날짜 배지는 표시하지 않는다.
6. +/−, 과거 이동 슬라이더, 오른쪽 드래그 확대·왼쪽 드래그 전체 복원이 ADR와 지수 캔들에 함께 반영된다. 자동 갱신은 확대 범위를 유지하고 드래그 중 도착한 갱신은 종료 후 처리한다.

### 추가 Functional Requirements

- **FR-032**: 쏠림율·ADR·거래대금 순서로 세 차트의 가로폭을 균등하게 조정해 같은 줄에 표시한다. 좁은 화면에서는 기존 Rank 가로 스크롤을 사용한다. 각 캔들 펼침은 해당 패널만 확장하며, 다른 패널의 기준 높이를 늘리지 않는다.
- **FR-033**: KOSPI/KOSDAQ 선택, 일/당일 1분 전환, 일 모드의 6M·1Y·3Y·5Y 선택 및 선택 상태를 제공한다. 제목은 ADR만 표시한다. ADR 최종값은 확대 구간과 무관하게 불러온 마지막 값이며 캔들 버튼과 같은 줄 오른쪽에 표시한다.
- **FR-034**: 1분 데이터는 한국시간 거래일과 09:00~15:30 구간을 기준으로 정규화한다. 타임스탬프가 더 오래된 응답으로 거래일을 되돌리지 않는다. `asOf`가 장외 갱신 시각이면 장중 봉을 만들지 않는다.
- **FR-035**: 일 모드는 실제 원천의 날짜·ADR 시계열을 조회하고 6M은 월, 1Y는 약 2개월, 3Y는 약 4개월, 5Y는 연도 눈금을 기본으로 사용한다. 첫 날짜·월 눈금이 겹치지 않게 간격을 조절하며 MAX·MIN 글자와 해당 극값 표식은 표시하지 않는다.
- **FR-036**: ADR 세로축은 오른쪽에 10단위 눈금을 표시하며 80·100·120의 동일한 빨간색 눈금 글자와 80~120 회색 배경을 유지한다. 가로선은 기준선을 포함해 쏠림율과 같은 회색 점선이다. 시장 지수 캔들은 실제 OHLC를 사용하고 ADR와 동일한 X축·표시 범위·커서를 공유한다.
- **FR-037**: ADR 분봉·일봉과 펼쳐진 지수 캔들은 Rank 주기를 공유한다. 독립 타이머나 서버의 ADR 기록 저장을 추가하지 않는다. 외부 오류는 상태 안내로 처리하고 기존 차트 데이터를 보존한다.
- **FR-038**: 세 차트 모두 메인 그래프 위 고정 정보 줄 한 곳에 마우스 오버 정보를 표시한다. 글자는 `--text-primary`이며 캔들에서는 같은 정보 줄을 갱신하고 중복 정보창은 표시하지 않는다. 정보를 숨겨도 줄 높이를 유지해 레이아웃 변동을 방지한다. ADR 커서 날짜 배지는 표시하지 않는다.
- **FR-039**: 두 차트는 줌 바 위·기간 정보 아래 순서, 두 요소 사이 8px 간격을 사용한다. 슬라이더 손잡이 양쪽 트랙은 같은 색이며 진행률 채움은 없다. 쏠림율 기간은 YYYY-MM-DD를 사용하고 분봉은 시각도 포함한다. 하단 Jusikbot 문구는 표시하지 않는다.
- **FR-040**: 차트 ResizeObserver는 크기 쓰기·재그리기를 다음 화면 프레임으로 예약하고 동일 크기 재적용을 방지하여 초기 로그인 화면 전환과 리사이즈에서 반복 알림 오류를 예방한다.

### 추가 Success Criteria와 범위 제한

- **SC-009**: 시장·모드·네 기간 선택에 맞는 API와 값이 표시되고, 실제 타임스탬프에 따라 직전 거래일/당일이 전환된다.
- **SC-010**: ADR와 지수 캔들 확대·이동·드래그 범위 및 X축이 일치하고 자동 갱신 후에도 확대 범위가 유지된다.
- **SC-011**: 정보창 중복·첫 날짜 겹침·슬라이더 채움 없이 두 차트의 하단 배치가 일관되며 캔들 펼침은 각 패널에만 영향을 준다.

Rank ADR의 선택·기간·캔들 상태는 현재 페이지 메모리 상태이며 사용자 설정 백업에는 추가하지 않았다. 수신한 당일 분봉은 기존 브라우저 localStorage에 저장할 수 있으나 서버 파일/DB에는 저장하지 않는다. 직전 거래일 분봉은 원천 또는 현재 페이지가 이미 수신한 값에 의존하며 새 방문에서 원천이 제공하지 않으면 복원할 수 없다. 독립 Rank 창에 ADR를 추가하는 것은 이번 구현 범위가 아니다.

### ADR 고정탭 제거 (2026-10-13)

- **FR-041**: 고정 ADR 탭·전용 자동갱신 설정·HTML 조회 기능을 제거하고 Rank ADR 기능은 유지한다. 예전 로컬/서버 설정 및 가져온 백업의 tab_adr 콘텐츠와 adrInterval은 무시하며 활성 탭이 tab_adr이면 Rank로 복원한다. 나머지 탭과 설정은 보존한다.
- **SC-012**: 이전 ADR 탭이 포함된 설정을 복원해도 ADR 탭이 재생성되지 않고 Rank의 시장 선택·일/1분·캔들·줌 기능을 계속 사용할 수 있다.

이 절은 위 단계별 UI 설명보다 우선하는 최종 요구사항이다. 로컬 구현과 2026-10-13 사용자 확인에 따른 Oracle 운영 세 차트 정상 동작을 기록한다. 실제 키움 전체 기간 조회·응답 검산의 완료를 의미하지 않는다.

### User Story 6 - 코스피·코스닥 거래대금 추이 비교 (Priority: P1)

사용자는 ADR 오른쪽에서 두 시장의 일별 거래대금을 동시에 비교하고, 선택한 시장의 지수 캔들을 같은 구간에서 펼쳐 확인한다.

**Acceptance Scenarios**:

1. 최초 조회에서 KOSPI 선택·1Y 기간으로 두 시장의 선을 표시한다. 선택 시장은 선명하고 다른 시장은 흐리며, 시장을 바꿔도 다른 선을 숨기지 않는다.
2. 일봉만 제공하고 6M·1Y·3Y·5Y 기간을 선택한다. 시장 선택에 맞는 지수 일봉 캔들을 펼치거나 접을 수 있다.
3. 오른쪽 거래대금 축은 0조부터 10조 간격으로 표시하며 두 시장의 현재 표시 범위를 함께 수용한다.
4. 메인 차트 또는 캔들에서 오른쪽으로 드래그하면 구간이 확대되고 왼쪽으로 드래그하면 전체 구간으로 복원된다. 버튼·슬라이더도 두 그래프의 시간축에 함께 적용된다.
5. 마우스 이동 시 두 시장의 이동 점·수평선·우측 값 배지와 공유 수직선을 표시한다. 날짜와 두 거래대금 정보는 메인 그래프 위 전용 줄에만 표시한다.
6. 캔들 버튼 행 오른쪽에 KOSPI와 KOSDAQ 오늘 거래대금을 두 줄로 표시한다. 시장명은 왼쪽, 수치는 오른쪽 정렬한다. 확대 구간을 과거로 이동해도 오늘 값은 바뀌지 않는다. 오늘 데이터가 없으면 직전 거래일을 오늘 값으로 대체하지 않고 —를 표시한다.

### 추가 Functional Requirements

- **FR-042**: 제목은 거래대금만 표시하고 일봉·두 시장 동시 표시·시장 강조 선택·네 기간·시장 지수 캔들 펼침/접힘을 제공한다. 분봉은 제공하지 않는다.
- **FR-043**: 일별 시장 거래대금은 일봉 쏠림율의 분모와 같은 원천·변환 기준을 사용한다. 원 단위 값으로 전달받아 조원으로 표시하며 누락·무효 데이터를 0 또는 가격×거래량 추정치로 대체하지 않는다.
- **FR-044**: 거래대금의 표시 날짜는 두 시장의 거래일 합집합이며 실제 거래일 간격으로 배치한다. 확대·이동·양 캔버스 드래그가 지수 캔들과 같은 시간축에 반영된다. 기간 변경은 확대 범위를 초기화하며 시장 변경은 두 선과 확대 범위를 유지한다.
- **FR-045**: 거래대금은 기존 Rank 갱신주기를 공유한다. 최초 기간 조회 후 갱신은 각 시장의 최근 일봉 구간만 조회하여 기존 데이터와 병합하고 두 시장 요청은 순차 처리한다. 한 시장 조회 실패는 해당 시장 상태로 안내하고 기존 수신값과 다른 시장 표시를 유지한다. 시장별 일부 구간·거래대금 없음 상태를 구분한다. 과거 기간으로 변경한 뒤 실패한 요청에 이전 기간 데이터를 혼합하지 않는다.
- **FR-046**: 세 메인 차트와 펼친 캔들 모두 오른쪽 Y축을 사용하고 가로선은 쏠림율과 동일한 회색 점선으로 통일한다. 거래대금은 10조 간격이며 ADR 기준 눈금 80·100·120 글자는 모두 현재 100과 같은 빨간색이다.
- **FR-047**: 쏠림율은 ADR와 같은 파란 실선이며 ADR 일봉·분봉도 동일한 선을 사용한다. 세 메인 차트는 마우스를 따라 이동하는 점을 표시한다. 오늘 데이터 점은 주황색이며 ADR는 현재 표시 구간의 오늘 마지막 점만 강조한다. 끝 점은 그리기 경계에서 반으로 잘리지 않는다.
- **FR-048**: 마우스 오버의 수직선 외에 데이터 값 위치의 수평 점선과 우측 Y축 값 배지를 표시한다. 거래대금은 두 시장을 각각 표시하며 펼친 캔들은 해당 봉 종가를 표시한다. 값 배지는 캔버스 오른쪽 경계를 넘지 않는다. 이동 점·수평선은 마우스의 임의 Y좌표가 아니라 선택 봉 값에 대응한다.
- **FR-049**: 세 차트의 최종값은 캔들 버튼 행에서 해당 차트 Y축 눈금의 오른쪽 끝과 정확히 맞춰 정렬하며 파란색·같은 글꼴/크기/굵기를 사용한다. 거래대금 시장명은 기존 시장 색과 강조를 유지하고 오늘 수치는 두 줄의 오른쪽 정렬이다. 값·레이블은 패널 오른쪽 경계를 넘지 않는다.
- **FR-050**: 세 차트 마우스 정보는 그래프 위 전용 줄에 표시하며 정보 줄에서 그래프 상단까지의 간격을 거래대금 차트 기준으로 동일하게 맞춘다. 줄 공간 확보를 위해 메인 그래프 세로 높이를 조정하고 패널 기준 높이를 유지한다. 날짜는 YYYY-MM-DD로 통일하고 분봉에서는 시각을 덧붙인다. ADR 제목은 ADR, 분봉 버튼은 당일 1분이며 MAX·MIN 글자와 극값 표식은 제거한다.

### 추가 Success Criteria와 범위 제한

- **SC-013**: 두 시장의 일봉 거래대금을 동시에 표시하며 시장 선택은 강조와 지수 캔들에만 적용된다. 같은 일봉 원본 입력에 대한 거래대금 값은 쏠림율 분모와 정확히 일치한다.
- **SC-014**: 세 차트가 같은 줄에 표시되고 각 차트의 최종값·축 배지·오늘 점이 오른쪽에서 잘리지 않는다. 거래대금의 오늘 값은 두 줄이며 시장명/수치 정렬과 버튼 행 위치가 유지된다.
- **SC-015**: 거래대금 메인·캔들 드래그 확대/전체 복원, 슬라이더, 기간 선택, 마우스 이동 점·수평 가이드·축 값 배지가 브라우저 검증에서 동작한다.
- **SC-016**: 모의 응답의 필드 누락·부분 조회·한 시장 실패 안내와 실제 키움/운영 환경 확인을 구분한다. 로컬 테스트 통과만으로 실제 장기 데이터 완전성이나 운영 배포 완료를 주장하지 않는다.

거래대금 선택·기간·펼침·확대 상태는 현재 페이지 메모리만 사용한다. 사용자 설정 백업이나 서버 차트 기록 저장은 추가하지 않았다. 독립 Rank 창에 세 차트를 추가하는 작업은 이 범위에 포함하지 않는다. 캔들 데이터는 거래대금 일봉 조회 응답에 함께 있으므로 거래대금에서는 캔들 펼침 자체가 추가 API 요청을 발생시키지 않는다.

### 검증 상태 갱신 (2026-10-13)

사용자가 Oracle에서 쏠림율·ADR·거래대금 세 차트가 정상 동작한다고 수동 확인했다(T089 완료). 이는 기존 로컬 모의 테스트와 별도의 운영 확인 증거이며 에이전트가 운영 응답을 직접 검산한 결과는 아니다. SC-013~016의 개별 항목 전체 통과로 확대하지 않고, 실제 데이터 검산·장기 기간·실패/휴장일·장중 갱신·좁은 화면 상세 검증은 T088/T090으로 남긴다. 이전 절의 운영 미확인 설명은 당시 기록이며 현재 검증 상태는 이 절을 따른다.
