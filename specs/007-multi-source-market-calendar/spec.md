# Feature Specification: 증시캘린더 다중 소스 탭

**Feature Branch**: `007-multi-source-market-calendar`
**Created**: 2026-10-03
**Updated**: 2026-10-06
**Status**: Implemented (운영 통합 검증 일부 대기)
**Input**: 증시캘린더에서 지표/실적 일정, 배당 일정, 각국 금리 일정을 전환한다. Investing.com 중앙은행 페이지는 iframe 대신 테이블 이미지로 제공한다.

## User Scenarios & Testing

### User Story 1 - 캘린더 공급자 전환 (Priority: P1)

사용자는 증시캘린더 고정 탭에서 `지표/실적 일정`, `배당 일정`, `각국 금리 일정`을 선택한다.

**Independent Test**: 공급자를 전환하면 선택 표시와 원본 링크가 바뀌고, Toss/SEIBro는 iframe, Investing.com은 이미지로 표시되는지 확인한다.

**Acceptance Scenarios**:

1. 최초 진입은 Toss의 지표/실적 일정이 기본 선택이다.
2. 배당 일정은 SEIBro iframe, 각국 금리 일정은 중앙은행 테이블 PNG를 표시한다. 각국 금리 일정에서는 iframe을 숨긴다.
3. 공급자 변경은 활성 탭과 원본 링크를 함께 갱신하고 기존 설정 저장/복원 흐름으로 마지막 선택을 유지한다. 공급자 ID `investing`은 유지한다.
4. 원본 사이트 링크는 선택한 공급자의 페이지를 새 창에서 연다.

### User Story 2 - 각국 금리 테이블 캡처와 당일 재사용 (Priority: P1)

**Independent Test**: 최초 선택으로 PNG를 조회하고, 다른 메뉴 또는 소탭을 갔다가 돌아오면 한국시간 기준 같은 날의 이미지를 재사용하는지 확인한다.

**Acceptance Scenarios**:

1. 캐시가 없으면 숨겨진 브라우저로 중앙은행 페이지를 조회하고 검증된 테이블만 캡처한다.
2. 같은 날 다시 진입하면 기존 이미지를 사용하며 외부 페이지를 다시 조회하지 않는다. 새로고침 버튼을 누르면 화면·서버 당일 캐시를 우회해 다시 캡처하고 성공 이미지를 교체한다.
3. 한국시간 날짜가 바뀐 뒤 다음 진입/조회에는 새 이미지를 캡처한다. 자정 자동 조회는 하지 않는다.
4. 중복 클릭과 동시 요청은 진행 중인 캡처 결과를 공유한다. 실패 결과는 캐시하지 않아 다음 조회로 재시도한다.

### User Story 3 - 로딩 상태 확인 (Priority: P2)

**Independent Test**: 응답을 지연시켜 표시 영역 중앙에 `화면 로딩 중...`이 나타나고, 이미지 디코딩 완료 뒤 사라지는지 확인한다.

**Acceptance Scenarios**:

1. 최초 조회, 날짜 변경 또는 이미지 준비 중에는 표시 영역의 가로·세로 중앙에 메시지를 표시한다.
2. 실제 이미지 디코딩이 끝난 뒤 메시지를 이미지로 교체한다.
3. 조회 또는 디코딩 실패 시 오류 및 새로고침 재시도 안내로 교체한다.

### Edge Cases

- 외부 페이지 구조 변경, 접근 차단 또는 테이블 검증 실패는 조회 실패로 안내한다. 다른 공급자는 계속 사용 가능하다.
- 서버 재시작은 서버 메모리 캐시를 초기화한다. 열린 화면의 당일 캐시는 유지되지만 재시작 후 캐시 없는 화면의 첫 요청은 다시 캡처한다.
- 페이지 재로드는 화면 메모리 캐시를 초기화하지만 실행 중인 서버의 당일 캐시를 재사용한다.
- 조회 도중 소탭을 바꾸면 비선택 이미지 영역만 갱신하며 현재 공급자 상태를 덮어쓰지 않는다. 이전 렌더 호출은 새 렌더 결과를 덮어쓰지 않는다.
- SEIBro의 iframe 차단 여부는 부모 화면이 완전하게 판별할 수 없으므로 원본 링크를 제공한다.

## Requirements

- **FR-001**: 소탭은 지표/실적 일정, 배당 일정, 각국 금리 일정으로 표시한다.
- **FR-002**: 초기 공급자는 Toss이며 선택한 공급자의 콘텐츠 하나만 표시한다.
- **FR-003**: 공급자 선택 시 선택 표시, 콘텐츠, 제목 및 원본 링크를 갱신한다.
- **FR-004**: 선택 상태는 기존 설정 저장/복원 흐름을 사용한다.
- **FR-005**: Toss는 `/calendar` 프록시, SEIBro는 직접 HTTPS iframe을 사용한다. Investing.com 원본 및 캡처 소스는 `https://kr.investing.com/central-banks/`이다.
- **FR-006**: 선택 공급자의 원본 사이트 새 창 링크를 항상 제공한다.
- **FR-007**: 탭 역할, 선택 상태, focus-visible 스타일 및 로딩 상태 접근성(role=status, aria-busy)을 제공한다.
- **FR-008**: Playwright headless로 접속하고 domcontentloaded 이후 **1초** 대기한다. 팝업·쿠키 버튼 및 Escape를 처리한 뒤 최대 10초의 탐색 구간에서 약 0.5초 간격으로 테이블을 반복 확인한다. 탐색 구간은 접속·팝업 처리·캡처 시간을 포함하지 않는다.
- **FR-009**: 중앙 은행 / 현재 금리 / 다음 회의 / 마지막 변경 헤더 네 개와 등록된 주요 중앙은행 이름 네 개 이상을 확인한다. 공백을 정규화하고 보이는 테이블만 인정한다.
- **FR-010**: 검증된 테이블 영역만 PNG로 캡처하며 브라우저는 성공·실패 모두 자동 종료한다.
- **FR-011**: 성공 PNG는 서버와 화면 메모리에서 Asia/Seoul 날짜 기준 당일 재사용한다. 이미지 파일은 서버에 저장하지 않는다.
- **FR-012**: 동일한 진행 중 요청을 공유하고 실패는 캐시하지 않는다. 각국 금리 일정의 명시적 새로고침 버튼은 당일 성공 캐시를 우회해 재조회한다. 진행 중 재조회는 중복 실행하지 않고 공유하며 일반 재진입도 진행 중 결과를 기다린다. 자동 전체 갱신은 당일 캐시를 재사용한다.
- **FR-013**: 이미지 준비 시작부터 디코딩 완료까지 화면 중앙에 정확히 `화면 로딩 중...`을 표시한다.
- **FR-014**: 조회 실패 시 재시도 안내를 제공하고 다른 공급자 동작을 유지한다.
- **FR-015**: 이미지는 비율을 유지하고 영역 너비에 맞추되 최대 800px, 상단 여백 30px로 표시한다.

## Success Criteria

- **SC-001**: 세 공급자 모두 올바른 콘텐츠와 원본 링크로 전환된다.
- **SC-002**: 공급자 선택 상태가 기존 저장/복원 과정에서 유지된다.
- **SC-003**: Toss 및 SEIBro 새로고침 동작이 유지된다.
- **SC-004**: 같은 날 일반 재진입은 추가 외부 캡처 없이 성공 이미지를 재사용한다. 새로고침 버튼은 새 캡처를 수행하고 동시 요청은 그 진행 결과를 공유한다.
- **SC-005**: 한국시간 날짜 변경 후 다음 조회에서 새 캡처를 수행하고 실패 후 재시도가 가능하다.
- **SC-006**: 지연 응답 중 중앙 메시지가 표시되고 이미지 디코딩이 끝난 후에만 이미지로 교체된다.

## Assumptions

- 외부 서비스의 구조·접근 정책에 따라 조회가 실패할 수 있다.
- 캐시는 프로세스 메모리 범위이며 재시작·다중 서버 간 영구 공유는 요구하지 않는다.
- 위 로딩 표시는 각국 금리 일정 이미지 영역에 적용한다. 일반 동적 차트의 공통 로딩 기능 변경은 이번 범위에 포함하지 않는다.

## 명시적 새로고침 수용 기준 — 2026-10-06

- 당일 이미지가 있을 때 새로고침 버튼을 누르면 중앙 로딩 메시지를 표시하고 재캡처 성공 후 이미지와 조회 시각을 갱신한다. 이후 일반 재진입은 갱신된 이미지를 재사용한다.
- 강제 재조회가 실패하면 해당 요청은 오류를 표시하되 기존 성공 캐시는 보존한다. 이후 일반 재진입은 보존된 이미지를 사용하며 새로고침 버튼으로 재조회할 수 있다.
