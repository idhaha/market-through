# Quickstart: 증시캘린더 검증

## Manual scenarios

1. 서비스 페이지를 다시 열고 지표/실적 일정, 배당 일정, 각국 금리 일정을 각각 선택한다. 콘텐츠와 원본 링크를 확인한다.
2. 개발자도구 Network에서 각 iframe 문서 요청을 확인한다. 각국 금리 일정은 central-banks/image API를 요청하지 않아야 한다.
3. 세 소탭 및 다른 메뉴를 반복 전환한다. 같은 날에는 추가 iframe 문서 요청 없이 기존 페이지를 유지해야 한다.
4. 앱 자동 갱신도 같은 날 재접속을 유발하지 않아야 한다.
5. 새로고침 버튼은 선택 공급자만 다시 접속하고 이후 전환은 갱신 페이지를 유지해야 한다.
6. 한국시간 날짜 변경 후 다음 조회에서 해당 공급자가 다시 접속해야 한다.
7. 서비스 페이지 자체 새로고침 후에는 iframe이 새로 생성되어 접속할 수 있다.
8. Investing.com 접속 중 중앙 로딩 안내를 확인한다. 회원가입 팝업은 직접 닫는다. 빈 화면이면 원본 사이트로 확인한다.

## Verified — 2026-10-06

- 사용자: 변경한 각국 금리 일정이 잘 표시됨을 확인. 잠시 후 회원가입 팝업이 나타남을 확인.
- 실제 외부 접속 조사: 기본 headless 환경은 403/SAMEORIGIN, Chrome 형식 User-Agent 환경은 200으로 다른 도메인 테스트 페이지 iframe에서 로드됨. 모든 사용자 환경에서 허용된다는 보장은 아니다.
- 로컬 Playwright 모의 페이지, 너비 1400px 및 390px: 세 공급자 반복 전환 시 각각 1회, 자동 갱신 시 횟수 유지, 명시적 새로고침 시 각각 2회, 날짜 변경 후 각각 3회 접속 확인.
- JavaScript 구문 검사 및 git diff --check 통과.

세 공급자의 최신 변경을 실제 Oracle 서비스에서 전환/새로고침/날짜 변경으로 확인하는 통합 검증은 아직 대기이다. 009 기준금리 차트의 운영 성공으로 간주하지 않는다.
