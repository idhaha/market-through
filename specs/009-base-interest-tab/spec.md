# Feature Specification: 기준금리 고정 탭

**Created**: 2026-10-06
**Status**: Implemented (운영 통합 검증 대기)
**Input**: 증시캘린더 오른쪽에 기준금리 고정 탭을 추가하여 Investing.com의 12개 중앙은행 금리 차트를 이미지로 표시한다. 사용자 첨부 move_test/base_interest.js를 구현 참고로 사용한다.

## User Scenarios & Testing

### US1 — 은행별 금리 차트 조회 (P1)

기준금리 탭은 증시캘린더 바로 오른쪽에 표시하며 이름 변경·삭제·드래그 대상에서 제외한다. 초기 설정 또는 오래된 백업에 탭 정보가 없어도 생성한다. 탭을 처음 선택하면 조회를 시작한다.

- 12개 카드를 2열로 표시하며 각 카드 좌측 상단 제목은 약어 (중앙은행 명칭)이다.
- 행 순서: FED ECB / BOE BOJ / BOK RBA / BOC SNB / RBI BCB / CBR PBOC.
- 은행 명칭: FED 연방준비제도, ECB 유럽중앙은행, BOE 영국은행, BOJ 일본은행, BOK 한국은행, RBA 호주 연방준비은행, BOC 캐나다 은행, SNB 스위스 국립은행, RBI 인도 연방준비은행, BCB 브라질 중앙은행, CBR 러시아 중앙은행, PBOC 중국인민은행.
- iframe을 사용하지 않고 차트 SVG 영역만 PNG 이미지로 표시한다.

### US2 — 당일 재사용 및 명시적 새로고침 (P1)

같은 한국시간 날짜의 일반 재진입은 메모리 이미지를 재사용한다. 오른쪽 위 새로고침 버튼만 캐시를 우회하여 다시 캡처한다. 중복 클릭은 진행 중인 작업을 공유한다. 날짜 변경 후 다음 진입은 새 캡처를 수행한다.

### US3 — 진행 상태 및 실패 표시 (P2)

카드마다 화면 로딩 중...을 표시하고 완료된 이미지부터 순서대로 채운다. 실패한 은행은 해당 카드만 오류를 표시하며 다음 은행의 캡처는 계속한다. 전체 실패는 재시도 안내를 제공한다. 강제 새로고침 전체 실패 시 당일 이전 성공 결과를 보존한다.

## Requirements

- FR-001: tab_base_interest 고정 탭을 증시캘린더 바로 오른쪽에 생성하고 설정 복원·동적 탭 초기화에서도 유지한다.
- FR-002: 위 제목과 순서의 12개 차트를 정확히 2열에 배치한다.
- FR-003: 소스는 https://kr.investing.com/central-banks/ 이며 headless Playwright로 조회한다. 사용자 테스트처럼 Chrome channel을 먼저 시도하고 설치되지 않은 경우 기존 Chromium 경로를 사용한다.
- FR-004: 1400×1200 viewport, ko-KR locale, Asia/Seoul timezone, 초기 5초 대기와 팝업 처리를 적용한다. 기존 각국 금리 일정 테이블의 1초 대기는 변경하지 않는다.
- FR-005: section#leftColumn 내 은행 탭 선택 상태와 Highcharts 데이터 변경을 최대 15초 확인한다. 이미 선택된 은행은 유효 데이터가 있으면 변경을 요구하지 않는다. 다른 은행으로 전환할 때 데이터 변경 확인 실패는 오류로 처리하여 이전 은행 이미지를 잘못 저장하지 않는다.
- FR-006: 해당 섹션의 차트 SVG만 캡처하고 성공·실패 모두 브라우저를 종료한다. PNG 및 디버그 파일은 서버에 저장하지 않는다.
- FR-007: 서버와 화면의 이미지는 메모리에서 Asia/Seoul 당일 재사용한다. 서버 재시작 및 화면 재로드 시 해당 메모리 캐시는 소실될 수 있다.
- FR-008: 새로고침 버튼은 새 캡처를 수행하고 진행 중이면 해당 작업을 공유한다.
- FR-009: 개별 실패를 격리하고 완료된 이미지를 순차 표시한다. 이미지 디코딩 전까지 로딩 안내를 유지한다.
- FR-010: 캡처 작업은 요청과 분리하여 실행하며 짧은 상태 조회를 반복한다. API는 기존 로그인 세션 인증을 적용한다.
- FR-011: 기존 TE 및 중앙은행 테이블 캡처와 브라우저 슬롯을 공유하여 서버에서 동시 브라우저 최대 1개를 유지한다.

## Success Criteria

- SC-001: 요구된 순서와 제목의 이미지 12개가 2열에 표시된다.
- SC-002: 같은 날 탭 재진입은 외부 조회를 추가하지 않고 새로고침은 새 캡처를 수행한다.
- SC-003: 일부 은행 실패가 다른 은행 및 다른 탭의 사용을 중단하지 않는다.
- SC-004: API 요청 하나를 12개 캡처 전체 시간 동안 유지하지 않고 로딩 진행을 표시한다.

## Limits

최초 조회는 은행 12개를 순차 처리하여 수십 초 이상 걸릴 수 있다. 일부 성공 결과도 당일 보관하며 실패 카드는 새로고침으로 다시 조회한다. 외부 페이지 구조/접근 정책 및 운영 환경 검증은 별도 확인이 필요하다.
