# Rank 독립창

노트 아이콘은 별도의 Windows 노트 창을 연다. 메모 탭과 동일한 Quill 편집 도구를 사용하며 저장 버튼은 내용과 서식을 서버에 저장하고 취소는 마지막 저장 상태로 되돌린 뒤 닫는다. ‘항상 위’ 체크박스와 Windows 이동·크기 조절·최소화·최대화·닫기를 지원한다. 노트 창 지원은 새 설치 파일로 덮어 설치해야 적용된다.

Windows x64 전용 앱이다. 거래대금 상위 표 → 쏠림율 차트 → 수급 차트를 항상 세로로 표시하고 메인 화면의 원본은 유지한다. 메인 페이지에서 로그인 후 Rank의 독립창 버튼으로 실행한다. 연결이 끊겨도 독립창과 마지막 데이터를 유지하며 재시도한다. 서버 재시작·채널 만료는 로그인한 메인창이 같은 연결을 복구해 최신 결과를 다시 전달한다. 메인 페이지를 닫았거나 로그인이 풀린 경우에는 메인 페이지를 열고 로그인해야 복구할 수 있다.
독립창은 Windows 기본 제목 표시줄과 크기 조절 테두리를 사용한다. 최소화·최대화·복원·이동은 Windows 기본 창 동작을 따르며, 독립창 상단 갱신 주기 왼쪽의 '항상 위' 체크박스로 최상위 표시를 선택한다. 이 변경은 새 설치 파일로 재설치해야 적용된다.
스마트폰과 Windows가 아닌 기기에는 독립창 버튼을 표시하지 않는다. Windows PC는 브라우저 창 너비와 관계없이 사용할 수 있다.

허용 주소: `https://azikanbal.duckdns.org`, `http://localhost:3000`. 하나의 설치 앱으로 운영과 로컬을 모두 사용한다. 현재 연결된 페이지의 주소에서만 콘텐츠를 불러온다.

## 설치/사용

독립창 거래대금 제목 옆의 ⇅ 버튼은 기본 → 10개(중간) → 5개(최소) → 기본 순서로 표시 개수를 전환한다. 제한 모드에서는 상위 목록만 표시하고 해당 수에 맞춰 테이블 카드와 창 높이를 줄이며, 기본으로 돌아가면 이전 카드 높이를 복원한다. 다른 차트의 높이와 창 너비는 유지하고, 새 데이터가 도착해도 선택한 개수는 유지한다.

화면 밖 창 복구는 제목 표시줄이 현재 모니터 작업 영역에 접근 가능한지를 검사한다. 활성화·이동 완료·모니터 변경 및 2초 주기 점검에서 복구하며, 사용자가 최소화한 창은 유지한다. 캔들 자동 갱신 메시지가 최소화된 창을 임의로 복원하지 않는다. 이 복구와 자동 크기 변경 완료 신호는 새 설치 파일로 재설치해야 적용된다.

서비스에 배포한 뒤 Rank의 **독립창** 버튼을 누른다. 20초 이내 앱 연결이 확인되지 않으면 미설치 또는 실행 취소 안내와 함께 `/downloads/MarketThroughSetup.exe`를 자동 다운로드한다. 받은 파일을 직접 실행한다. 별도 설치 링크는 표시하지 않는다. 로그인/서버 연결 오류일 때는 자동 다운로드하지 않는다. 설치 위치는 `%LOCALAPPDATA%\MarketThrough\Independent`, 창 상태와 WebView2 사용자 폴더는 `%LOCALAPPDATA%\MarketThrough\State`다. 관리자 권한이 필요 없는 사용자별 HKCU protocol 등록을 사용한다.

Windows x64와 .NET Framework 4.6.2 이상을 사용한다. WebView2 Runtime이 이미 있으면 재설치하지 않는다. 없으면 Microsoft 공식 bootstrapper를 PC에서 다운로드하고 Authenticode 서명을 확인하여 설치한다. 런타임 다운로드는 Oracle 서버에 올리지 않는다. 인터넷이나 PC 정책 때문에 실패하면 설치 화면에 오류를 표시한다.

앱 설치 후 웹페이지의 독립창 버튼을 다시 누르고 브라우저의 외부 앱 실행 안내를 승인한다. 쏠림율과 수급의 종목 선택은 메인창과 독립창 사이에서 항상 양방향 동기화한다. 시장/거래소/갱신 간격/봉 종류·간격은 공유하고 줌·스크롤은 각각 유지한다.
독립창의 상단 왼쪽에는 메인 Rank와 동일한 갱신 시각과 진행 상태를 표시한다. 앱 실행 시 메인의 자동 갱신을 유지하고, 실제 페이지 종료 시 타이머를 중지한다. 저장된 갱신주기를 복원하거나 페이지로 복귀하면 현재 선택된 주기로 자동 갱신한다.
거래대금 상위·쏠림율·수급은 왼쪽 위의 ▲/▼로 각각 접거나 펼칠 수 있다. 접은 콘텐츠의 제목은 유지하며 접은 영역만큼 Windows 창 크기를 줄인다. 나머지 콘텐츠의 크기는 유지하고 펼치면 해당 영역을 다시 확보한다. 이 동작은 메인 Rank의 표시와 조회 상태를 바꾸지 않는다. 창 자동 크기 조절은 새 설치 파일로 앱을 재설치해야 적용된다. 분봉으로 전환할 때 기본값은 5분이다.
표의 초기 글꼴·글자 크기·행 간격은 메인 Rank의 실제 표시 스타일을 따른다. Inter 글꼴도 동일하게 로드한다. 창 높이를 줄이면 셀 위아래 여백과 행 간격만 줄이고 글자 크기는 고정한다. 창을 키우면 Rank 기본 간격까지만 복원하며 그 이상 늘리지 않는다. 브라우저 확대 배율과 Windows 표시 배율 차이는 WebView2 표시 배율로 맞춘다. 배율 동기화는 새 설치 파일로 재설치해야 적용된다. 쏠림율과 수급에는 종목 동기화 해제 옵션을 제공하지 않는다.
쏠림율과 수급의 캔들 열림·닫힘은 메인창과 독립창이 각각 유지한다. 최초 연결 때도 메인의 캔들 상태를 가져오지 않는다. 종목과 봉 종류는 계속 공유한다.

캔들을 열 때 해당 차트의 현재 그래프 높이를 측정해 같은 높이의 캔들 영역을 추가한다. 다른 차트와 기존 그래프의 높이는 유지하며 실제 창은 세로로만 늘린다. 접으면 실제 늘어난 높이만큼 줄인다. 사용자가 변경한 창 너비는 유지한다. 모니터 경계로 창을 늘릴 수 없으면 내부 스크롤을 사용한다. 수동 크기 변경 후에는 변경된 높이를 기준으로 다시 측정한다. 네이티브 크기 변경 완료 신호로 자동 변경과 수동 변경을 구분한다.

## 빌드

저장소 루트에서 Windows PowerShell:

```powershell
node desktop/generate-page.cjs
./desktop/build.ps1 -Publish
```

SDK package는 고정 버전 `Microsoft.Web.WebView2 1.0.3537.50`을 공식 NuGet에서 받아 캐시한다. `build`와 `packages`, `dist`는 Git에서 제외한다. 게시 대상은 `public/downloads/MarketThroughSetup.exe` 하나이며 runtime 포함 없이 약 260KB다. 새 앱 코드를 변경할 때 반드시 재빌드한다. .NET SDK/Rust/Node를 최종 사용자 PC에 추가 설치하지 않는다.

다른 로컬 포트가 필요하면 `-ServerOrigin` 배열에 운영 주소와 해당 로컬 주소를 명시하여 빌드한다. 허용 목록은 포트까지 정확히 검사한다.

배포는 일반 웹서비스 배포에 `rank-independent.js`, `public/rank-independent-*`, HTML/CSS/차트 코드, 설치 파일을 포함하여 Express를 재시작한다. 설치 파일의 허용 origin 목록을 변경했다면 기존 PC 앱도 재설치한다. 파일은 현재 코드 서명되지 않았으므로 Windows 다운로드/실행 확인이 발생할 수 있다.

## 확인

```powershell
./desktop/test.ps1
```

`dev/tests/RankNativeSmoke.cs`를 desktop/build의 WebView2 DLL을 참조해 x64 exe로 컴파일하면 테스트가 실제 WebView2 런타임 초기화와 relay 페이지 로드도 확인한다. 사용자 상태를 변경하지 않고 workspace 내 native-test-state를 사용한다.

남은 인수 확인: 운영 HTTPS에서 실제 Google 로그인 연결, protocol 실행/다중 실행, 다른 일반 앱과의 항상 위, 실제 drag/resize/최소화·복원, 다중 모니터 복원, runtime 없는 새 PC 자동 설치. 자동 테스트가 이 인수 확인을 대체하지 않는다.

캔들이 화면 밖으로 넘친 상태에서 영역을 접어도 창 크기는 실제 viewport와 툴바·제목 행의 필요 공간을 기준으로 계산한다. 세 영역을 모두 접어도 각 펼치기 버튼은 창 안에 유지한다.

## 제거

독립창을 닫은 후 **Windows 설정 → 앱 → 설치된 앱 → MarketThrough 독립창 → 제거**를 실행한다. 앱 파일(Independent), 창 위치·WebView2 사용자 데이터(State), HKCU protocol 및 설치된 앱 등록을 함께 지운다. 빈 MarketThrough 폴더도 제거한다. 다른 앱도 사용하는 Microsoft WebView2 Runtime은 유지한다.

이전 설치에 제거 기능이 없었다면 새 설치 파일을 한 번 실행해 덮어 설치하면 등록된다. 수동 폴더 삭제나 regedit 작업은 필요 없다. 제거 프로그램은 자신도 지우기 위해 TEMP의 복사본으로 실행하며 해당 작은 임시 실행 파일은 Windows 임시 파일 정리 대상이다. 설치 폴더에 다른 용도의 파일이 있으면 보존한다.


## 변경 적용 구분

독립창은 사용자가 이동·크기 변경을 완료한 위치를 별도로 기억한다. 화면 구성 변경 후 4초 동안 위치 보정을 유예하고, 원래 위치가 작업 영역에 들어오면 복원한다. 원격 연결이나 모니터 분리로 임시 보정된 위치는 저장 위치를 덮어쓰지 않는다. 최소화·최대화 상태에서는 복원하지 않으며, 원래 위치를 사용할 수 없을 때는 기존 제목 표시줄 복구 기능을 유지한다. 네이티브 변경이므로 새 설치 파일로 덮어 설치해야 적용된다.

서버·웹 코드 변경만으로 앱을 매번 재설치할 필요는 없다. 서버 코드는 Node 프로세스 재시작, 웹 코드는 메인 새로고침과 독립창 재실행으로 반영한다. 네이티브 창 위치 복구·자동 크기 변경·허용 주소 목록을 바꾼 경우에는 새 설치 파일로 덮어 설치한다. 먼저 제거할 필요는 없다. `-Publish`는 로컬 설치 파일을 `public/downloads`에 복사하는 빌드 옵션이며 Oracle 배포가 아니다. 배포와 서버 재시작은 사용자가 수행한다. 상세 점검은 [운영 절차](../docs/operations/server-runbook.md#9-수급-차트와-독립창-변경-적용), 수집·보관 정책은 [수급 차트](../docs/SUPPLY_CHART.md)를 따른다.

## 2026-10-21 독립창 기본 높이 상한

거래대금 표시 개수 버튼은 하나의 세로 선 양끝에 화살촉이 있는 SVG 양방향 화살표를 사용한다. 독립창 높이를 늘려도 카드에 남는 높이를 분배하지 않는다. 기본 거래대금 본문은 메인과 같은 최대 560px, 쏠림율·수급 기본 그래프는 각각 260px를 유지한다. 캔들 영역도 260px를 사용하며 펼칠 때 해당 카드만 증가한다. 남는 창 공간은 아래에 두고 작은 창은 내부 스크롤을 유지한다. 이 정책은 이전 수동 창 높이에 따라 그래프를 늘리는 설명보다 우선한다. 기본/10개/5개 순환 전환을 사용한다.

2026-10-22 크기 변경 요청은 네이티브 완료 신호 순서로 처리한다. 연속 접기·펴기는 실제 카드 높이와 툴바 높이로 최종 창 높이를 계산하며, 캔들을 빠르게 열고 닫아도 화면 경계에서 실제 늘어난 높이만 되돌린다. 목록 표시 개수 변경은 변경 전 카드 높이를 기준으로 창 높이도 함께 조절한다. 기본으로 돌아가면 목록 높이 제한 속성을 제거해 기본 높이를 복원한다. 카드 행은 콘텐츠 높이를 따르므로 목록 변경·좁은 창에서의 줄바꿈·수동 창 크기 변경 후에도 빈 그리드 행이나 겹침이 남지 않는다. 웹 코드 변경이므로 배포 후 독립창을 다시 열면 적용되며 앱 재설치는 필요 없다. 복합 회귀 검증: `node dev/tests/rank-independent-resize.test.cjs`.


## 2026-10-22 서버 재시작 후 연결 자동 복구

메인창의 정기 시세 갱신은 독립창 연결 여부와 무관하게 계속 시도한다. 서버 재시작으로 메모리 채널이 사라져 owner 조회가 404이면 로그인한 메인창이 기존 id·token·ownerKey로 복구를 요청하고 최신 스냅샷을 다시 올린다. 연결 복구 자체는 새 네이티브 창을 실행하거나 설치 파일 다운로드를 시작하지 않는다.

독립창은 peer 401/404에서 폴링을 중단하지 않고 마지막 화면을 유지하며 복구를 기다린다. 연결 요청은 10초 제한 시간을 두고 실패 시 다시 시도한다. 서버 세대(epoch)를 비교하므로 재시작 전후 버전 번호가 같아도 새 스냅샷을 받는다. 기존 소유자·자격 검증, 동시 연결 한도, 비활성 채널 정리와 사용자의 명시적 창 닫기 처리는 유지한다.

적용 시 서버 재시작과 메인 새로고침이 필요하다. 이미 실행 중인 구버전 독립창은 한 번 다시 열어 새 클라이언트 코드를 로드한다. 이후 재시작부터 자동 복구한다. 네이티브 실행 파일 변경은 없다. `node dev/tests/rank-independent-recovery.test.cjs`로 일시 장애·메모리 채널 초기화·기존 창 재연결·계속되는 최신 결과 전달·접근 검증을 확인했다. 운영 배포는 별도다.
