방법과 한계

GUI CPU 비교는 별도 단일 실행입니다. System.Drawing HighQualityBicubic으로 긴 변이 1,280px를 넘는 이미지만 축소했고 원본의 정답 영역 정규화 좌표는 유지했습니다. 8B 전반 5개 → 9B 10개 → 8B 후반 5개 순서로 모델을 번갈아 실행했습니다. 블록별 워밍업은 평가하지 않는 OCR 이미지로 수행해 채점 이미지 캐시를 피했습니다. 작은 글자는 축소로 가독성이 떨어질 수 있습니다. CPU GUI와 OCR 실행 메타데이터를 아래에서 확인할 수 있습니다.

CPU 최종 비교에서는 presence_penalty=0, frequency_penalty=0, repeat_penalty=1을 맞췄습니다. 최초 8B 실행 로그가 이 값임을 확인했습니다. 9B 태그는 presence_penalty=1.5가 기본이므로 최초 결과를 보존하고 0으로 명시한 9B 추가 실행을 최종 비교에 사용했습니다. 최초 기본값 실행 · 모델 기본 설정. CER은 글자 누락·오독뿐 아니라 지정한 행 순서와 다른 전사 순서도 오류로 계산합니다. 숫자 토큰은 공백을 제거한 뒤 대조합니다.

GUI 표본은 ScreenSpot 공개 미러 test 1,272개 중 균등 간격 10개를 결과 확인 전에 고정했습니다. 한글 OCR은 기존 앱 테스트 화면 5개 영역을 원래 해상도로 잘라 사용했으며 실사용 개인정보는 포함하지 않았습니다. 두 모델에 동일한 바이트와 과제별 동일 프롬프트·JSON 형식을 전달했습니다. temperature=0, seed=42, context=8192, think=false. GUI 출력 한도 128, OCR 1024 토큰입니다. 모델 자체의 이미지 처리 방식은 다를 수 있습니다.

당초 GPU 실행은 8B 전반 → 9B 전체 → 8B 후반 순서였으나 두 모델에서 반복되는 이미지 인코더 Vulkan device lost 오류로 중단했습니다. 실행한 기록은 보존하고 미실행 사례를 오답으로 채우지 않았습니다. 이후 CPU에서 8B 한글 OCR 5개 → 9B 한글 OCR 5개를 별도로 실행했습니다. 프롬프트와 정답은 변경하지 않았습니다. 표본이 작고 같은 앱의 제한된 글꼴·디자인이므로 일반 문서, 손글씨, 사진 또는 모든 한글 화면에 일반화할 수 없습니다.
